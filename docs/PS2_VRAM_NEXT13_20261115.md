# Pass 13: VRAM layout audit and exact clear-strip research

**No VRAM saving or clear change is adopted.** A bounded 32-pixel clear-strip
candidate passed isolated host and complete actual EE build/code-binding
checks. An executed literal-C ring/source-cache counterexample then
**rejected the ordinary compact clear for this pass**. It has not been run
on a GS or adopted into production. No FPS or physical GS timing improvement
is claimed.

The frozen control is revision `353cc94103aeb38cef87d26151c779302135d0e9`.
The [driver](../tools/ps2/next13_vram_clear_hosttest.py) exports all 602 literal
`src/` files, changes only `gs_fill_all` in `ps2_hw_gs.inc`, records both complete
source manifests, and refuses to overwrite an existing stage. It preserves
the earlier packed prototype independently of the smaller compact candidate.

## VRAM alternatives checked

The [read-only audit](../tools/ps2/next13_vram_layout_audit.py) executed against
the frozen source and stock archive SHA256
`0c5025b70dbd83faea86e59fbe888250ea70d799fa3b8c2f82535d180a3ef5b5`.
Its retained output is
`build/nov15-next13/vram-layout/stages/audit-v1/report.json`.

| Opportunity | Exact arithmetic | Remaining obstacle |
|---|---:|---|
| CLUT page rounding | 124 × 1,024 B images reserve 131,072 B: 4,096 B gap | Giving the gap to the pool changes quality/eviction inputs. |
| T8 internal block holes | 64×1024 reserves 496 blocks, occupies 256: 61,440 B holes | Reusing discontiguous holes changes ownership/window eviction; contiguous span arithmetic cannot simply be reduced. |
| Existing tall split example | 64×1536 uses 752 span blocks and 384 occupied blocks: 94,208 B holes | Both pieces, views, transfer bounds, owner maps and policy histories must remain valid. This is arithmetic, not a newly measured live image. |
| Identical raw flats | 16 full-byte-verified groups, 17 redundant images, 425,984 B redundant corpus payload | Not simultaneous residency. General sharing changes owner lifetime, eviction and source-cache keys. |
| Z24 unused upper byte | Index-capacity ceiling 81,920 B at actual PAL 320×256; 71,680 B at NTSC 320×224 | T8H address/bitplane ownership, native texture-cache/page-break hazards, complete policy and source-cache histories. CT32 CLUTs cannot fit in an 8-bit plane. |

For the common CT32 sizes audited, full FB/Z allocation pages have no spatial
padding to reclaim. CT16S retains its explicit opt-in precision policy. Neither
framebuffer alpha nor 24-bit depth is discarded. No resource capacity, cap,
reserve or setting was reduced or padded to manufacture a saving.

These alternatives retain the [pass-12 rejection](PS2_P4_NEXT12_20261115.md).
More pool space is not a proof that every existing texture stays equally fine.
Relevant consumers in the frozen source include:

* `ps2_hw_plan.inc:832`: pool budget; `:784`: thrash-driven percentage;
  `:1024`: stored size and full-size source-cache presence.
* `ps2_hw_gs.inc:654`: measured unplanned reserve and its pool clamp.
* `ps2_hw_tex.inc:345`: evicted current-frame blocks; `:482`: weighted eviction
  windows; `:548`: admission/failure; `:1559`: adaptive-cap budget;
  `:1970`: cached level/source selection; `:2190`: configured byte budget.
* `ps2_hw_draw.inc:509`: unplanned residency; `:543`: cap predictions;
  `ps2_hwd.c:1744`: upgrade budget/restamping.
* `ps2_hw_tex.inc:1213`: DMA-source release; `:1240`: release polling;
  `:1124`: finer cached source selection. Different source choices can change
  non-associative `dec_level` output.

Preserving only numeric costs without preserving eviction/reupload/source
history is insufficient. Unavailable logical tails are not counted as reclaimed
usable quota. This pass does not repeat naive P4 packing.

## Smallest retained clear candidate

`do_clear` in `ps2_hw_draw.inc:2708` calls `gs_fill_all` for ordinary engine
clears; `gs_clear_both` also calls it during initialization. The compact
candidate leaves all eight AD state writes unchanged: framebuffer mask, Z24
write mask, whole-target scissor, always-pass Z test, ALPHA, TEX1, CLAMP and
TEXFLUSH. It sets the same untextured, unblended, unfogged, non-AA sprite
primitive and RGBA through one PACKED tag. One REGLIST tag then emits pairs of
exact X16/Y16/Z32 vertices for
`[x,min(x+32,vw)) × [0,vh)`. All Z values remain zero.

The final RGBAQ, XYZ2 and `H.gsr.valid=0` behavior is retained. Integer absolute
XY positions retain per-pixel dither coordinates. The final strip handles odd
widths. There is one bounded sprite allocation, no new persistent data, no new
fence, no FINISH, and no allocator/planner/cap/source-cache code change.

| Width | Old clear total | Packed prototype | Compact candidate | Compact extra bytes |
|---:|---:|---:|---:|---:|
| 320 | 14 QW | 50 QW | 22 QW | 128 |
| 640 | 14 QW | 90 QW | 32 QW | 288 |
| 1024 | 14 QW | 138 QW | 44 QW | 480 |

Totals include the unchanged nine-qword state packet. The compact sprite
allocation is at most 35 QW versus the old five. Additional GIF bytes, CPU
construction and primitive setup must be paid for by reduced GS page changes;
packet size alone does not establish a net improvement.

The primary authorities are the SCE GS v6 manual
[§3.2.9 p46](https://raw.githubusercontent.com/ninjadynamics/PS2Docs/main/GS_Users_Manual.pdf#page=46)
(top/left-inclusive, bottom/right-exclusive sprites), §§3.2.1–3.2.2 pp37–38
(independent two-vertex sprites, flat/no-AA), §3.9.1 p70 (coordinate-based
dithering), and XYZ2 p137 (register packing). The SCE EE v6 manual
[§7.3.2 p153 and §7.4 p159](https://raw.githubusercontent.com/ninjadynamics/PS2Docs/main/EE_Users_Manual.pdf#page=153)
establish PACKED RGBAQ's tag-initialized Q=1 and REGLIST's direct 64-bit
register writes/ignored PRE. GS supplement
[§§1.1–1.2 pp6–8](https://raw.githubusercontent.com/ninjadynamics/PS2Docs/main/GS_Users_Manual_Supplement.pdf#page=6)
explains horizontal drawing/page changes and parallel engines. The checked
SCEE 2003 paper slide27 and pinned PS2SDK strip clear implementation are linked
in the [pass-13 source addendum](PS2_RESEARCH_NEXT13_20261115.md).
GS main manual §4.2.4 p78 separately warns about image transfers into draw/Z
pages; that issue applies to the deferred Z24 alias family, not this clear.

## Executed proof and its limits

The retained compact stage is
`build/nov15-next13/vram-clear/stages/compact-v2`.
Its candidate patch SHA256 is
`f66fd40ef59516349ec7cf67a2c1c3e506569a626e4138df3b4ba2217673b930`.
Plain GCC and ASan/UBSan each passed **353,336 cases and 254,002,504 checks**:
all widths 1–1024, 18 height boundaries, both framebuffer formats/buffer indices,
all four clear-flag combinations, full-byte RGBA component sweeps, every ring
starting position at seven widths/modes, 273 modeled rollovers and 11,919,912
modeled color/Z pixels. Six executed mutations fail for edge coverage, depth
mask, RGBA, GIF loop count and hidden policy-state changes.

The host compiles the literal frozen `pk_alloc`, `ad_alloc`, register builders
and old/new clear functions. It decodes every emitted vertex, verifies each
column is covered once, compares the eight AD writes, and compares every
non-ring production `H` byte. VU closure and ring retirement are host substitutes.
The pixel oracle is the documented half-open coverage model; it is not native
GS rasterization or an independently implemented GS emulator. The earlier
`packed-v1` stage preserves its own original tools, binaries, manifests and
247,165,860-check result without being overwritten.

Independent source review found no direct sprite/state counterexample and
confirmed that the existing stream validator already handles REGLIST. Its
executed literal-C witness then proved a lifecycle problem that the earlier
host ring stub omits.
With an already open frame, `need_copy=0` and no queued overlay, `do_clear` →
`frame_prepare` does not drain references. At width 320 and pre-clear
`H.wr=8178`, the nine-qword state plus old five-qword sprite fits exactly in
8192 QW. The compact thirteen-qword sprite forces a flush. Real `pk_flush`
reaches `rel_release_buf`/`rel_poll` at `ps2_hw_gs.inc:290–291`.

A completed but unreleased reference A in the next ring buffer therefore
becomes idle only in the compact path. If the 4-MiB CPU data cache is full and
A is its oldest 16-KiB entry, the next `dc_slot(4096)` can discard A in the
compact path while the old path retains busy A and discards a different idle
entry. This happens before the new upload's own packet allocation. A may be
level 1 of a legal 256² texture. For a tiled 4×4 source pattern whose central
2×2 indices are 255 and border indices 100, direct level 2 construction gives 255;
level 1 followed by level 1 gives 100. Different cached source availability can
thus change actual texture indices, including holes.

The immutable witness is
`build/nov15-next13/review/gs-cache-witness-v2/report.json`, SHA256
`72078838e498e29fb8dec215c4b2a5c174b11c2a1a31eda49352a9c146966f07`.
Ordinary GCC and ASan/UBSan both execute the counterexample with `V.on=0`
and `V.on=1`. The original path performs zero flushes/unlocks and discards B;
the compact path performs one flush/unlock and discards A. Its finer-source
lookup changes from level 1 to unavailable, and **all 4,096 output indices
change from 100 to hole 255**. Output hashes change from `da741dc5` to
`34e76dc5`. Three executed source mutations—omitting completed-buffer
release, ignoring busy exclusion, and hiding the finer source—each destroy
their required witness.

The harness executes the original `pk_alloc`, `pk_flush`, `ad_alloc`,
`frame_prepare`, `do_clear`, reference-release/poll/add, cache-slot/find/finer/drop
and `dec_level` bodies. Hardware queue start/completion, cache coherency,
validator and zone deallocation remain explicit host boundaries. **No new DMA
completion occurs during the clear**: buffer 1's reference was already complete
and only its release is deferred. This is an executed constructed legal-input
counterexample, not an observed stock-game, GS-pixel or physical-timing result.
An initial witness stage `gs-cache-witness-v1` failed to compile because its
extraction omitted the existing `clampf`; it remains preserved. Stage v2 fixes
that extraction without changing production.

Checking only the immediate clear boundary is insufficient: a longer packet
also shifts later allocations and reference-release boundaries. Neither the
host state comparison nor passing clear pixels establishes preservation of
subsequent LOD/source-cache history. The ordinary compact clear is rejected.
No actual GS fixture or emulator run was made for it; those steps were stopped
after the executable counterexample. A suggested immutable DMA-REF geometry
table of at most 512 B is only a future unimplemented design discussion. Its
memory cost, lifetime, ring/VIF behavior and source-cache preservation are
unproved; no feasibility, usable capacity or saving claim is attached to it.

## Complete actual target build and binding

The frozen `context-v1` stage recompiled exactly `ps2_hwd.c` in the accepted
203-C-plus-2-VU Hardware graph. Its existing `opt_units.txt` `-O3` override
was retained; the entire `.gnu.lto_.opts` section matches the canonical IR
byte for byte, including common `-O2` followed by the existing unit `-O3`.
The other 204 actual IR inputs remain identical. Normal whole-game linking and
separate control/candidate retained-RELA links passed exact equality of every
original allocated byte, address, capacity and defined symbol in each replay.
The candidate ELF SHA256 is
`8f150519600edcc24b156530e4ad50fbd057339de4c18e9839ed1e8f11f63867`.

The separate `object-audit-v1` stage uses the existing strict binder to
reconstruct eleven complete clear/caller/lifecycle bodies in each actual ELF,
including 901/905 ordered RELAs, explicit addends, all referenced data and
literals, and actual PDR frames. No relocation field is masked. Only
`gs_fill_all`'s raw code changes: **800→960 B**, with its **48-B frame
unchanged**. Final `.text` grows 160 B; every other final allocated section
size is unchanged. Alignment shifts `_end`, `_gp` and H's address upward 256 B.
That static placement cost is real and is not a memory saving.

These checks bind the actual candidate's code and costs; they do not repair
the source-cache counterexample. No EE runtime, GS fixture or emulator was
invoked. Reproduction, requiring a granted serial EE worker:

```sh
python3 tools/ps2/next13_vram_clear_context.py --out build/nov15-next13/vram-clear/stages/context-replay-v1
python3 tools/ps2/next13_vram_clear_codecheck.py --candidate build/nov15-next13/vram-clear/stages/context-replay-v1 --out build/nov15-next13/vram-clear/stages/object-audit-replay-v1
```

## Concrete native benchmark protocol

The following is a deferred protocol, not a completed native test or an
adoption gate that overrides the counterexample above. Build separate frozen
control/candidate HW_TEST ELFs through the official `gs_list_eetest.py` with
bounded test-only clear cases after an EE compiler slot is granted. Preserve
that fixture's default common `-O2`; it is distinct from the full game's
existing per-unit `-O3`, and no timing/body identity follows from it. Retain exact source,
config, tool/dependency, ELF and map hashes. First run raw framebuffer plus
Z24 readback for color-only, depth-only, both, no-op, nonzero depth seeds,
restricted preexisting viewports, odd widths, CT32 and opt-in CT16S with both
dither settings. Exercise initialization twice, all three video modes,
post-clear drawing, captures/wipes, scalar and VU paths, and near-full rings.

For timing on physical PS2, open/warm one frame, drain with `PS2HWD_Sync`, then
time batches of 1, 32 and 256 identical clears. Record the interval through the
last submission and separately through the following successful
`PS2HWD_Sync` FINISH. Record an empty Sync overhead control, QW, DMA kicks/waits,
timeouts and repeated alternating baseline/candidate runs. The completed
interval includes real CPU/submission/GS costs and is the relevant net number;
submission time alone cannot claim completed fill performance. Run a second
test with ordinary rendering between clears to cover ring/source-cache pressure.
Compare exact frames/depth, resident levels, upload/source selection,
cache eviction/reconstruction, quality budgets/caps and failures. PCSX2 remains
a functional gate; emulated EE cycle changes cannot certify physical GS speed.

Reproduction into new, never-reused stages:

```sh
python3 tools/ps2/next13_vram_clear_hosttest.py --encoding compact --negative-controls --out build/nov15-next13/vram-clear/stages/compact-replay-v1
python3 tools/ps2/next13_vram_layout_audit.py --out build/nov15-next13/vram-layout/stages/audit-replay-v1
```
