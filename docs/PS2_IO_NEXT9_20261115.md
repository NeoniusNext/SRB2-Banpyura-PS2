# Rejected pack-header RAM saving — ninth pass, 2026-11-15

**No ninth-pass I/O optimization is retained.** The proposed 768-byte BSS
saving changed allocator topology and increased resource-cache reconstruction
in the 32 MiB MAP11 pressure traces. The coordinator rejected it after an
isolated opt-out restored the preceding allocation/cache behavior and elapsed
time. Production `src/w_pack.c` is restored byte for byte to SHA256
`94532c49e6a1886677099849ce96ecd5e804eb2facd6a05c1732660443ab2664`,
committed as `2d0e8bf28f31a37c2d9ce2af9342f5f35284a69f`.

The rejected reader SHA256 is
`ec0065b0198695006f0019f237dcb8b0ea5ea2c9b351893af607c0f866ca8e06`.
Its full source is frozen in `io/rejected-candidate/w_pack.c`; the published
`tools/ps2/next9_io_rejected.patch` and checked `next9_io_variant.py` reconstruct
those exact bytes under `build/` without changing production. The reference
remains `19cf5df2a82b04e37fabe76a4441f3d5062ebaf1` and its frozen source.

the changed heap layout preserved performance.

including the Software kernel and revision metadata, were reused byte for byte.
The complete engine was merged and linked using the same SDK and wrappers.
The original IR objects, canonical ELF and engine were hash-checked unchanged

## Rejected representation and local costs

The remaining implementation and unit-proof details describe the rejected
candidate. It overlaid each of the six stream slots' 128-byte raw header
probes with the 64-byte parsed header and 64-byte parsed extension. The
existing `hdrok` flag selects these mutually exclusive lifetimes. Actual EE layout:

| Quantity | Before | After | Difference |
| --- | ---: | ---: | ---: |
| One stream record | 492 B | 364 B | −128 B |
| Natural alignment | 4 B | 4 B | 0 |
| Six-slot static BSS | 2,952 B | 2,184 B | **−768 B** |
| Pack/consumer full-LTO text sections, Software | 24,048 B | 24,256 B | +208 B |
| Pack/consumer full-LTO text sections, Hardware | 24,136 B | 24,344 B | +208 B |

The rejected BSS saving was fixed storage, independent of the number of open
packs. Slot count, full offsets/pointers/sizes, all header fields, path capacity,
device policies, windows, decoder buffers, prefetch capacity and allocations
are unchanged. There is no new persistent scratch, heap allocation or parser
callback. This is a static-storage change; no universal whole-game peak, heap
fragmentation, FPS, physical-console timing or CPU improvement is claimed.

## Lifetime and late probes

`ReadHeader` keeps its original local outputs and validation order. Only its
existing final successful assignments publish the parsed view, followed by
`hdrok = true`. Every rejected header or failed read retains every raw-cache
byte. A console error callback can reenter parsing without sharing temporaries.

An important reachable edge needs separate handling: after slot turnover,
`WPack_VerifyNMUS` or `WPack_GetLumps` can parse a stream before its first
signature probe. It then has `hdrok == true` and `magic == 0`. A later
`WPack_Detect` must still inspect the current source, while a valid cached
parsed header must survive that probe. Simply overlaying the fields would
overwrite the parsed cache.

`PeekCheckedMagic` handles that edge with a private 128-byte stack probe. It
uses the original zeroing, 128-byte `ReadBulk`, short-circuit signature test,
magic update and descriptor reset. Changed/truncated/non-pack sources retain
the previous detect/drop behavior; a source that still has the signature keeps
the preceding parsed-cache behavior. Ordinary probes keep their original
storage/read sequence. No caller pointer escapes the helper.

The rejected complete default-LTO code and both rejected linked ELFs agree on the
new helper's 176-byte body and **144-byte frame**, including its 128-byte
temporary and register saves. All existing pack/consumer frames are unchanged:
`PeekMagic` is 32 B, `ReadHeader` 192 B, and `ReadBulk`/`DevRead` 112 B each.
The late-probe transfer is a tail jump whose delay slot releases the caller's
32-byte frame. That edge therefore adds **112 B of local call depth** relative
to an ordinary probe. It does not create a recursive call or a new callback
stage; independently invoked/reentrant probes own independent temporaries.
These individual frames are not a universal thread stack-peak bound.

The isolated full-feature EE object also gains 208 B text, with unchanged
rodata and writable data and exactly 768 B less BSS. The existing aligned
LZ4/bounce-buffer reuse and read-only `WPack_CanReadWithoutAlloc` recovery
precondition are unchanged. No texture recovery/purge/pinning policy changes.

  --candidate build/next9-io-replay/w_pack.c \

python3 -B tools/ps2/next9_io_objectcheck.py --baseline src/w_pack.c \
