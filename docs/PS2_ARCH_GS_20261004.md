# PS2 architecture continuation: GS/GIF — 2026-10-04

The optional hardware renderer now sends short triangle fans through native GIF REGLIST. The vertex values and primitive state equal the previous PACKED path. This reduces the EE stores, GIF input and DMA traffic of already used GS drawing paths. This is a measured submission optimization, not proof of complete PC HW parity or whole-game FPS.

## Implementation

- `src/ps2/hw/ps2_hw_draw.inc`: a short fan uses one REGLIST GIFtag containing explicit PRIM followed by ST/RGBAQ/XYZ2 or XYZF2. PRE is zero because REGLIST does not apply the GIFtag PRIM field. Up to 16 native 64-bit registers fit the descriptor; NREG=16 is encoded as zero. Native RGBAQ contains each vertex's actual Q before the XYZ kick. The existing colour/Q cache is invalidated exactly as for perspective PACKED vertices.
- Native XYZ2/XYZF2 uses the same EE float expressions, saturation and integer conversion. ST values, modulation, fog and depth are preserved. Q=1 affine fans use exactly 1.0f without division, after the existing all-vertices unit-Q check. A 768-byte constant descriptor table removes an otherwise measurable per-fan loop.
- Larger fans, vertex-coloured sky and indexed triangle runs use the previous PACKED encoder. No fan is truncated or resampled; primitive order, pass order, clipping, texture sizes, palette, framebuffer precision, filtering, geometry and physics are unchanged.
- Packets are allocated as a whole from the existing 64-byte-aligned DMA producer ring, synchronized by its existing SyncDCache ownership protocol. An unused final half-quadword is initialized to zero. No new heap, DMA staging, VRAM allocation or runtime static BSS is introduced.
- `tools/ps2/hw_hosttest.c`: independently decode native REGLIST registers into the existing logical assertion representation. The decoder retains the physical DMA size for buffer-boundary checks and validates explicit PRIM, repeated descriptors, count and padding. All prior assertions and negative controls remain active.
- `tools/ps2/oct4_gs_hosttest.c/.py`: bit-for-bit comparison against the unchanged PACKED encoder for all five compact formats, odd/even register totals, full NREG=16, producer buffer-end reservation, RGBAQ cache invalidation and three deliberate corruptions.

The original `put_vertex` encoder was compared with the pre-edit source snapshot and is byte-for-byte unchanged (normalized source SHA256 `b61bd2476c72152ced98d0f9b3ddc068df202bc49c3b595eb09a1ff203e57895`). Source snapshots and baseline ELF are retained under `build/ps2-arch-gs-baseline-20261004/`.

## Executed validation

Builds used `SRB2_PS2_RELEASE=1`, `SRB2_PS2_HW=1`, `-O2 -Wall -Wextra -Werror`, separate `SRB2_PS2_OUT` directories and the actual driver. The emulator was launched only through `run_hw_test.py` -> `run_pcsx2.py` and its machine-wide lock, with the configured real 32-MiB RAM model.

```powershell

$env:SRB2_PS2_HW='1'
$env:SRB2_PS2_OUT='D:/Ai-Project3/SRB2-PS2-Port/build/ps2-arch-gs-baseline-20261004'
python -B tools/ps2/build_hw_test.py
python -B tools/ps2/run_hw_test.py --no-build --tag before --timeout 900 -- soak=60 ext

$env:SRB2_PS2_OUT='D:/Ai-Project3/SRB2-PS2-Port/build/ps2-arch-gs-final-20261004'
python -B tools/ps2/build_hw_test.py
```

The mixed 60-frame soak submits the same 18857 polygons, 67255 input vertices and 68482 output vertices. GIF quadwords change from 1356370 to 1324146 and DMA kicks from 516 to 513. It is not an uncapped engine-frame benchmark. The submission improvement should not be represented as a corresponding whole-game FPS gain.

## Scope and outstanding work

The optional HW driver benefits; software-renderer GS presentation is not changed. The existing CT32 default remains. CT16S is still explicitly lossy opt-in and was only tested for compatibility. No VU1 program, VU0 transform, IPU workload or hardware-engine feature was claimed solely to enumerate architecture capabilities.

Whole-game map FPS, physical EE cache/GS timing, high-resolution/PAL/480p engine scenarios and full PC hardware-renderer feature parity remain unverified by this continuation. Existing missing shader/water/palette/blend/large-resource capabilities listed in `HW_RENDERER.md` remain open. Integration should be rebuilt by the coordinator; this report does not mark G1/G2 or the HW renderer complete.
