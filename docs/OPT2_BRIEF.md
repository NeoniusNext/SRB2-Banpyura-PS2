# Бриф сессии 2026-10-04: FPS, стабильность, звук (3 агента)

Проект: нативный порт SRB2 2.2.15 на PS2 (EE R5900 294.912 МГц, GS 4 МБ VRAM, **32 МБ ОЗУ**), запуск только в PCSX2.
Рабочая копия `D:\Ai-Project3\SRB2-PS2-Port`, ветка `ps2`. Общее рабочее дерево, три агента одновременно, **никто не коммитит** (коммитит координатор).
Дерево на старте собирается: `SRB2_PS2_RELEASE=1 SRB2_PS2_OUT=<свой> python -B tools/ps2/build.py` → 108/108 файлов, ELF ≈ 7.4 МБ.

Обязательно прочитать: `docs/AGENT_BRIEF.md` (железные правила: ничего не утверждать без запуска, не менять игровую логику/RNG/демо/сейвы,
правки ядра только под `PS2`/`PS2_PROFILE`), `docs/OPT_BRIEF.md` (инструменты: `perf_phases.py`, `opt_run.py`, `run_ps2_ref.py`, хост-тесты, правила замеров),
`docs/PS2_MEMORY.md`, `docs/PS2_AUDIO.md`, `docs/DEVIATIONS.md`, отчёты прошлых сессий: `docs/GATES/g1/opt-S.md`, `docs/PS2_ARCH_{EE,AUDIO,GS}_20261004.md`,
`docs/PS2_SOFTWARE_OPT_20261003.md`, `docs/PS2_NEXT_*.md`.

## Цель пользователя (дословно по смыслу)
1. **Намного больше FPS** на PS2 и **намного выше стабильность**. Рендер и движок можно переписывать полностью, но **без потери графики, физики и прочего**
   (допустима небольшая погрешность: единицы пикселей на кадр, не накапливающаяся в физике; игровая логика/RNG/демо/сейвы — побайтно).
2. **Исправить глюки звука**: (а) при загрузке карт и прочих загрузках, (б) когда мало FPS (игра лагает).

## Известное состояние (измерено 2026-10-03/04, PCSX2, релиз)
* Бюджет: **8.43 М тактов EE на тик (35 Гц)**. Базовая линия DEMO_001/002: ≈ **25 М тактов/кадр** (BSP/стены 9.6-12.7, planes 5.6-6.7, masked 1.9-2.3, P_Ticker 1.5-4.4, audio ≈ 3.3-3.7 М, setup 1.8-2.7).
* Звук сейчас: микшер 22 050 Гц/16 бит/стерео/64 голоса, **выполняется в главном потоке** из `I_UpdateSound` (≤ 4 отправки за вызов, очередь ≈ 8192 Б ≈ **93 мс**).
  Пока главный поток занят (загрузка карты, чтение пака, медленный кадр, декодирование Ogg-эффекта при промахе кэша) — очередь audsrv пустеет → щелчки/зацикливание/пропуски.
* MAP11 (CEZ2) на стандартных 32 МБ: **падает** `PU_RENDERWORK` 524 288 Б в `Picture_TextureToFlat` (свободно ≈ 1.9-2.1 МБ, но наибольший блок 370-450 КБ — фрагментация).
  Эксперимент с переупорядочиванием выделения отклонён (`docs/PS2_ARCH_EE_20261004.md`). Это главная известная причина нестабильности.

## Реестр отличий и отчёты
Нумерация: A = `PS2-60..69`, B = `PS2-70..79`, C = `PS2-80..89`. Строки добавляй в `docs/DEVIATIONS.md` (перечитай файл перед записью, только свои строки).
Итоговый отчёт: `docs/GATES/g1/opt2-<A|B|C>.md` (1. что сделано; 2. команды и числа до/после; 3. не проверено/ограничения; 4. строки реестра; 5. нужные правки в чужих файлах).
Свои каталоги вывода: `SRB2_PS2_OUT=build/opt2-<x>/out`, `SRB2_PS2_RUN=build/opt2-<x>/run`. Эмулятор — только через обёртки (общая блокировка, очередь — норма).
Замеры — только релизная сборка (`SRB2_PS2_RELEASE=1`). Любая оптимизация = хост-тест эквивалентности (с негативным контролем) + замер до/после.
Если работа оборвётся — состояние должно быть пригодным: после каждого этапа дерево собирается, отчёт обновлён.
