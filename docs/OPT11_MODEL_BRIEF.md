# OPT11, агент MODEL: 3D-модели (MD3) и вся «трёхмерная» часть HW-рендерера на GS

Окружение, правила, команды сборки/прогона/эталонов — `docs/OPT11_BRIEF.md` (читай целиком). Состояние остальных агентов и профиль — `docs/OPT11_ROUND2.md`. Ты — шестой агент (реестр `PS2-HW-260..299`, отчёт `docs/GATES/g1/opt11-MODEL.md`).

## Требование пользователя
Портировать на PS2 HW-рендерер **3D-модели** и **всё, что связано с 3D и HW** — включая освещение моделей (Ambient / directional lighting, `gr_modellighting`) и прочее — так, чтобы GS HW умел всё, что умеет OpenGL HW-рендерер SRB2 2.2.15 Banpyura (в пределах железа PS2), без потери картинки и без падений. Данные игры — собственные файлы пользователя.

## Что есть и чего нет (проверено)
* Официальная раздача SRB2 2.2.15 (`/opt/dl-srb2/srb2full.zip`, уже скачана; распаковывай в **свою новую пустую папку вне репозитория**, например `/opt/srb2-assets-models/`, `unzip srb2full.zip 'models/*' models.dat -d <папка>`): **165 MD3 (16.6 МБ) + 208 PNG (1.3 МБ)**: `models/PLAY/{SONIC,TAILS,KNUCKLES,AMY,FANG,METAL_SONIC}.md3` (0.45–1.57 МБ каждая) + `*_blend.png` (карты для цвета скина), `models/OBJE/*`, `models/BOSS/*` (BRAK 1.46 МБ), `models/ENMY/*`, и `models.dat` (текстовая таблица «спрайт → модель, масштаб, смещение, поворот…»).
  `/opt/srb2-assets/models.dat` уже есть. В `srb2.pk3` моделей нет; ПК-движок читает `models/` с диска.
* PS2-движок: `hw_md2.c`/`hw_md2load.c`/`hw_md3load.c`/`hw_model.c` (общий код) собираются; драйверная часть — `src/ps2/hw/ps2_hw_model.inc` (`draw_model`, всего ≈ 100 строк; FX добавил `PF_ColorMapped`, PS2-HW-126). Проверено FX только на самодельном кубе (`tools/ps2/make_fxmodel.py`) — **на настоящих моделях игры не проверялось**. По умолчанию `gr_models Off` (как на ПК), поэтому модели в кадре не бывают.
* **Не реализовано/не проверено (список FX, раздел 3 `opt11-FX.md`):** `gr_modellighting` (направленный свет, `0.75 + max(n·(0,1,0),0)`: нужен вершинный цвет), покраска моделей цветом скина (`*_blend.png`, `HWR_GetBlendedTexture`), `gr_modelinterpolation` на настоящих моделях, PNG-текстуры моделей (в PS2-движке нет libpng — паки получили конвертированные «cooked pictures» только для PNG из pk3),
  загрузка `models.dat`/`models/` с PS2 (сейчас в логе: `Error while loading models.dat: I/O error` — файла нет рядом с ELF; должно быть тихо при отсутствии), память (32 МБ, арена 22–24 МБ, HW уже упирается: `docs/PS2_MEMORY.md`, `opt11-STAB.md`), `gr_lightdithering`, `gr_spritebillboarding`, `gr_shearing`, `gr_slopecontrast`/`gr_fakecontrast` (проверь реально), `gr_skydome`, `gr_filtermode`/`gr_anisotropicmode` (фильтрация/мипы — решать по железу), тени моделей, полупрозрачные модели, `PF_Decal`, `PF_Wireframe`, другие 3D/HW-опции меню Options → Video → OpenGL options.

## Задачи
1. **Конвейер данных моделей для PS2.** Расширь `tools/ps2/cook.py` (или добавь `cook_models.py`): `models/` + `models.dat` → пак `MODELS.PAK` (формат `docs/PACK_FORMAT.md`) с готовыми к загрузке MD3 (LZ4 для больших) и **текстурами, конвертированными на хосте** (PNG → RGBA/палитровый «cooked» формат, который PS2-движок читает без libpng; учти VRAM/CLUT и память: ≈ 1 МБ на крупную модель; грузить лениво и вытеснять — как `PU_CACHE`). Движок: загрузка `models.dat`/MD3/текстур из пака, тихий отказ при отсутствии (тогда спрайты, как сейчас), без `I_Error` при нехватке памяти (откат на спрайт; согласуй с `PS2HWFB`/зональным стражем STAB, `PS2-170`).
   Раскладку для запуска добавь в `tools/ps2/make_dist.py`/`opt_run.py` (stage копирует `*.PAK` — `MODELS.PAK` подхватится; проверь).
2. **Рендер моделей на GS по уровню ПК:** геометрия MD3 (покадровая интерполяция `gr_modelinterpolation`: Always/Sometimes/Off), culling, масштаб/смещение/поворот/flip из `models.dat`, модели игроков и объектов/врагов/боссов, прозрачность (`PF_Translucent` и т.п.), `RF_FULLBRIGHT/FULLDARK`, свет сектора и **освещение моделей** (`gr_modellighting` On/Off: направленный + ambient; вершинные цвета; на VU1 или EE), цвет скина (blend-текстуры; кэш по (модель, цвет)), тени/дроп-тень моделей, перекрытие со спрайтами/полигонами (Z, сортировка прозрачных), «ломаные» кадры (нулевые нормали, пустые меши) без падений.
   Скорость: модель — десятки-тысячи вершин на кадр; не пересчитывай интерполяцию на EE для каждой вершины, если можно на VU0/VU1 (отдельная микро-программа VU1 `ps2_hw_vu1_model.vsm`, чтобы не конфликтовать с VU2, который правит основную `ps2_hw_vu1.vsm`; начни с рабочего EE/VU0-пути, оптимизируй после), считай стоимость в тактах/кадр (`-ps2prof`, HWPROF) на сценах с несколькими моделями.
3. **Эталон — ПК-OpenGL** (`build/pc-ref`, команды в `OPT11_BRIEF.md`, FX-инструменты `tools/ps2/fx_pair.py`, `pcshot.py`, `fx_*`): ПК с `gr_models On` (и `gr_modellighting On/Off`, `gr_modelinterpolation`) на картах с моделями: игроки (Sonic в MAP01 под управлением демо/свой кадр), враги/объекты GFZ/THZ/DSZ, боссы; число и MAD. **Осторожно:** ПК-движок пишет cvar в общий `/opt/srb2-assets/reference.cfg` — работай с копией (`-config`/свой `-home`), по окончании не оставляй там `gr_models On`.
4. **Остальное 3D/HW (матрица):** по каждому `gr_*`/HW-опции и HW-эффекту ПК (список выше + `HWR_*` функции движка без PS2-реализации: `grep -n "hw_\|HWD\." src/hardware/hw_drv.h`, `src/ps2/hw/ps2_hwd.c` — пункты, помеченные «not implemented/stub») — таблица «реализовано / нет / отличается (величина)», реализация недостающего по убыванию заметности, начиная с моделей и их освещения. `gr_lightdithering`, `gr_spritebillboarding`, `gr_shearing` (наклон камеры сдвигом), skydome — решить по замеру (цена/польза), записать.
5. **Не навреди:** без моделей кадр не дороже (A/B `wall` на DEMO_001/004, 0 различий пикселей при `gr_models Off`); `gr_models On` не ломает сеть/сплитскрин/Lua; ПК-сборка не ломается (`ninja -C build/pc-ref`).
