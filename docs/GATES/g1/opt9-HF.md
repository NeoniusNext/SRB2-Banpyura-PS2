# OPT9, агент HF: GS Hardware Renderer — корректность картинки и паритет эффектов с OpenGL (отчёт, ведётся инкрементально)

Сессия 2026-10-06 (ночь). Каталог сборок/прогонов: `build/opt9-hf/{out,out-sw,outp,run,ref}`. Инструменты (копии opt8-h с правкой путей):
`mk.sh` (HW релиз), `mksw.sh` (software), `mkp.sh` (HW `--prof`), `run.py NAME --elf ELF -- <engine args>`, `maps.sh NAME ELF "1 2 4 ..."` (HW-прогон по списку карт, снимок на тике 300 каждой: `-vidshot k300=map~N,...`),
`pcshot.py` (эталон: ПК SRB2 из `srb2-assets`, OpenGL, 320x200, тик N), `pcall.sh` (эталоны ПК по списку карт, `ref/pc_m<N>_{gl,sw}_t300.png`),
`m4.py` (панели GL | HW | SW | разность, метрика MAD по размытым картинкам), `reg2.py` (регистрация аффинного сдвига/масштаба HW относительно GL).
Эмулятор — только `tools/ps2/run_pcsx2.py` через `run.py` (4 слота автоматически).

## 0. Состояние на старте (проверено запуском)
* HW релиз собирается (`build/opt9-hf/out`, ELF 10 219 052 Б, SHA драйвера 8ae2d2b7…); сохранён как `base.ELF`.
* Эталоны ПК-OpenGL получены для карт 1, 2, 4, 5, 7, 10, 13, 16, 22, 25, 30, 50, 51, 70, 72 (тик 300): `build/opt9-hf/ref/`.


## 1. Измерение (стадия 1): что видно в HW до исправлений
Метод: `-skipintro -warp N -renderer Hardware -vidshot k300,...` (новый вид снимка PS2-HW-60: `kN` = первый кадр с `leveltime >= N`, не зависит от частоты кадров; `KN` = то же, но только в уровне, начавшемся после предыдущего снимка — для цепочек карт `K300=map~N`),
сравнение с эталоном ПК (OpenGL, тот же тик, `build/opt9-hf/ref/`), `cmpmaps.py`/`m4.py` (панели GL | HW | SW | разность), `shiftscan.py`/`reg2.py` (сдвиг/масштаб).
* **Находка 1 (главная для паритета света).** `hw_InitShaders()` возвращал `false`, поэтому движок считал шейдеры недоступными (`gl_shadersavailable = false`, `HWR_UseShader() = false`):
  весь код света на GS (`LM_BANDS`/`LM_RAMP`, CLUT-тинт, fog-блоки, вода) в игре **никогда не выполнялся**; HW получал «запасное» плоское освещение движка (`HWR_Lighting`: constant `fade_alpha` на полигон).
  Цифры (THZ1, MAP04, средний цвет области стен R,G,B): ПК-GL = (95, 28, 9), ПК-GL без шейдеров = (97, 34, 13), HW = (79, 46, 27) — серая «вуаль».
* Геометрия: вертикаль/масштаб HW совпадают с GL (`reg2.py`: HW против GL и PS2-SW против ПК-SW дают одинаковое отношение масштабов ≈ 1.0); в разных картах камера на тике 300 отличается от ПК на несколько пикселей (чейс-камера), поэтому поточечное сравнение — только после регистрации.
* Нехватка текстуры: GFZ2 (`F:GFS_CLD2` 1024x1024, 4096 блоков) — `HWD texture not resident: no VRAM block (pool)`, потолок облаков не рисуется (полигон пропущен, `pool used 8064/12032, free ranges 1`).
  Причина — размещение/вытеснение пула (зона HT), но видимый эффект — дыра в картинке.
* Цепочка карт в одном запуске (`map~N`): в первом прогоне `I_Error: Out of memory allocating 829440 bytes` на третьей смене карты в HW (GFZ1 → GFZ2 → THZ1 → DSZ1) — задача стабильности (п. 3), не исправлена на этом этапе.


## 2. Стадия 2: свет как в GLSL (PS2-HW-61/62) — результат измерения
Правка: `hw_InitShaders()` возвращает `true` (кроме `-hwdbg 2048`), `hw_CompileShader()` — `true` для базовых шейдеров (слоты < `NUMSHADERTARGETS`), `hw_LoadShader()` молчит для них;
`HWR_ShouldUsePaletteRendering()` под `PS2_PROFILE` всегда `false` (на GS нет 3D-LUT палитры; PC по умолчанию `gr_paletterendering On`, но в обоих режимах ПК цвета близки — снято `pcshot` для карты 4 и 7).
Теперь движок передаёт `LightInfo/TintColor/FadeColor` и драйвер освещает по глубине (полосы GS fog с точными порогами класса `floor(R_DoomColormap)`, тинт — через CLUT, fade-цвет — FOGCOL).
Доказательство (тот же тик 300, ПК-OpenGL как эталон цвета; `cmpmaps.py`, ошибка среднего цвета по кадру, 0..255; было = `build/opt9-hf/run/b*`, стало = `run/h*`, `run/tb`):

| карта | MAD (размыт.) было → стало | ошибка среднего цвета было → стало |
|---|---|---|
| 1 GFZ1 | 22.7 → 17.7 | 12.6 → 0.9–1.2 |
| 4 THZ1 | 30.3 → 15.4 | 15.4 → 8.0 |
| 5 THZ2 | 24.1 → 18.4 | 17.0 → 6.1 |
| 7 DSZ1 | 42.2 → 13.8 | 39.2 → 7.8 |
| 13 ACZ1 | 21.1 → 19.2 | 14.8 → 6.6 |
| 25 BCZ1 | 16.6 → 13.6 | 7.3 → 1.4 |

(MAD остаётся ≈ 14–19 из-за разницы камеры ПК и PS2: чейс-камера на ПК стоит иначе — `rowreg.py` для PS2-software против ПК-software даёт то же рассогласование, что HW против ПК; HW против PS2-software совпадает по геометрии: `rowreg` y_sw = 1.02·y_hw − 1.0.)
Картинки: `build/opt9-hf/res/base_m*.png` (до) и `res/lit_m*.png`, `res/t1_m*.png` (после): панели ПК-GL | HW | ПК-software | разность.
Стоимость: `pl4` против `pf4` (THZ1, статичный кадр, окна по 105 кадров, `wall` ≈ 8.8–9.0 М оба): число полос света `bands` = 237 за окно (≈ 2 полигона на кадр режутся по глубине, остальные целиком в одном классе) — расход EE на свет в этой сцене ≈ 0.
Замечание: прогоны `pl4`/`pf4` первой серии имели 17+ аргументов, `-hwdbg 2048` был отброшен — оба шли со светом; честный A/B — ниже (п. 4).


## 3. Стадия 3: вода, предел UV, диагностика (PS2-HW-63..67), инфраструктура
* **PS2-HW-63 рябь воды** (`PF_Ripple`, шейдер 4): `emit_water_poly()` режет полигон по глубине полосами в 16 единиц (до 640) и сдвигает ST полосы на `(sin a, cos a) * 0.025`, `a = -pi * (z/2 * 0.025) + leveltime * 2` — как `GLSL_WATER_FRAGMENT_SHADER`. Ошибка ≤ 0.5 текселя (64-текс. флэт). Таблица синуса 256 + линейная интерполяция.
* **PS2-HW-64 предел UV**: полигон, у которого ST охватывает > 4096 текселей по оси (`UV_EXTENT`), режется по целым повторам (`cut_and_emit` стадии 0/1 теперь режет и степень двойки; шаг `cutlist_t.step`); быстрый путь такой полигон не берёт. Причина: целая часть U/V на GS 14 бит; на больших полах/горизонтах (до 27000 единиц) 14.4 переполняется. В PCSX2 (float) разницы нет — защита для реального GS.
* **PS2-HW-65**: состояние GS прохода 0 пишется один раз на план (`P.serial != H.serial`), а не на каждую полосу/кусок (`emit_piece`).
* **PS2-HW-66**: перепись эффектов (`HWFX frame N: translucent additive ... fogblock water tint fade-colour ...` раз в 300 кадров) — по ней видно, какая карта проверяет какой эффект. Карты 4 и 7: `translucent water tint fade-colour decal nodepth alpha-poly ripple-flag`.
* **PS2-HW-67**: `CONS_Printf/CONS_Alert` в `ps2_hwd.c` → `I_OutputMsg` (лог): строки драйвера («HWD texture cap 512 -> 1024 blocks», «WARNING: PS2 GS experimental limitation ...») рисовались поверх игры — видны на снимках `res/base_m1.png`, `res/t1_m4.png`. Это тоже «глюк картинки».
* **PS2-HW-60 инструменты**: `-vidshot kN/KN/wN`, клавиши `console`/`f1`/`f2` для `-vidkeys`, буфер спецификации 1536; `-hwdbg` починен (см. ниже).
* **Найденная ловушка тестов: PCSX2 передаёт ELF не более 16 аргументов** — 17-й и далее молча отбрасываются (в логе `HWE parms myargc=17`, значение `-hwdbg` терялось, поэтому прогоны `-hwdbg 2048/4096` на самом деле шли без флага). Обёртка `build/opt9-hf/run.py` теперь кладёт лишнее в ответный файл (`@r.txt`, `M_FindResponseFile`). Чтение `-hwtrace/-hwdbg` в `Impl_HWAcquire` заодно переписано последовательно (старый вызов вычислял оба `M_CheckParm()` в аргументах одного вызова с общим курсором — порядок не определён).
* **Приватное дерево** `build/opt9-hf/tree` (снимок `pre-opt9` + только мои правки) — чтобы чужие незаконченные правки (HT: `tex_view`, `img_of`, `lod_note`, `Z_ChangeTag ... no owner`) не ломали мои измерения. Правки зеркалятся в общее дерево скриптом `patchboth.py`. Быстрая сборка без LTO (`mkt0.sh`, ≈ 90 с) для функциональных проверок, с LTO (`mkt.sh`, ≈ 10 мин) для цифр скорости.
