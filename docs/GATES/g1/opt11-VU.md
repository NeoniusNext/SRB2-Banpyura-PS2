# OPT11, агент VU: GS Hardware Renderer — драйвер: VU1 / VIF1 / GIF (отчёт, дописывается по этапам)

Ветка worktree `worktree-agent-af8eb538583cafe96`. Единицы: такты COP0 EE на кадр (`HWPROF wall`), PCSX2 2.6.3 (32 МБ, программный GS), `-ps2prof`, релиз с LTO,
`-renderer Hardware -zreserve 1536`, окна по 105 кадров (окно 0 = загрузка карты, среднее и максимум по окнам 1..9), FPS = 294.912 М / такты. Реестр отличий: PS2-HW-100..119.

## 0. Как мерить (скрипты в `build/vu/`, не в git)
* `build/vu/mk.sh TAG [--prof]` — сборка полной конфигурации (`SRB2_PS2_NO= SRB2_PS2_HW=1`, `--jobs 2`) в `build/out-TAG` (`SRB2_PS2_LTO=0` для быстрых функциональных проверок:
  там два файла (`ps2_curl.c`, `d_netfil.c`) просят `-Wno-format-truncation`, mk.sh это делает).
* `build/vu/run.sh NAME TAG DEMO_00n [арг. движка]` — таймдемо в PCSX2, `python3 tools/ps2/hwsum.py --skip 1 NAME` — среднее / максимум окон 1..9.
* `build/vu/snap.sh NAME TAG MAPxx k100 [арг.]` — снимок карты (`-hwfbh 200`, 1:1), `build/vu/ab.sh TAG "карты"` — снимок с путём EE (`-hwdbg 268435456`) и с VU1, число различных пикселей.

## 2. Этап 1 — VU1 по умолчанию, палитровый свет с резкой по рядам на VU1 (PS2-HW-100)

### 2.1 Что сделано
* `src/ps2/hw/vu1/ps2_hw_vu1.vsm` написана заново (600 инструкций): трансформ, классификация по 6 плоскостям (guard band), отсечение Сазерленда–Ходжмана в общем цикле по таблице плоскостей
  (таблица загружается при старте VU1 и лежит в памяти VU1 всё время; код стал вдвое короче — 12 вариантов макроса не помещались в диапазон ветвления ±1024 инструкций),
  перспективные ST/Q, деление, Z, упаковка пакета GIF (ST, RGBAQ, XYZF2 или одни XYZF2 для плоских), XGKICK, двойная буферизация выхода.
* **Палитровый свет на VU1 без резки на EE:** программа сама считает ряд colormap по формуле SRB2 (`row = clamp(floor(max(base − K80/(lightz+1), cap)), 0, 31)`, `lightz = clamp((w − near)·kz/16, 0, 127)`)
  для минимальной и максимальной глубины полигона после отсечения; если ряды разные, режет полигон плоскостями `w = T_m` (T_m — глубина, где ряд становится m: одно деление на ступень) и каждый
  кусок выводит с A+D-пакетом `TEX0` (CBP ряда, CLD = 1) перед пакетом веера. Таблица TEX0 рядов (по QW на ряд) приходит с константами плана; драйвер гарантирует, что CLUT рядов `[rlo, rhi]` этой
  таблицы света есть в VRAM (`prow_blk`: слот проверяется по ключу, обычный `clut_get` при промахе).
* EE: `ps2_hw_vu1.inc` переписан: `vu_plan_setup` (ряды, состояние GS `pass_setup`, константы), `vu_poly` (проверка размаха UV, заголовок и вершины в чанк), чанки через UNPACK/MSCAL как раньше.
  VU1 теперь по умолчанию (`-hwdbg 268435456` = `HWDBG_NOVU1` выключает: путь EE как раньше, для A/B); `-hwvu1` ничего не делает.
* Пригодность к железу: константы плана идут за `FLUSHE`; `MSCAL` идёт за `FLUSH` (пакеты состояния PATH2 исполнены GS до пакетов PATH1 программы); каждый `DIRECT` за `FLUSH` (было);
  индекс выходного буфера и ряд, который держит GS, лежат в памяти данных VU1, а не в регистрах (между запусками ничего не предполагается о регистрах);
  следующий `XGKICK` ждёт предыдущую передачу, буфер переписывается только после него.

## 2.3 Этап 2 — свет на полигон, один открытый чанк для одиночных рисований, единые ряды CLUT (PS2-HW-101..106)
* `PS2HWD_PalLit` (PS2-HW-106): для палитровых полигонов уровень света больше не часть ключа батча. Заголовок полигона VU1 (QW0.y) несёт `light_level` сектора; программа считает `cap`/`base` ряда
  из него (константы `K_LIGHTB`). Партии больше не режутся по сектору: DEMO_001 248 → 76..95 батчей на кадр. `PS2HWD_DrawFans` получил тройки (first, count, light) (`hw_batching.c`, файл роли GEOM, правка только `#ifdef PS2`).
* PS2-HW-101: `H.clut_epoch` (+1 при каждой сборке CLUT-образа) — по нему проверяется, что таблица TEX2 рядов (`VU.rt`) по-прежнему указывает на нужные блоки VRAM; без пересчёта на каждый батч.
* PS2-HW-102: после записи CLUT-образа в VRAM идёт `TEXFLUSH` (на железе кэш текстур GS иначе может держать старую палитру; PCSX2 этого не показывает).
* PS2-HW-103: одиночные рисования (`hw_DrawPolygon`: HUD, тени, спрайты вне батча) идут на ту же программу VU1. Чанк остаётся открытым между вызовами; кто пишет в кольцо иначе (`pk_alloc/pk_ref/pk_flush`) — закрывает его сам.
  Рисование с тем же ключом плана (`vukey_t`, 28 слов) присоединяется к открытому чанку без `begin_draw` и без констант.
* PS2-HW-104: VU0 (макро-программа планировщика/трансформации) грузится лениво при первом использовании.
* PS2-HW-105: ряды CLUT «keyed» и «plain» различаются только записью 255. Текстура карты/плоскость без индекса 255 использует keyed-ряды в обоих вариантах → вдвое меньше CLUT-слотов; на DEMO_001 была
  «пробуксовка» кэша CLUT (84 сборки CLUT на кадр, `prow_ensure` 1.2 М) — пропала (rows=0..2).

## 5. Правки в чужих файлах
* `ps2_hw_draw.inc`, `ps2_hw_gs.inc`, `ps2_hw_vif.inc` — файлы роли VU (по брифу).
* `src/hardware/hw_batching.c` (роль GEOM): только `#ifdef PS2` — `HWR_DrawBatch` передаёт `count/3` и тройки (first, numVerts, light_level); хэш пересчёта батча не учитывает `light_level`, когда
  `PS2HWD_PalLit(...)` истинно. Интерфейс к кэшу геометрии GEOM: блок VU1 = заголовок (QW0: n, light; QW1: sb, tb), по 2 QW на вершину (x, y, z, 1 / s, t, 0, 0).
* `ps2_hw_tex.inc` (роль HT): `clut_build_into` (эпоха), `clut_write` (TEXFLUSH).
