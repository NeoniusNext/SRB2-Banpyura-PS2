## 5. Найденная ошибка PS2-511 (корень) и MAP11 в Hardware

**Ошибка в моём коде (PS2-511, коммит 517f4bf), найдена прогоном HW-отката на MAP11 с ZDEBUG-ELF.** `Z_LevelPoolAlloc` выдавал каждому куску пула один и тот же указатель-владельца (`&pool->chunk`). У пула с ≥ 2 кусков
у всех, кроме последнего, `*block->user != payload`, и `Z_CheckHeap(420)` в следующем `Z_FreeTags` (смена уровня) падал: `I_Error: Z_CheckHeap 420: block 19 doesn't have a proper user`; ZDEBUG-ELF показал
`block 15 tag 50 size 8240 (owned by z_zone.c:1123): user 0x64a530 holds 0xef7f40, outside the arena`. Демо-прогоны (по одному уровню на запуск, без `Z_FreeTags` после загрузки) ошибку не видели, поэтому «golden» на PS2-511 её не ловил —
её ловит только вторая загрузка уровня (цепочка карт, откат HW→SW). Исправление (коммит 03d3575): куски без владельца (`user = NULL`, для `PU_LEVEL` допустимо), пул помнит «эпоху» — счётчик `zlevelepoch`, который `Z_FreeTagRange`
увеличивает при любом освобождении тега `PU_LEVEL`; пул из прошлой эпохи берёт новый кусок. Проверено: тот же сценарий (HW MAP11, откат посреди загрузки) — `rc=0`, 60 кадров в software, `ps2_hwfb: fallbacks 1`;
цепочка `-zchain 02,11,01,02` на ZDEBUG-ELF: `check=ok` на каждом из 5 шагов (`Z_CheckHeap` с проверкой владельцев). Урок: до исправления PS2-511 нигде не был проверен сменой карты; полный прогон 84 карт/50 смен (раздел «стабильность») идёт на ELF после исправления.

**MAP11 в Hardware без отката на software — недостижимо в 32 МБ, измерено.** (1) На HEAD HW для MAP11 отключён статически (`PS2HWFB_PreLoad`: ≥ 14000 подсекторов, у MAP11 15 942), software падал на 22…24 кадре
(`OOM PU_RENDERWORK 65536 B` → «Back to the title screen»). (2) Теперь software держит MAP11 (раздел 3). (3) Принудительный HW (`-hwfbss 99999 -hwfbfree 0`): после `specials` свободно 1.81 МБ (PU_STATIC в HW 5.65 МБ против 4.41 в software:
драйвер и массивы пакетов), `HWR_CreatePlanePolygons` кончается на 52…76-байтной просьбе `PU_HWRPLANE` (`free 22 КБ`) → откат на software посреди загрузки, карта проходит. (4) Оценка потребности HW по самой большой HW-карте MAP23 (12 590 подсекторов, `-zck -zquit 40`):
после `specials` свободно 6.57 МБ, через 40 кадров 0.49 МБ, то есть HW съел 6.08 МБ: `PU_HWRPLANE` 14 698 блоков / 2.69 МБ (полезных 2.32 МБ; заголовки+округление 14 %), `PU_HWRCACHE_UNLOCKED` 1.67 МБ, `PU_CACHE` 0.96 МБ, пакеты `PU_HWRBATCH` 0.25 МБ.
MAP11 крупнее в 1.27 раза по подсекторам (полигоны ≈ 3.4 МБ) и свободно после `specials` 1.81 МБ: не хватает **≈ 4…5 МБ**. Состав `PU_LEVEL` MAP11 (16.08 МБ, ZDEBUG `-zowners`): пулы мобжей/ffloor/slope 3.66 МБ, `line_t` 2.61, `seg_t` 2.18, `side_t` 1.55 (36 Б),
`sector_t` 1.27, `node_t` 0.83 (52 Б), блокмап-лумп `INT32` 0.69 + `blocklinks` 0.28, вершины 0.47 (20 Б), `mapthing_t` 0.37 (92 Б), подсектора 0.32 (20 Б), ...: любая из статей урезается на десятки процентов только структурными правками (не побитно-безопасными без отдельной работы), нужно −30 % всего уровня. Остаётся только архитектурный путь:
строить полигоны плоскостей лениво/потоком в HWFRONT (≈ −3.4 МБ) и ужать статику драйвера (≈ −1.2 МБ) — это файлы `hw_bsp.c`, `ps2/hw/*`, не CORE; в отчёт HWFRONT/HWDRV передано как предложение с числами. Откат MAP11 HW → software сохранён (по замыслу, без регрессий).
