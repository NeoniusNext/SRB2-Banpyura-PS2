## 1. Находка: ELF вырос на 786 КБ из-за сборки (ест арену напрямую)

* `build/opt4-s/out/size.log`: text 3 122 000; `build/opt5-s/out` (текущее дерево, `python tools/ps2/build.py`, релиз): text **3 901 136** (+779 КБ). Разница по символам (`nm -S`): `fineacon` +524 288 Б
  (таблица arccos из `tables.c`, никем не вызывается без Lua), `eng.lto_priv.0` +68 КБ и ещё сотни КБ мёртвого кода/данных.
* Причина: LTO-шаг `build.py` (PS2-93, `gcc -r -flinker-output=nolto-rel`) получает из CFLAGS только `-G*`/`-mno-abicalls`, без `-ffunction-sections -fdata-sections`;
  результат - крупные секции без раздробления, и `--gc-sections` при линковке не выкидывает мёртвые функции/таблицы.
* Проверка (копия build.py `tools/ps2/_build_s_tmp.py` с `-ffunction-sections -fdata-sections` в `rcmd`, каталог `build/opt5-s/out-gc`, тот же набор объектов):
  text **3 269 984** (-631 КБ), ELF 7 561 416 Б против 8 234 768. Это 631 КБ арены даром (каждый КБ арены - меньше перестроений кэша и OOM).
* **Нужная правка в чужом файле (owner C, `tools/ps2/build.py`, строка с `rcmd = [...]`)**: добавить `'-ffunction-sections', '-fdata-sections'` к флагам LTO-шага. Я её не вносил в `build.py`.
