# OPT13, агент IZ: детерминированная зона и всплески кадров (реестр PS2-600..)

Ветка `opt13i-iz` (worktree `/home/user/wt/iz`), база `ea3d0fa`, PCSX2 2.8.2, релизная LTO-сборка `--prof`, HW-рендерер, 4 демо `-timedemo`, паки `build/pak2` (+ `TEXC.PAK` в `build/pak-iz`).
Единицы: такты EE (COP0 Count) на кадр, среднее окон 1..9 (945 кадров) по строкам `HWPROF`; «окно max» — худшее среднее окно; `wmax` — худший кадр окна (`HWPROF0 wmax=`, wall одного
кадра, включает ожидание vsync); `p50/90/99` — процентили кадров окон 1..9 (`HWFH`, ведро 1 М); `regen` — события `HWREGEN` (> 2 М тактов). Сводка по прогонам — `tools/ps2/iz_sum.py` (`build/runs/NAME/boot.txt`).
A/B везде на ОДНОЙ ELF флагом (`-zfront 0|1`, `-hwgcdead 0|1`, `-notexc`, `-zroomcost 0|1`, `-zpartial 0|1`, `-hwwarm M`), кроме сравнения с базовой ELF (`ea3d0fa` без правок).
Ёмкость арены: `-zreserve KiB` (по умолчанию 512 КиБ; арена 22 876 КиБ при 512, 21 852 при 1536, 19 804 при 3072).

## 1. Z1: ограниченный `Z_MoveFrontier`, режим арены в журнале, кэш геометрии без «навсегда» (PS2-600, PS2-601)

### Что сделано
* **`ZA_FrontBlock` / `ZA_SetAnchor`** (`ps2_mem.c`): блок, в котором лежит граница, находится от «якоря» (начало блока на/ниже границы), а не обходом арены с начала. `ZA_Free` (слитый блок начинается
  с первого байта: якорь внутри него переносится на начало) и `ZA_Resize` поддерживают якорь; выделение только добавляет границы блоков. Результат становится новым якорем: следующий вызов проходит только блоки,
  созданные после предыдущего.
* **`Z_MoveFrontierNear`** (`z_zone.c`): то же решение, что у обхода арены (первая цепочка свободных и вытесняемых блоков, доходящая до границы), но цепочка ищется вперёд и назад от блока границы
  (назад: свободный блок по `ZA_PrevFree`, кэш-блок как соседний элемент реестра), не больше `Z_FRONT_WALK_MAX` = 1024 блоков в каждую сторону; вытеснение идёт от блока, где лежит новая граница.
  Старая реализация осталась как `-zfront 0` (A/B на одной ELF). `-zfront 2` — доказательство: на каждом вызове блок границы по якорю сравнивается с обходом от начала арены.
* **Журнал режима арены:** строка `ZMODE level: capacity … free … reclaimable … largest free …` в конце загрузки уровня; `ZMODE cap=… free=… reclaimable=… | slow=N (циклы) front calls=… failed=… walked=… (циклы)
  down=… up=… zoneless=… | lru last resort … | anchor checks … bad … | registry …` в каждом окне `HWPROF`; `[zslow]` в `-zreport`. `Z_ArenaCapacity()`, `Z_ReclaimableBytes()` (свободные + вытесняемые кэши) — новые функции зоны.
* **Кэш геометрии** (`hw_gcache.inc`): решение «создать / расти» принимается по `Z_ReclaimableBytes()` (что зона может отдать), а не по мгновенному `Z_ArenaFree()`; отбор зоной (`HWR_GCacheReclaim`)
  больше не навсегда: пауза 210 кадров, повтор вдвое дольше каждый раз, не больше 5 раз за уровень (`-hwgcdead 1` — прежнее правило). `HWPROF32` получил `dead=` и `tries=`.
* **Диагностика, нужная для замеров** (`i_video.c`): `HWPROF0 wmax= spikes=`, `HWFH` (гистограмма кадров), `HWSPIKE` (первые 40 кадров > 15 М с разложением по стадиям и драйверу).

## 2. R2: готовые композиты текстур (LZ4HC) в `TEXC.PAK` и читатель (PS2-602)

### Что сделано
* **Формат:** `TEXC.PAK` — необязательный пак рядом с ELF (как `MODELS.PAK`): тот же контейнер SRP2 v2, читают те же читатели; движок без него работает как раньше, пак v1/v2 игры не меняется (подробно — `docs/PACK_FORMAT.md`,
  раздел «TEXC.PAK»). Лампа = пиксели композита `w*h` байт (индексы палитры, 255 = дыра), имя = 16 hex-цифр ключа определения текстуры; `TEXCINFO` — лампа 0.
  **Ключ** (`PS2TexC_Key`, `src/ps2/ps2_texc.c`): FNV-1a 64 по размеру, типу, числу патчей и по каждому патчу (wad, lump, origin, flip, alpha, style) + тройка контрольных сумм пака-источника патча
  (`chktable`, `chkpool`, `chkcrc` расширения v2: сумма таблицы CRC32 покрывает содержимое каждой лампы); для прозрачного патча — ещё лампы `TRANS10..TRANS90`. Определение аддона, патч не из пака v2, стиль смешивания
  кроме copy/translucent, квадратный флэт (пол) — ключа нет, текстура собирается из патчей как прежде: **устаревший композит показать нельзя**.
* **Кукер:** `tools/ps2/cook_texc.sh PAKDIR OUTDIR` — хост-движок (профиль PS2 на x86: тот же `r_textures.c`, `w_pack.c`, код патчей, та же функция ключа) читает паки, строит список текстур и собирает каждую подходящую
  (`-texcdump`, ≈ 1 с); `tools/ps2/cook.py --texc DUMP --out DIR` упаковывает (LZ4HC, повторы пикселей хранятся один раз).
  `TEXC.PAK`: **3309 композитов, 129.7 МБ пикселей → 15.7 МБ (12.1 %)**, лампы в порядке списка текстур (текстуры зоны лежат рядом), 59 с на 3 ядрах.
  Состав: 3318 из 4740 текстур списка (остальные — квадратные флэты-полы, 30 текстур с патчами не из паков v2, 3 больше 1 МиБ, 3 с `AST_SUBTRACT`); сюда вошли вертикальные перевороты, прозрачные патчи и
  флэты-стены (небо `SKY4` — флэт 512x768, 151 патч; `SKY1`, `SKY8` — прозрачные и перевёрнутые) — самые дорогие текстуры игры.
* **Читатель** (`w_pack.c`: `WPack_ReadRaw`, `WPack_DecodeMem`, `WPack_Identity`; `ps2_texc.c`): первое действие `HWR_GenerateTexture` для P8-текстуры — `PS2TexC_Fetch`: сохранённая форма из предзагрузки уровня или одно чтение
  лампы, декодирование прямо в блок данных текстуры. **Предзагрузка** (`PS2TexC_PrefetchLevel` в конце `P_LoadLevel`, пока экран загрузки): сохранённые формы текстур уровня (стороны, небо, анимации, к которым они
  относятся) читаются отсортированными по положению в паке, с объединением близких лампов в одно чтение (щель ≤ 16 КБ, ≤ 256 КБ), в один блок `PU_LEVEL`, если в арене есть запас (свободно ≥ размер + headroom + 1 МиБ; `-texcmem KiB`, по умолчанию 1024).
  `-notexc` — выключить; `-hwdbg 16777216` — сверять каждую текстуру при сборке; `-texccheck` — сверить все.

### Доказательство побайтного равенства (`-texccheck`, MAP01, PCSX2)
`TEXC check: 3318 textures checked, 0 differ; 0 eligible textures have no stored composite` — каждый сохранённый композит побайтно равен тому, что даёт **оригинальная** колоночная композиция движка
(`ps2_slow_composite`, не быстрый путь) на EE; хост-кукер и консоль считают один и тот же ключ (ни одной подходящей текстуры без композита). Дамп хоста воспроизводим (повторный запуск — тот же файл).
