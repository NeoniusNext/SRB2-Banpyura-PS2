## 6. Маска Lua-хуков (RTICK L-1)

`src/lua_hook.h`, `src/lua_hooklib.c`, `src/p_mobj.c`. Вместо глобального `lua_mobjhooks_any` (после первой регистрации любого хука мобжа любого вида на любой тип все `LUA_HookMobj / Hook2Mobj / HookMobjLineCollide` каждого объекта шли в `*Slow`: `prepare_mobj_hook` → `init_hook_type` → `mobj_hook_available`, всегда с ответом «нет») — `UINT32 lua_mobjhookmask[тип]`: бит k = на этот тип зарегистрирован хук вида `MOBJ_HOOK(k)`, строка `MT_NULL` = хуки на все типы. `LUA_MobjHookWanted(mo, вид)` даёт тот же ответ, что `mobj_hook_available` (то же условие, `mo == NULL` — только строка `MT_NULL`), и вызывается встроенно; без хука `*Slow` не вызывается. Маска растёт в `LUA_GrowMobjHooks` вместе с таблицей типов, бит ставится после `add_hook`. `P_SceneryQuick` (быстрый путь неподвижной декорации, PS2-203) теперь отказывается только для типов с хуком `MobjThinker` (единственный хук, который быстрый путь пропустил бы: у него `fuse == 0`, движения нет), а не для всех типов после любой регистрации.
Условия и порядок вызова хуков не меняются: проверка эквивалентна проверке внутри `prepare_mobj_hook` (при недоступном хуке `init_hook_type` не трогает стек Lua и возвращает умолчание: 0).

## 7c. Самопроверка отсева спрайтов HWC и находка: Vorbis затирал матрицу рендерера в VU0

**Что проверяется.** `HWR_ProjectSprite` бросает вещь, чей квад не содержит центра пикселя (PS2-HW-72/240). Два теста: точный (`HWR_PS2_SpriteHidden` → `PS2HWD_QuadHidden`, по умолчанию версия на VU0 `quad_hidden_vu0`) и дешёвая сфера (`HWR_FX_SpriteHiddenCheap`). Режим `-hwdbg 16777216` оставляет спрайт (`vis->ps2_hid` = 1 точный / 2 сфера) и в `HWR_DrawSprite` сверяет с эталоном `PS2HWD_QuadVisibleRef` (квад режется всеми шестью плоскостями в double, поле на 0.01 пикселя меньше, чем у драйвера); печатает `HWC sprite cull check: N sprites, M differ (exact test a/b, sphere test c/d)` и для первых 12 расхождений — спрайт, кто отсёк, ещё раз точный тест, ограничивающий прямоугольник эталона. Прежняя проверка спрашивала `PS2HWD_QuadHidden`, который для квада у глаза отвечает «не скрыт», и показывала 2…67 % «расхождений», не бывших ошибкой.

**Атрибуция** (DEMO_001/002/004, ELF до исправления): сфера ни разу не ошибается (0/44957, 0/19312, 0/159247); все расхождения даёт точный тест: D1 446 из 2147 отсечённых им, D2 2056 из 3216 (D4: 0 из 497, D3: проверок меньше 1024, строки нет). Типичный случай: далёкий мелкий спрайт (фейерверк, `FWR5`/`THZP`), ограничивающий прямоугольник эталона 1.2 × 3.6 пикселя — квад с таким прямоугольником центр пикселя содержит всегда, т. е. отсечён зря.

**Диагноз.** `-hwqh 1` (скалярный `quad_hidden_ref` вместо VU0): **0 расхождений из 21504** (точным тестом отсечено 1258). По умолчанию (VU0): 2514…2635 из 21504…22528 (точным 3423…3676). Временный дамп (в коммит не вошёл) показал клип-координаты четырёх вершин, посчитанные `quad_hidden_vu0`, вида −7.1·10^7 (все x, y, z, w почти равны) при −1301…5353 у скалярного расчёта: в vf21..vf24 лежит не матрица. Причина: ядро PS2 не сохраняет COP2 при переключении потоков (`tools/ps2/ee_tests/vu0ctx.c`), поток декодера Vorbis приоритетнее игрового, а его секции (`ps2a_vu0_enter/leave`, `src/ps2/vorbis/ps2_vu0a.h`) сохраняли только vf1..vf18, хотя `ps2a_conv` (float → s16 PCM) кладёт свои константы в vf20..vf23 (clamp-ядра используют vf30, vf31). Рендерер (PS2-HW-220) грузит матрицу в vf21..vf24 один раз на `xf_ver` (`vu0b_mvp`), т. е. после любого куска декодера и до следующей смены матрицы и тест спрайтов, и планировщик (`plan_part`, `vu0b_mvp` строки 337, 408) считали с матрицей из PCM-констант. Побочный эффект: отсев спрайтов с видимыми пикселями (мелких, далёких) и неверные данные планировщика текстур, зависящие от момента, когда поток декодера успел поработать.

**Исправление** (`ps2_vu0a.h`): секция сохраняет и восстанавливает vf1..vf31 (`r[31][4]`; +13 `sqc2` и +13 `lqc2` на секцию, ≈ +50 тактов на кусок декодера, PCM не меняется: добавлены только сохранения и загрузки, вычисления те же). Ни ACC, ни Q, ни clip-флаг ядра декодера не трогают (как и раньше).
