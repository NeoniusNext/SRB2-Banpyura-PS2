## 2. uninit_fixes (RCACHE U1) и `-zpoison`

Патч `uninit_fixes.patch` лёг без правок (`r_portal.c`: границы в начале условия; `s_sound.c`: `Z_Calloc` для `channels`; `r_things.c`: обнуление vissprite). Вторым коммитом (IQ-2b) обнуление vissprite сужено до двух мест, которые заполняют спрайт частично (`R_ProjectDropShadow`, `R_ProjectBoundingBox`): патч исследования обнулял **каждый** vissprite в `R_NewVisSprite`; измерено, что это +0.8 % кадра software D1 (8.307 → 8.373 М), а `R_ProjectSprite` заполняет всё, что читается (memcheck 4 демо чист).
Новый ключ `-zpoison` (`src/z_zone.c`, `Z_MallocInternal`): каждый новый блок зоны заливается 0xA5 (то же, что `MALLOC_PERTURB_` на хосте). В PCSX2 ОЗУ при старте нулевое, на консоли нет, поэтому чтение непроинициализированной памяти там молчит; с ключом оно видно в эмуляторе. Цена вне ключа: один булев тест на выделение.
**Проверка:**
* host, `MALLOC_PERTURB_=90`, 4 демо, хэши 1050 кадров против чистого прогона: база — D3 расходится в **23 кадрах** (D1, D2, D4 — нет; как в исследовании), с исправлением — 0 расхождений на всех четырёх;
* host, valgrind memcheck `--track-origins=yes`, 4 демо целиком: с исправлением **0 ошибок / 0 контекстов** на D1, D2, D3, D4 (исследование: база D1 108 ошибок/1 контекст, D3 78/3);
* EE, golden software (`--ps2ref` ELF, `golden_full`-цикл): D1..D4 «0 differ» и `tics.csv` совпадает с `golden/ps2-head` и `golden/phase0-v2/run1`;
* EE, **те же 4 демо с `-zpoison`**: «0 differ», `tics.csv` тот же (RESULT OK ×8) — вывод не зависит от содержимого новых блоков зоны.
Файлы: `src/r_portal.c`, `src/r_things.c`, `src/s_sound.c`, `src/z_zone.c`.

## 4. rdrv 0001 и 0002

**4a (0001).** `static FOutVector pts[4096]` внутри `PS2HWD_TestVU0` (режим `-hwvu0bench`) → `malloc`/`free` в самой функции. `size`: `.bss` 2 307 160 → 2 225 248 Б (**−81 912 Б**); арена зоны в журнале `Zone arena:` 22 876 → 22 956 КиБ (+80 КиБ).
**4b (0002).** Взяты пункты (а)–(в) отчёта RDRV, колонковый путь (г) не взят (отчёт: прироста нет). Правки: `hw_cache.c` (`HWR_GenerateTexture`: лумпа читается целиком только для флэта; патч, который кладётся в текстуру повторно, строится один раз на текстуру — список до 32 удерживаемых патчей; патч читается без `Patch_CreateGL`), `w_wad.c/h` (`W_CachePatchNumPwadNoGL`), `ps2_hwd.c` (`-hwcomp 0` — прежняя сборка, A/B на одной ELF; `-hwcomp 1` и по умолчанию — новая).
Отличие от патча исследования: условие пункта (а) там было `defined(NO_PNG_LUMPS)`, а в полной конфигурации (`HAVE_PNG`, `SRB2_PS2_NO=`) `NO_PNG_LUMPS` не определено, т. е. (а) в продукте было бы выключено. Здесь (а) включено и в полной конфигурации: для не-флэта лумпа не читается, PNG-лумпа в составной текстуре (только у надстроек) преобразуется внутри `W_GetPatchPwad` тем же вызовом `Picture_PNGConvert`, что и прежняя ветка.
**Эквивалентность картинки:** `-hwdbg 16777216` собирает каждую текстуру ещё раз прежними циклами **и прежней обработкой патчей** и сверяет байты: D1, D2 — «HWC composite check: 64 textures identical, 0 differ», D3, D4 (меньше 64 текстур) — ни одной строки `MISMATCH`; «HWC patch composite check» (патчи HUD/спрайтов): 416…736 патчей, 0 расхождений.
