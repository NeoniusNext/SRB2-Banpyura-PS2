# OPT10, агент HF: GS Hardware Renderer — корректность картинки и паритет эффектов с OpenGL (отчёт, дописывается по этапам)

Ветка worktree: `worktree-agent-a48617638a6de29c5`. Окружение Linux (PCSX2 2.6.3 AppImage, программный GS по умолчанию). Каталоги: `build/ref` (эталоны ПК-OpenGL),
`build/runs` (прогоны PS2), `build/panels` (панели ПК-OpenGL | PS2-HW | разность и метрики JSON). Все картинки в отчёте — в `docs/GATES/g1/opt10-hf/` (уменьшенные PNG).

## 0. Инструменты (новые, закоммичены)
* `src/ps2ref.c` (только ПК, `#ifndef PS2` внутри `PS2REF`): `-ps2ref-shot SPEC` — движок ПК делает **свой** скриншот (OpenGL: `glReadPixels` кадра) в тех же кадрах, что и PS2 `-vidshot`
  (`tN` N-й кадр титула, `lN` уровня, `fN` любой, `kN` первый кадр с `leveltime >= N`, `KN`, `wN` кадр wipe, `iN` кадр интермиссии; `=команда` консоли после снимка);
  `-ps2ref-keys 20:enter,50:console` — нажатия по номеру кадра; `-ps2ref-cmd 'con_hudlines~0;...'` — команды консоли на 3-м кадре. На PS2 те же `-vidshot`/`-vidkeys` + `-vidcmd` (i_video.c).
* `tools/ps2/pcshot.py` — запуск ПК-движка под Xvfb + llvmpipe (`build/pc-hf`: `cmake -S . -B build/pc-hf -G Ninja -DSRB2_CONFIG_STATIC_STDLIB=OFF -DSRB2_CONFIG_USE_GME=OFF -DSRB2_CONFIG_PS2REF=ON`),
  результат `build/ref/<name>/shot-<n>.png` (320x200, ≈ 15 с на снимок). `--demo DEMO_00n`, `--cmd`, `--keys`, `--sw` (ПК-software).
* `tools/ps2/hf_run.py` — прогон PS2 (stage как `opt_run.py`, но с `--cfg`, `--demo`, `--emu`): `--emu /opt/pcsx2/hwgl/AppRun` — копия PCSX2 с **аппаратным OpenGL-рендерером GS** (`Renderer = 12`, llvmpipe): второй «GS» для поиска ошибок,
  которые программный GS прощает.
* `tools/ps2/hfpanel.py` (панель и метрики MAD / MAD по размытым / % пикселей с разностью > 48), `hfbatch.py` (карты: ПК-эталон + HW + панель), `hfseq.py` (кадры демо), `hfshift.py` (суб-пиксельная регистрация), `hfpix.py` (значения пикселей).
* `-hwfbh N` (диагностика, PS2-HW-68): внутренний кадровый буфер N строк (200 = без растяжения 200 -> 224, 1:1 с ПК).

Выводы стадии 1 (по измерению):
1. **Пять карт из 13 в полной HW-сборке не загружаются (OOM)** — это не картинка, а память зоны (арена 21.2 МБ при HW: `PU_STATIC` 5.8 МБ + уровень 4.5 МБ + кэш данных текстур HW 2–4 МБ + фрагментация 80–94 %). Задача S/HT, но для пользователя это первое, что «ломается» в HW.
2. На загруженных картах HW-кадр совпадает с ПК-OpenGL по геометрии и положению текстур (регистрация `hfshift.py`: лучший сдвиг 0.00/0.00 px по HUD, стенам и полу). Остаточное MAD 4–14 — цвет/свет и ресэмплинг (см. ниже).
3. **Цвет света отличается систематически**: ПК по умолчанию включает «палитровый рендеринг» (`gr_paletterendering On`): каждый тексель получает цвет `палитра[colormap[уровень_света][индекс]]` (как в software),

   Вода DSZ1 на ПК по умолчанию тёмно-синяя, в HW — бирюзовая.
4. Снимок `-vidshot` HW — билинейный ресэмплинг 224 -> 200 строк (внутренний кадровый буфер 320x224): мягкие края HUD в панелях — артефакт **снимка**, а не вывода на экран (`-hwfbh 200` даёт 1:1).

## 2. Стадия 2: палитровый рендеринг на GS (PS2-HW-71) — главный разрыв паритета света

Находка (измерением): ПК-OpenGL по умолчанию рисует с `gr_paletterendering On` (цвет = `lighttable[индекс][строка]`, затем экранная палитра 565), то есть так же, как software. Движок на PS2 это отключал (PS2-HW-62 OPT9, `HWR_ShouldUsePaletteRendering() == false`)
и освещал формулой GLSL (`mix(цвет, fade, darkness)`), что на самом деле картинка ПК с `gr_paletterendering Off`. Проверка: DSZ1 (MAP07) ПК palette Off против HW — MAD 5.3, а против ПК по умолчанию — 14.1; признак палитровой картинки — 100 % пикселей на сетке RGB565 (`tools/ps2/hfgrid.py`).
(Побочное открытие: часть ПК-эталонов старта (карты 25/30/50/70) была снята llvmpipe без шейдеров — не на сетке 565; `pcshot.py` теперь проверяет сетку и повторяет снимок.)

Реализация (GS умеет таблицу цветов как CLUT):
* `src/ps2/hw/ps2_hw_pal.inc` — таблицы света движка (32 x 256 RGBA) хранятся как палитровые индексы (8 КБ на таблицу, `lt_store`), `out_pal()` = экранная палитра (flash / 565) вместо палитры текстур во всех CLUT палитровых текстур;
* полигон с `LightTableId` и PSMT8-текстурой режется по глубине там, где меняется строка таблицы (лестница `ps2_hw_light.inc`; классы 0 и 1 — одна строка: `lightp_t.pal`), каждый кусок рисуется с CLUT своей строки (`CK_LIGHT`, ключ = таблица + поколение + строка);
  fog GS для таких полигонов не используется; быстрые пути (`lit_fast_poly`) меняют CLUT при смене строки; путь VU1 для таких планов выключен (`P.vuok`);
* `hw_SetScreenPalette` — вспышки (урон, предметы, вода) применяются при построении CLUT, постобработка не нужна; финальный экран — сам кадр (`GENERIC2`), копия `GENERIC3` не делается; цветовой UI-fade (`SHADER_UI_COLORMAP_FADE`) на PS2 — полупрозрачный чёрный квад (путь без палитры);
* прямые цвета (CT32), плоские цвета, fog-блоки, спрайты с частичной прозрачностью остаются на уравнениях GLSL; текстуры карты остаются P_8 + chroma key (`textureformat` не переключается на AP_88), оптимизации HT (zero-copy, LOD, общий образ) работают;
* `clut_get`: прямое индексирование по хешу ключа перед линейным поиском по 124 слотам (PS2-HW-72) — запрос CLUT на каждую смену строки.
