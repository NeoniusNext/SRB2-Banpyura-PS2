# OPT10, агент HG: GS Hardware Renderer — геометрия и CPU-путь (отчёт)

Ветка `worktree-agent-a5f093907a411cb86` (слита с `claude/determined-knuth-8c4nbi`: X, HT, SW). Единицы: такты COP0 EE на кадр (`HWPROF wall` / `PROF total`), PCSX2 2.6.3 (32 МБ, программный GS), `--prof` = боевой путь кода
+ счётчики, релиз с LTO, `-timedemo DEMO_00n.lmp -ps2prof`, окна по 105 кадров (окно 0 = загрузка карты, среднее по окнам 1..9), FPS = 294.912 М / такты.
HW-прогоны: `-renderer Hardware -zreserve 3072`, настоящие текстуры (база после слияния HT). Скрипты лежат в `build/` (не в git): `mkp.sh`, `bench.sh`, `benchsw.sh`, `finalm.sh`, `verify.sh`, `rt60.sh`, `hwsum.py`, `cmpsets.py`.
**`-hwdbg` принимает десятичное число** (`atoi`).

## 1. Сделано

Цель задания (HW `wall` ≤ 8.4 М на всех 4 демо и явно ниже software) **не достигнута**: HW на 15 % (D1), 5 % (D2), 2 % (D3, окна 1–2), 13 % (D4) быстрее базы `fef4b4e`, но software на тех же демо быстрее или равен HW (раздел 2.2).

Этапы (подробности и промежуточные числа — приложение A; номера реестра — раздел 4):
1. **Чистая стоимость геометрии** (`-hwdbg -2147483648` = `HWDBG_NOUP`, только измерение): до текстур HT геометрия стоила 12.75 М/кадр на DEMO_001 — это то, что разбиралось.
2. **Вода одним проходом** (PS2-HW-47, 57), **кэш света сегмента** (51), **сортировка спрайтов слиянием** (50), **батчинг спрайтов** (52), **`clip_poly`**, `hw_floorf`, `min.s/max.s` (53, 54), **вид скайбокса**: купол неба по экранному фрустуму (56), быстрый вертикальный цикл плоскостей (49, 58, 58b), память класса света по диапазону глубин (43b).
3. После слияния с HT (мерж `d53dc54`) — этот раунд, **PS2-HW-59**:
   * лёгкий путь `lit_fast_poly` берёт и **обрезанные** полигоны одного класса света (раньше любой клиппинг отправлял полигон в `cut_and_emit`): скалярная проекция `emit_reglist_fan`, как в `emit_piece`;
   * **память ступеней света на план** (`lf_thresholds`, `lf_fog`): глубина каждой ступени `doom_depth_of_level` считается один раз на план (три деления на вызов), `cut_and_emit` и вода не вызывают `doom_thresholds`, когда оба конца в одном классе;
   * **`clip_attr2`**: обе части одного разреза за один проход по рёбрам (точка на ребре считается один раз и идёт в обе части);
   * `(u32)(int)zf` вместо беззнакового преобразования float (одна команда вместо сравнения и перехода; `0 <= zf <= Z24`);
   * **парный VU0-трансформ** `vu0_xform2` (два вершины за последовательность: умножения второй скрывают деление первой, один `cfc2`): 65 -> 54 такта на вершину, результаты **побитно** равны одиночному (`pair_diff=0` на 16384 вершинах, `-hwvu0bench`);
   * **групповая сортировка ключей батчей** `HWR_GroupSort32` (`hw_sort.h`): ~250 различных ключей на ~3000 полигонов считаются хеш-таблицей, сортируются только различные ключи, один проход раскладки; порядок побитно тот же, что у стабильной поразрядной (хост-тест); сортировка вида скайбокса (70 полигонов) 77 К -> 31 К тактов (у поразрядной три гистограммы по 2048 — фиксированные 75 К);
   * ленивый `lit_fast_plan` (параметры класса считаются при первом запросе: −46 К/кадр на `begin_draw`);
   * инструменты: счётчики `HWPROF20` (почему полигон идёт общим путём), `HWPROF21/22` (части `HWR_RenderBatches`), `-hwhash` (хеш потока GIF каждого кадра, строки `HWHASH`), `-hwvu0bench`, хост-тест `tools/ps2/hg_hosttest.py` (группы `water bands litclip sort plancache clip`, 6 негативных контролей), `hw_test.c` снова линкуется;
   * номера флагов `-hwdbg` развёл с HT: `HWDBG_OLDWATER` = 1073741824 (было 268435456 = `HWDBG_IMMDBG` HT), `HWDBG_NOUP` = −2147483648 (бит 31; было 134217728 = `HWDBG_LODDBG` HT).
4. Картинку из перечисленного меняет только **вода** (47, отклонение зарегистрировано). Остальное проверено хост-тестами (побитно, раздел 2.4); сравнение потоков GIF целиком (`-hwhash`) добавлено, но прогоны не выполнены (остановлены по указанию).

### 2.1 Как мерить
* HW-сборка: `SRB2_PS2_OUT=build/outN SRB2_PS2_NO= SRB2_PS2_HW=1 python3 tools/ps2/build.py --jobs 2 --prof` (`build/mkp.sh`), software в той же ELF: `-renderer Software`.
* Прогон: `python3 tools/ps2/opt_run.py --name N --elf ELF --pak build/pak --out build/runs --demo DEMO_00n --no-ref --until "gametics in" -- -renderer Hardware -zreserve 3072 -ps2prof [-hwdbg N]` (`build/bench.sh`, `build/benchsw.sh`, `build/finalm.sh ELF TAG`).

* Хост-тест: `python3 tools/ps2/hg_hosttest.py --negative-controls` (gcc, исходники драйвера как есть).

### 2.4 Картинка
* **Хост-тесты** (`tools/ps2/hg_hosttest.py --negative-controls`, PASSED, все 6 негативных контролей краснеют): `litclip` (800 полигонов, в том числе обрезанные, с резкой по повторам текстуры не степени двойки и по > 4096 текселей, 13 842 куска) — побитно равен общему пути (`-hwdbg 8192`); `sort` (351 вход, до 8192 элементов) — порядок `HWR_GroupSort32` равен порядку стабильной поразрядной; `clip`, `water`, `bands`, `plancache` — как раньше; `lf_thresholds` против `doom_thresholds` (140 К пар глубин) — равны. `vu0_xform2` против `vu0_xform`: `pair_diff = 0` на 16 384 вершинах (PCSX2).
* **Потоки GIF**: ключ `-hwhash` печатает хеш всех буферов GIF каждого кадра (`HWHASH f=N h=...`, сравнение `build/hashcmp.py`); прогоны A/B (`-hwdbg 8192` против умолчания) **не выполнены**.
* Снимки `-vidshot` (таймдемо, кадры f150/f450/f750, настоящие текстуры), набор «старый путь» (`-hwdbg 1074537472` = вода + батчинг спрайтов + купол + свет сегмента + 8192) против базы `fef4b4e`: 172 из 640 000 пикселей (0.027 %); **итоговая ELF по умолчанию против базы: 8 278 из 640 000 (1.29 %)**, из них:
  * вода (PS2-HW-47): с `-hwdbg 1073741824` (старая вода) снимки DEMO_003 f150 и DEMO_004 f150 совпадают с базой побитно (0 пикселей), без него 3 382 / 784 пикселя расходятся (макс. дельта 27 / 43): ряби дальше z=320 нет; на MAP07 (вся поверхность — вода) 22 % пикселей, дельта до 121;
  * остальное — одиночные пиксели по рёбрам стен (DEMO_001 f150 1 395, DEMO_004 f750 1 485). Они **не воспроизводятся между ELF с одной и той же геометрией**: ELF e27 (отличается от e26 только размещением массивов группового сортировщика и комментариями) совпала с базой на f150 (0 пикселей) и f750 (2) и разошлась с ней на f450 (1 775), у e26 наоборот (1 395 / 94 / 761). Значит, часть расхождений — недетерминизм снимка или состояния, а не геометрии; причина **не установлена** (проверка воспроизводимости одной ELF дважды и `-hwhash` не выполнены).
  * VU1 против EE-пути: 10 снимков из 11 расходятся не более чем на 19 пикселей, DEMO_001 f450 — 1 691 (2.6 %, рёбра кирпичной стены, ±1/16 пикселя): VU1 остаётся по запросу.
* MAP01/02/04/07 (`k100`): MAP04 0 пикселей; MAP02 6 % — плашка названия уровня (зависит от времени); MAP01 7 %, MAP07 22 % — вода.

### 2.5 Рекомендация: HW по умолчанию?

**Пока нет.** Числа PCSX2 (раздел 2.2): HW не быстрее software ни на одной из 4 демо в обычных окнах (D1 +0.4, D2 ±0, D3 +2.3 в окнах 1–2, D4 +2.8 М/кадр), выигрывает только в тяжёлых по заливке окнах (D2 окно 9 −7.8) и даёт 60 Гц интерполяцию на лёгких кадрах; на тяжёлой D4 теряет тики (34.4 TPS), software нет. DEMO_003 в HW падает по памяти (на тике 306, и на базе тоже). Цель ≤ 8.4 М не достигнута (10.4 / 11.9 / 18.4 / 20.1 М).
Что остаётся у HW: ≈ 1.5–2.5 М/кадр постоянных накладных расходов CPU на ~3000 полигонов (≈ 7 К тактов на полигон со всеми фазами: сбор 0.3, планировщик 0.25, сортировка 0.1, трансформ+обрезка+резка+упаковка 1.5–6 К, `begin_draw` 1 К на смену состояния). Переход имеет смысл при одном из условий:
(1) **VU1 по умолчанию** (−0.5 М D1, −1.0 М D4, −0.36 М D2; проверено только в PCSX2, картинка ±1/16 пикселя) — на DEMO_004 всё ещё 19.1 против 17.3 software;
(2) измерение на реальном железе: PCSX2 не моделирует D-кэш (промахи по массивам батча/вершин) и DMA — на железе software (запись в кадровый буфер) и HW могут оказаться в другом порядке;
(3) исправить память DEMO_003 (S/HT) и профилировать 11 М «не рендеринга» (логика тика), без этого DEMO_003 ≥ 11 М в любом рендерере.
Если нужен 60 Гц на лёгких сценах — включать HW по выбору пользователя (`renderer "Hardware"` + `fpscap "Match refresh rate"`), а не по умолчанию.

## 3. Не проверено / не закрыто
* Слитая ветка (мерж `claude/determined-knuth-8c4nbi`: X, HT, SW, коммит `93f3186`) только **собрана** (software, полная HW-конфигурация), эмулятор на ней не запускался; все числа — ELF до слияния с SW (дерево HG `4d102fb`..`bb67f36`). При слиянии `src/r_things.c` (код SW) не собирался в HW-конфигурации с `-Werror` (неиспользуемые `x1 x2 scale` в `R_CreateDrawNodes` при `PS2_OPT_NODES`): добавлен `(void)`.
* Реальное железо: парный VU0, групповая сортировка, VU1 (по умолчанию выключен), все тайминги — только PCSX2 (в нём нет модели D-кэша; для PCSX2 «Possible old value used in COP2 code» печатается и у одиночного `vu0_xform`).
* DEMO_003 в HW не проходит дальше тика 306 (OOM 512 К `PU_HWRCACHE`); числа — окна 1–2; источник 11 М не-рендера не профилирован.
* Снимки `-vidshot` в HW не воспроизводятся между ELF с одинаковой геометрией (раздел 2.4, одиночные пиксели по рёбрам стен); причина не установлена; сравнение потоков GIF (`-hwhash`) не прогонялось.
* 60 Гц проверен на DEMO_001 и DEMO_004; на DEMO_002/003 и на других картах — нет.
* Golden software (`golden/ps2-head`, «0 differ») не перепроверялся: общий (не-HW) код ветки мной не менялся (все мои правки — `src/hardware`, `src/ps2/hw`, `src/ps2/i_video.c`, `tools`); слитый общий код SW-агента проверен им.
* `tools/ps2/hw_test.c` линкуется, но запуск зависает в начале (лог PCSX2 обрывается через 14 с, заглушки HT возвращают NULL): тест `vu0_transform` заменён `-hwvu0bench` в движке.
* Не сделано (по оценке 0.1–0.4 М каждое): VU0-трансформ в планировщике HT (`plan_measure`, ≈ 0.15), раздельные циклы упаковки по формату (≈ 0.1), пакетная отрисовка HUD (194 полигона = 0.48 М), повторное использование проекции общих вершин разрезов (≈ 0.5 М на DEMO_004), причина 0.76 М в `draw` вида скайбокса DEMO_004.

### A.3. Правки и результаты

**PS2-HW-47 (вода одним проходом, `ps2_hw_water.inc`)**: выпуклый полигон воды режется по двум монотонным цепочкам вершин (минимум..максимум глубины) сразу по всем плоскостям (полосы ряби и ступени света, слитые по глубине),
каждая плоскость пересекает цепочку один раз, точка интерполируется от нижнего конца ребра (как `clip_attr`), кусок отдаётся в `emit_piece` с сдвигом ST полосы и классом темноты. Было 20 000 тактов на полигон воды, стало ≈ 6 500.
Отличие (реестр): полосы ряби 16 ед. до z=160, 32 ед. до z=320, дальше без ряби (было 16 ед. до 640): сдвиг шейдера ≤ 0.025 текстуры, texel < 0.5 пикс. на z=320 (320 px, FOV 90). `-hwdbg 1073741824` (тогда 268435456) — старый путь, `-hwdbg 536870912` — свип со старыми полосами.
Хост-тест (`python3 tools/ps2/hg_hosttest.py --negative-controls`, gcc, группа `water`): 400 случайных полигонов, 1932 куска сравнены с `emit_water_poly`: расхождение ≤ 1 LSB XY (1/16 пикс.), ST ≤ 3e-6, туман/Z совпали; контроль 1 (другое время ряби) краснеет.
Замер DEMO_001 NOUP: `water` 1.41 М -> 0.45 М, `wall` 12.75 -> 12.28 М.

**PS2-HW-46 (кэш планов `begin_draw`) — убыточен**: хит 1060 тактов (ключ+поиск 543, копия P/LF 268, касание текстуры 100, прочее 146) против 840 тактов полного плана; кэш 628 хитов / 194 промаха на кадр, итог `begin` 0.70 -> 1.02 М.
Код оставлен (тест `plancache`: 600 случайных вызовов, поток GIF побитно одинаков с кэшем и без, 395 хитов, контроль 2 краснеет), но выключен по умолчанию (`-hwdbg 16384` = отключение, см. ниже: по умолчанию выключен).

**PS2-HW-44/45 (VU1) — заработал, найдены три ошибки (все в сборках OPT9 никогда не проверялись запуском)**:
1. `-hwdbg 67108864` вешал `gsKit_init_screen` (канал VIF1 в маске `dmaKit_init`/`dmaKit_chan_init`): канал теперь сбрасывается вручную, маска только GIF.
2. `pk_flush`: пустой «run» после CNT-элемента с данными (константы VU1, UNPACK-чанк) превращал CNT в REFE и DMA читала данные с адреса 0 (цепочка зависала через ~135 кадров): теперь завершающий тег END (qwc 0).
3. Ссылочные прогоны (`pk_ref`, нулевое копирование текстур) шли с `FLUSH`: FLUSH ждёт конца GIF-пакета, а данные IMAGE лежат за ним — взаимная блокировка на первой загрузке текстуры (кадр 57): REF-прогон теперь `NOP + DIRECT`.
Проверка: DEMO_001 NOUP+VU1 до конца (1051 тик, без watchdog); картинки MAP01/MAP02 (реальные текстуры, `k100`, 35 Гц) отличаются от EE-пути на 3 и 2 пикселя из 64000 (макс. дельта 58/16).
Эффект VU1 на DEMO_001 NOUP: `batch` 2.84 -> 2.52 М (653 из 923 вееров батча идут на VU1, ≈ 500 тактов EE на полигон вместо ≈ 1000); `wall` 12.28 -> 11.90 М.
