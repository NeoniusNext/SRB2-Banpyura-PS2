# OPT10: итог сессии (2026-10-06/07) — что сделано, что измерено, что не закрыто

Шесть агентов (HT, HG, HF, SW, S, X) работали в отдельных worktree, ветки слиты в `claude/determined-knuth-8c4nbi`. Подробности и строки реестра отличий — в отчётах
`docs/GATES/g1/opt10-<РОЛЬ>.md` (реестр отличий лежит в них; `docs/DEVIATIONS.md` содержит сводку диапазонов и главные отличия). Бриф: `docs/OPT10_BRIEF.md`.

только скомпилировано во всех трёх конфигурациях). Проверка запуском — за пользователем; список рисков — раздел 5.

## 1. Скорость (такты EE на кадр, среднее по окнам 1..9 по 105 кадров; FPS = 294.9 М / такты; эмулятор PCSX2 2.6.3, не железо)

| Демо | software было → стало | FPS (software) | HW было → стало (HT+HG) | FPS (HW) |
|---|---|---|---|---|
| DEMO_001 | 9.98 → **8.66** | 34.0 | 72.1 → **12.0** | 24.6 |
| DEMO_002 | 10.18 → **8.90** | 33.1 | 35.7 → **13.1** | 22.4 |
| DEMO_003 | 16.27 → **11.91** | 24.8 | 46.7 → **17.9** (окна 1–6, дальше OOM арены в HW) | 16.4 |
| DEMO_004 | 15.06 → **12.32** | 23.9 | 74.5 → **21.8** | 13.5 |

* Цель пользователя «хотя бы около 60 FPS при 35 TPS» **не достигнута**. Лучший результат — software DEMO_001 ≈ 34 FPS; тяжёлые сцены (DEMO_003/004) ≈ 24 FPS. Для 60 FPS нужен кадр ≤ 4.9 М тактов.
* **GS HW-рендерер на текущий момент НЕ быстрее software** (в обычных окнах хуже на 0.4–2.8 М; выигрывает только на тяжёлых по заливке кадрах, напр. DEMO_002 окно 9: 16.8 против 24.6 М). Он стал в 4–6 раз быстрее, чем был
  (72 → 12 М), но остаётся CPU-ограниченным (emit_poly, отсечение, упаковка, BSP, аудио-декодер 0.5–1.4 М/кадр, логика тика). Опциональный путь через VU1 (`-hwdbg 0x4000000`, замер HG: −0.5…−1.0 М) проверен только в PCSX2.
  **Рекомендация (HG, принята): рендерером по умолчанию остаётся software; Hardware включается в меню Options → Video или `-renderer Hardware -zreserve 1536`.**
* Software: все оптимизации побитно эквивалентны (golden `golden/ps2-head` «0 differ» на 4 демо, FNV всех 1050 кадров) — отличий картинки/физики нет (PS2-160..176). Не хватило: DEMO_001 ≈ 0.25 М, DEMO_002 ≈ 0.5 М до 8.4 М;
  найден главный остаток — 73 % текстурированных колонок ничего не рисуют, но стоят ≈ 340–460 тактов из-за спиллов регистров в `R_RenderSegLoopX`; двухпроходный цикл подготовлен (`tools/ps2/sw_segloop2.patch.py`, PS2-177), **не применён и не проверен**.
* 60 Гц интерполяцией: на лёгких кадрах HW DEMO_001 работает (до 48 FPS, 35 TPS); на тяжёлых HW теряет тики (DEMO_004: 34.4 TPS). Для software не реализовано (бюджет 4.9 М недостижим при 8.7 М).

## 2. GS Hardware Renderer — что сделано
* **HT:** планировщик кадра — LOD текстур по реальной экранной плотности текселей (потеря качества записана: на 0.4–5.7 % пикселей разница > 8 уровней, рассеяна на дальних стенах/полах, сжатых > 2:1), один образ на CLUT-варианты,
  размещение в VRAM сверху/снизу (без фрагментации), загрузка без копирования (DMA по ссылке), текстуры 1025–2048 строк режутся на два образа без потерь, отсев невидимых спрайтов/теней/осадков. `tex` 17 М → 0.05–0.5 М на кадр.
* **HF (жалоба «текстуры на стенах и полах глючат»):** главная причина — освещение не как у ПК/software: ПК рисует палитровым рендерингом, а PS2-движок освещал формулой GLSL. Палитровое освещение перенесено на GS через CLUT
  (PS2-HW-71): ошибка цвета (MAD к ПК-OpenGL) 3.2–12.2 → 0.7–3.4 на 8 картах. Геометрия и положение текстур совпадают с ПК (сдвиг 0.00 px). Добавлены: валидатор потока GIF по правилам настоящего GS (0 нарушений на 15 картах),
  охрана границ VRAM, конформность текстур по тексель (1026 текстур, 0 ошибок), UI-fade, исправление двух причин OOM (цепочка из 50 смен по 7 лёгким картам в HW проходит; цепочки с тяжёлыми картами — 2, 5, 8, 13, 22, 40 — на объединённой базе останавливаются по арене).
* **HG:** лёгкий путь для обрезанных полигонов, парное преобразование на VU0 (65 → 54 такта/вершину), групповая сортировка батчей, вода одним проходом (**картинка воды отличается** от прежней, PS2-HW-47), счётчики/инструменты.
* **Не закрыто в HW:** DEMO_003 останавливается OOM арены на кадре ≈ 579; карты MAP10/11/14/23 не помещаются в зону 32 МБ в HW (даже при резерве 512 КиБ); MAP11 в HW падает по памяти. Автоматического переключения на software нет.
  Ширина текстуры > 1024 или высота > 2048 всё ещё сжимается; точный fill-rate/стоимость CLUT на настоящем GS в PCSX2 не измеряются; проверка «настоящего GS» — по документации (валидатор), не на железе.

## 3. Возвращённый контент и сеть (X; проверено запуском в эмуляторе на базе агента, не на итоговой ELF)
* **По умолчанию теперь собирается ВСЁ** (`SRB2_PS2_NO` пуст): Lua (в т.ч. Lua-HUD в software и HW), UDMF, аддоны (меню Add-ons, `addfile`, `-file`, `autoload/`, `mc0:`), лимиты как у ПК, сеть, мастер-сервер.
  Урезанный профиль — `SRB2_PS2_NO=lua,udmf,addons,limits`.
* Сеть: PS2↔ПК и PS2↔PS2 по 6500+ тиков без расхождений; режимы Co-op/Match/CTF/Race/Tag/TeamMatch; переподключение; аддоны по UDP и HTTP; мастер-сервер (mock) — список, вход на ПК-сервер из меню, регистрация PS2-хоста;
  чтение настоящего `ds.ms.srb2.org` — только GET; ввод адреса с пада (OSK) и USB-клавиатуры.
* Исправлено по пути: `BACKUPTICS` 256 → 1024 (PS2-сервер выбрасывал присоединяющегося PS2-клиента; цена +221 КБ статической памяти), MD5 файлов аддонов на PS2 (демо с аддонами), порядок вычисления аргументов ГСЧ (PS2-142: физика DEMO_003 теперь совпадает с ПК).
* Не закрыто: `mass:` (USB-накопитель) не проверяется в PCSX2; реальные чужие аддоны недоступны в среде (проверены синтетические); сохранения с аддонами не проверялись; **HW-клиент в сети** падал `Z_CheckHeap` — причина исправлена
  (PS2-140, `Z_PinCachePatch`, прогон до gametic 4071), но `hw-net-match` не прогонялся; сплитскрин в сети отвергает сам оригинальный движок.

## 4. Инциденты сессии (честно)
1. **Мастер-сервер SRB2:** тестовый ПК-сервер агента X дважды отправил POST-регистрацию на настоящий `ds.ms.srb2.org` (флаг `-room 1` применился раньше подмены на mock). В настоящем списке (комната 1) висят записи
   `160.79.106.128:5029` и `160.79.106.141:5029` «SRB2 server 2.2.15» — адреса выхода контейнера, играть на них нельзя; токена для снятия нет, обновления они не получают (должны истечь; иначе убрать могут только администраторы мастер-сервера).
   Защита добавлена (`net_session.py`: подмена `masterserver`, снятие прокси, аудит логов). Больше ни одного обращения, кроме GET списка.
2. **Диск:** шторм `TLB Miss` в прогоне HT (переполнение стека в `plan_measure`, исправлено) написал 16 ГБ лога эмулятора и забил диск; `run_pcsx2.py` теперь прерывает прогон при логе > 300 МБ.
3. **Эмулятор под нагрузкой:** PCSX2 сам зависает при загрузке CPU ≈ 30 (на 4 ядрах); часть сценариев пришлось перезапускать.

## 5. Риски итоговой ELF — проверить в первую очередь
* **Software MAP11 (CEZ2) после слияния SW**: запас арены был 0.25 МБ, SW добавил ≈ 100 КиБ таблиц — возможен OOM. Не перемерено.
* **Карты в HW:** `MAP08/10/11/14/23/31` могут падать по памяти (арена); при OOM переключитесь на software.
* Итоговая ELF не гонялась в эмуляторе (ни HW, ни software); последние полные sweep'ы: HW 81 из 84 карт (до последних правок S), software 83 из 84 (до слияния SW).
* Soak ≥ 20 мин на итоговой ELF не прогонялся (последний завершённый HW — 43.8 мин на более ранней базе).
* Меню: HF сообщает, что в его сборке не было пунктов MULTIPLAYER/ADDONS (она могла быть урезанной); X показывал оба меню на полной сборке — проверьте в итоговой.
* Вся проверка — только в PCSX2 (программный GS); настоящее железо, реальный DMA/кэш/GS и звук не проверялись.

## 6. Как проверить самому
* ELF: `prebuilt/SRB2-PS2-full-hw.ELF` (полная конфигурация, оба рендерера). Данные игры упакуйте своими файлами SRB2 2.2.15: `python3 tools/ps2/cook.py --src <папка с srb2/zones/characters/music.pk3> --out <папка>`
  (на Linux нужны gcc, libpng-dev, `pip install lz4`; на Windows — MSVC, как раньше). Положите ELF и `*.PAK` в одну папку (+ `FINEACON.DAT`, `modules/`, см. `README.txt`; готовая раскладка: `python3 tools/ps2/make_dist.py --elf ... --pak ... --out dist/SRB2-PS2`).
* Запуск: PCSX2 (BIOS, включить Host Filesystem, 32 МБ) или консоль; аргументы — файл `ps2args` рядом с ELF (по одному на строку): `-renderer Hardware`, `-zreserve 1536`, `+name "PS2 player test"`, `-connect адрес`.
* Вход на сервер через мастер-сервер: Multiplayer → Internet/LAN → выбрать комнату → сервер из списка (список — `http://ds.ms.srb2.org/MS/0`). Нужен Ethernet-адаптер PS2 с DHCP (в PCSX2: Settings → Network & HDD, Sockets).
* Профиль скорости: `-ps2prof` (строки `PROF`/`HWPROF` в `boot.txt`), `-timedemo DEMO_00n.lmp`.

## 7. Что дальше (по приоритету)
1. Прогнать итоговую ELF на картах и демо; MAP11 software, HW-карты с OOM → решение по памяти HW (зона для временных блоков ≥ 256 КБ, меньше `PU_HWRPLANE`/`PU_HWRCACHE`).
2. Применить и проверить PS2-177 (двухпроходный цикл стен): ожидаемо −0.25…−0.5 М → software ≥ 35 FPS на DEMO_001/002.
3. CPU-путь HW: VU1 по умолчанию (после проверки на железе), `HWR_RadixSort32` 0.5 М, `R_PointToAngle64` 0.26 М, аудио-декодер ≈ 6 % кадра, логика тика (DEMO_003: ≈ 5 М на 1883 объекта).
4. 60 FPS реалистичны только через HW при кадре ≤ 4.9 М: нужны VU1-конвейер геометрии и статический кэш геометрии карты (не сделан).
