# Exact PSMT8 row preparation, seventh pass, 2026-11-14

The two remaining PSMT8 row callbacks now read an immutable context value for
each call. In the separate-TU EE workload, **168 configurations improve and 48
are exactly equal**, with no measured regressions among 216 configurations.
Isolated object text shrinks **152 bytes**; the final Hardware LTO callback
bodies instead grow **8 bytes combined**. Stack frames, persistent data/BSS,
heap, scratch capacity and VRAM are unchanged. These are callback CPU/code measurements;
there is no independent whole-game FPS, frame-time stability or GPU-work claim.

Only `fill_idx` and `fill_ap88` in `src/ps2/hw/ps2_hw_tex.inc` change. The former
handles P_8, ALPHA_8 and palette-indexed RGBA uploads; the latter handles AP_88
uploads to PSMT8. The three CT32 callbacks optimized in pass six are unchanged.
The reference is the saved cumulative source at
`build/nov14-next7/baseline-src/src`, revision
`b1f243f5f768d24aef5cb3ee62b45f2341e53ff4`, rather than an older Git HEAD.

## Alias and callback lifetime

`tex_upload` owns `fc` on its stack, initializes its fields and passes it to
`upload_bands`. The latter reserves a DMA-ring payload with `pk_alloc`, then
calls the selected filler synchronously for each row. Each ring is a separate
`memalign` allocation; its output cannot overwrite that stack context. The
split-image path changes source/height only between completed upload calls.
The snapshot is fresh for every callback, with no retained pointer or cache.

The contiguous `fill_idx` branch keeps its existing `memcpy`. The AP88 compose
diagnostic still checks the completed row and may call the existing log function
afterward. Neither callback allocates, submits DMA, mutates a palette or invokes
another row callback. Source **contents** remain live reads in their existing
order; the snapshot captures parameters, rather than source texels. This is a
bounded production-caller argument, not a claim about a hypothetical output
buffer overlapping the context of a generic `void *` callback.

The fixture mechanically verifies that reverting only these two snapshots
reconstructs the **whole frozen texture file byte-for-byte**. It also checks
unchanged caller counts, source-address/gather helpers, production flag values,
and identical `ps2_hwd.c`/`ps2_hw_gs.inc` caller/ring sources. Thus the original
fast predicates, four-pixel loads, tails, aligned/unaligned stores, compose
diagnostic, `FX3_NOFILL` policy, format decisions, palette interpretation,
dimensions, planner, allocator, packets, DMA ordering and limits remain intact.

The actual frozen/current functions and fixture are in three separate non-LTO
translation units. An independent byte-oriented oracle checks every output
byte and surrounding canary. Source bytes and the complete context are checked
for writes. Every possible AP88 index/alpha pair occurs in every one of the
four packed lanes, in both modes. The width sweep covers 1..1024 and every
source/destination byte residue modulo 16. Other cases cover cropped source
strides, later rows, shifts 0..10, mixed/zero/opaque/partial alpha, nonzero
including negative modes, and repeated calls with changed context/source.

Ordinary and ASan/UBSan runs each pass **963,380 cases and 414,572,750 pixels**.
All five negative controls fail as required: a snapshot incorrectly retained
across calls, an oversized width, the next source column, a changed output bit
and the wrong source row. The native EE run passes **192,851 exact/oracle cases
and 6,480,229 pixels**, then completes all timings and reaches `GS NEXT7 DONE`,
wrapper exit 0, on the standard 32 MiB PCSX2 profile. Its width sweep uses 1..65
and the same large boundary widths; the complete byte-pair coverage remains.
The host executes portable gathering; the EE executes native `PPACB`.

## Callback costs and scope

EE GCC 15.2 uses the usual `-O2 -G8 -mno-abicalls` ABI and `-Werror`. Only the
existing SDK abicalls link warning remains. Volatile function-pointer selection
prevents constant-call specialization. Nine repetitions alternate version
order, and every timed output/canary is compared after each pair. The table
sums median CP0 cycles for the specified complete-row calls, with identical
call/result-observation overhead. It is not a frequency-weighted game trace.

| Index, two decimation groups | 24 | 42,262,416 | 24,064,784 | -43.0587% |

The default aligned and unaligned-output groups include complete four-pixel
loops and tails; all their medians improve. Widths are
1/2/3/4/7/16/31/64/127/256/511/1024. Restricting the aligned group to widths
4/16/64/256/1024, the ten mode/width medians improve 0.0267..2.1977%, with a
summed reduction of 0.8177%. Their complete four-texel loop and both store
branches preserve all 32 instruction mnemonics and relative offsets in the
paired standalone functions; this gain is row overhead, not a new gather.
`fast4-mnemonic-check.json` records that bounded check. `FX3_NOFILL` is extracted from its actual
production definition, 0x8000. Compose-debug behavior is exactness-tested; no
separate debug timing claim is made. No `PS2_NOOPT_GS` macro exists in these
production sources. DMA/device waits and complete upload/frame costs are
outside these callback timings. Existing zero-copy P_8 reference uploads bypass
these callbacks and receive no benefit from this change. Physical PS2 cache/bus
behavior was not measured.

## Final Hardware LTO audit

Read-only inspection of the complete Hardware ELF built from production
commit `2ec90684af655a9286b097224564083c4a007170` verifies that the parameter
capture survives the real engine's LTO. The original saved Hardware baseline
is used directly; no replacement source compilation or emulator run is part
of this audit.

| Actual linked helper | Baseline body | Current body | Stack frame | Native PPACB sites |
| --- | ---: | ---: | ---: | ---: |
| `fill_idx` | 192 B | 136 B | 0 -> 0 B | 0 -> 0 |
| `fill_ap88` | 1220 B | 1284 B | Conditional 16 -> 16 B | 3 -> 3 |
| Combined | 1412 B | 1420 B | Unchanged | 3 -> 3 |

The actual `fill_idx` decimation loop shrinks from 14 to seven instructions,
including its branch delay slot. Its repeated width/column-shift loads fall
from two to zero. `fill_ap88` captures its six used context fields at entry;
after the last load at offset 0x2c, there are no context reads in its pixel
loops. LTO also separates alpha-aware/keyed scalar paths and partially
unrolls the legacy fallback, accounting for a different code footprint from
the separate-TU fixture. The actual AP88 body grows 64 B; combined with the
56 B index reduction this is an **8 B code-size regression**, not a linked
code/RAM saving.

Both real AP88 fast4 kernels retain their exact instruction forms after
renaming equivalent register roles and relocated branch targets. The keyed
kernel retains 11 instructions and one `PPACB`; the alpha-aware kernel
retains 23 instructions and two `PPACB`. Each corresponding unaligned-store
branch retains the same 11 instructions. Their aligned stores, loads and
existing stack temporary are preserved, with no added mode branch, spill or
MMI-register pressure in those kernels. Tail/scalar context reloads are
removed. This establishes production code structure; the separate-TU timing
percentages are not assigned to these LTO callbacks or complete game frames.
