# Бриф сессии OPT11 (2026-10-07): 5 агентов Sonnet — GS HW-рендерер до конца, FPS, стабильность

Продолжение `docs/OPT10_BRIEF.md` и `docs/OPT10_RESULTS.md` (**прочитай оба, `docs/AGENT_BRIEF.md`, `docs/DEVIATIONS.md`, `docs/HW_RENDERER.md` и отчёты `docs/GATES/g1/opt10-*.md` своей области**).
Контейнер Linux, 4 ядра CPU на всех пятерых + эмулятор: не гоняй лишнего (`--jobs 2`, не больше ОДНОГО эмулятора одновременно на агента).

## Требования пользователя (критерий приёмки)
1. **Намного больше FPS** на PS2 — хотя бы около **60 FPS при 35 TPS** (60 Гц показ интерполяцией, тики 35) и **намного выше стабильность**. Рендер/движок можно переписывать целиком, но без потери графики/физики (допустима малая погрешность).
2. **Главное: полностью закончить GS Hardware Renderer** — нативный PS2 (GS + VU0/VU1 + VIF/GIF DMA + scratchpad), все эффекты/освещение/возможности OpenGL-рендерера SRB2 (в пределах железа), **стабильный, без графических багов
   (явная жалоба: «глючит шейдер поверхности воды»)**, и **заметно быстрее software** на всех демо (software сильно грузит CPU). Можно переписывать HW-рендерер, «шейдеры», функции под PS2.
3. Не потерять то, что уже есть: Lua, UDMF, аддоны, сеть, мастер-сервер (всё собирается по умолчанию).

## Состояние на старте (HEAD, проверено запуском в этом контейнере)
* `OPT10_RESULTS.md` раздел 1: software ≈ 8.7 М тактов/кадр на DEMO_001 (≈ 34 FPS), HW 10.4–12 М (**HW медленнее software**: CPU-ограничен — `emit_poly`, резка полигонов по ступеням света, BSP, `batch`, спрайты; логика тика 1.7–11 М/кадр).
  Повторено мной: `-timedemo DEMO_001` software «1051 gametics in 1050 realtics», HW «1051 in 1266 realtics»; средние окон 1..9: software 8.68 М, HW 10.4 М.
* Цель по кадру: 60 FPS = 4.9 М тактов (FPS = 294.9 М / такты), 35 FPS = 8.43 М. **Цели сессии:** HW ≤ 8.4 М на всех 4 демо и явно ниже software; DEMO_001/002 HW ≤ 5.5 М (≈ 53–60 FPS); software ≥ 35 FPS на DEMO_001/002.
  Бюджет в секунду: при 60 FPS и 35 TPS логика тика (35 × T) + рендер (60 × R) + звук ≤ 295 М → нужно T ≲ 2 М и R ≲ 2.5–3 М. Значит рендер-путь должен стать **на порядок дешевле на CPU**, а не на 20 %.
* Идеи, которые не сделаны (бери, если измерения подтверждают): статический кэш геометрии карты (стены/плоскости; пересчёт только «грязных» секторов, ключ — высоты/свет/колормап/версия), трансформ+клип+упаковка на **VU1** для кэшированных
  вершин и спрайтов (VIF1 DMA, XGKICK, двойная буферизация, по умолчанию, не за флагом), **освещение по расстоянию на GS без резки полигонов на CPU** (резка по ступеням света — главный расход `cut_and_emit`; идея: второй проход с 1D-текстурой-рампой,
  у которой S/Q = глубина глаза на пиксель — вершинам даётся Q=1/z, S=const; альфа рампы множит кадр `(Cd-0)*As`; сравнить с палитровым эталоном HF по MAD), массовая отрисовка HUD/спрайтов/теней одним проходом, аудио-декодер на IOP/SPU2 вместо EE, отсечение по PVS/узлам.

## Железные правила
* **Ничего не утверждать без запуска.** Числа — только релизная сборка с LTO; в отчёт — команда, среднее и максимум по окнам для всех четырёх демо (где это скорость). Каждая оптимизация — A/B на одной и той же ELF (флаг `-hwdbg`), чтобы цифры были честными (разброс между прогонами ≈ 0.1–0.3 М).
* Скорость не за счёт картинки: после каждой заметной правки HW — сравнение кадров с ПК-OpenGL / с предыдущим HW (`-vidshot`, MAD/число пикселей), реестр отличий (строка на каждое отклонение с причиной и величиной).
* Реальная PS2 строже PCSX2: кэш данных 8 КБ не эмулируется, DMA видит память сразу, 64-байтное выравнивание, `SyncDCache`/`FlushCache` перед DMA, uncached-доступ, VU1-память 16 КБ. Пиши код правильным для железа; `EnableEECache = true` + интерпретатор в PCSX2 проверяет часть этого (см. `opt10-S.md`).
* Внешние сервисы: **запрещено** регистрировать сервер на настоящем мастер-сервере `ds.ms.srb2.org` и заходить на чужие серверы; только чтение (GET) и локальные mock/ПК-сервер.
* **Отчёт `docs/GATES/g1/opt11-<РОЛЬ>.md` дописывай после каждого этапа и коммить** (сессии обрываются лимитом — недописанный отчёт = потерянная работа). Структура: 1) сделано; 2) команды и числа до/после; 3) не проверено/упёрлось; 4) реестр отличий (ID диапазона роли); 5) правки в чужих файлах.
* Файлы своей роли правь свободно; чужие — только точечно (Edit) и с записью в отчёт. Не переформатируй файлы целиком, не переименовывай/не переноси чужой код (слияние делает координатор).
* В конце — сводка ≤ 25 строк: что сделано, числа до/после, что не закрыто (честно).

## Роли (5 агентов)

### GEOM — HW, сторона движка: геометрия, видимость, кэш (реестр `PS2-HW-80..99`)
Файлы: `src/hardware/hw_main.c`, `hw_bsp.c`, `hw_clip.c`, `hw_batching.c`, PS2-части `hw_defs.h/hw_glob.h`, HW-части `src/r_fps.c`, `src/ps2/hw/ps2_hw_plan.inc` (совместно с VU — договаривайтесь через отчёты).
Задача: убрать с EE работу, которая не зависит от вида: сейчас `BSP` 2.3–5.3 М + `batch` 2.7–6.1 М + спрайты 0.6–4 М + узлы 0.5–0.9 М на кадр при 1000–2300 полигонах (≈ 840 тактов на полигон).
1. Измерь, где уходят такты (счётчики `HWPROF3..22`, сэмплер `build.py --sample`, `tools/ps2/sample_report.py`), составь таблицу «что можно кэшировать».
2. **Кэш геометрии карты:** полигоны стен/плоскостей (вершины, UV, свет, колормап, флаги) строятся один раз и пересчитываются только для «грязных» сегментов/секторов (двигающиеся пол/потолок, смена света/колормапа, FOF, склоны, поли-объекты, портал/скайбокс) — ключ-версия сектора; при несовпадении — прежний путь (то же изображение).
   Видимость: дешёвое отсечение узлов BSP по bbox/пирамиде видимости, без `double`/libm, кэш скайбокса. Спрайты: кэш проекции, пакетная подготовка, отсев до трансформа.
3. Интерфейс к драйверу (с агентом VU): блоки уже подготовленных вершин, которые драйвер шлёт на VU1 без повторной упаковки. Договорись о нём в отчёте/коде заранее, не ломай VU-путь.
4. Цель: `BSP+batch+спрайты+узлы` ≤ 2 М на DEMO_001/002, ≤ 4 М на DEMO_003/004.

### VU — HW, сторона драйвера: VU1/VU0, VIF/GIF, GS (реестр `PS2-HW-100..119`)
Файлы: `src/ps2/hw/ps2_hw_draw.inc`, `ps2_hw_gs.inc`, `ps2_hw_vif.inc`, `ps2_hw_vu0.inc`, `ps2_hw_vu1.inc`, `vu1/*.vsm`, `ps2_hw_xform.inc`, `ps2_hw_fast.inc`, `ps2_hw_priv.inc`, `ps2_hwd.c`, `ps2_hw_regs.inc`, `ps2_hw_plan.inc` (совместно с GEOM).
Задача: драйвер должен тратить на EE почти ноль на полигон. Сейчас 840 тактов на полигон (`emit_poly`, `clip_attr`, `emit_reglist_fan`, `cut_and_emit`), VU1-путь за флагом `-hwvu1` и даёт только −0.5…−1.0 М.
1. **VU1 по умолчанию** и полноценно: трансформ + отсечение по экрану (guard band) + перспективные UV + вершинный свет + упаковка GIF-тегов на VU1, VIF1 DMA цепочкой `REF`, двойная буферизация VU1-памяти, XGKICK; EE только строит списки (по возможности — из кэша GEOM). Проверить на PCSX2 и написать код корректным для железа (VU1 16 КБ, XGKICK-синхронизация).
2. **Освещение по расстоянию без резки полигонов на CPU** (см. идею в разделе «Состояние»), либо иное решение с доказанным совпадением с палитровым эталоном (HF: MAD 0.7–3.4); резка по ступеням света — только запасной путь. Измерить цену на GS (fill-rate в PCSX2 не показатель — оценивай по числу пикселей/проходов).
3. Одиночные отрисовки (1092 за кадр: тени спрайтов, спрайты, HUD 194 полигона, полупрозрачные) — в батчи; `begin_draw` 1288 раз за кадр; сортировка батчей (`HWR_RadixSort32` 0.5 М); загрузка текстур/CLUT — перекрытие с DMA.
4. Цель: стоимость драйвера на кадр ≤ 1.5 М на DEMO_001/002 при тех же картинках (побитное или MAD-сравнение с прежним HW).

### FX — HW: полнота эффектов и точность картинки, вода (реестр `PS2-HW-120..139`)
Файлы: `ps2_hw_water.inc`, `ps2_hw_sky.inc`, `ps2_hw_light.inc`, `ps2_hw_pal.inc`, `ps2_hw_screen.inc`, `ps2_hw_tt.inc`, `ps2_hw_val.inc`, `ps2_hw_tex.inc` (визуальная часть), `src/hardware/hw_model.c/hw_md2.c`, `hw_shaders.c` (PS2-часть).
1. **Вода («глючит шейдер поверхности воды»).** Сейчас PF_Ripple реализован резкой нарезкой полигона на полосы глубины с постоянным сдвигом UV (`ps2_hw_water.inc`) — на границах полос текстура скачет (шов), дальше z=320 ряби нет. Эталон — GLSL-шейдер воды ПК
   (`tex(s - sin(a)*0.025, t - cos(a)*0.025)`, `a = -π·z/2·0.025 + leveltime·2`, см. `hw_shaders.c`). Найди (снимки ПК-OpenGL против PS2 на картах с водой: DSZ/«Deep Sea», THZ, любая с FOF-водой; `tools/ps2/hf_*.py`) и **устрани** артефакты: непрерывная рябь
   (смещение UV считается в вершинах на границах полос и интерполируется — C0 без швов, густота полос по ошибке, а не по числу полос), совпадение прозрачности/фейда/цвета воды, поведение при подводной камере (`PostImgRedraw` heat/water), поверхности под углом, 3D-полы.
   Цена не должна вырасти (согласуй с VU: `emit_water_poly` — интерфейс).
2. **Матрица полноты** `PF_*`/шейдеров/эффектов ПК-OpenGL против PS2-HW: fog (колормап-фейд), цветные колормапы, translucent/additive/subtractive/reverse-subtractive, masked/альфа-тест, sky/skybox, ряби, FOF и полупрозрачные FOF, спрайты-портреты/билборды, MD3-модели (`models.dat` рядом с ELF, свет моделей, тени), палитровые вспышки (damage/pickup/NiGHTS), wipe/fade, HUD-fade, post-эффекты (heat, underwater), `HWR_DrawShadows`, скайбокс, склоны, повёрнутые флэты, линкдро.
   По каждой строке: реализовано / нет / отличается (величина) — со снимками и командой. Затем **реализуй недостающее**, начиная с самого заметного на экране.
3. Графические артефакты («текстуры на стенах и полах глючат»): прогон по картам 1..33, спец-этапам, NiGHTS, титулу, меню; список и исправления. Вся «математика картинки» (гамма, цветовая глубина, дизеринг, CT16/CT32, Z-режимы) — в сравнении с ПК.
4. Не замедляй: каждая правка — A/B по `wall` на DEMO_001/004.
