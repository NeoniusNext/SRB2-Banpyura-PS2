# Exact P4 packing and band scan on the EE

The accepted change accelerates only `p4_band` and `fill_p4` in
`src/ps2/hw/ps2_hw_tex.inc`. In the native actual-source fixture, aligned
1024×1024 packing plus eligibility drops from **24,147,980 to 1,902,646 COP0
Count ticks**, a **12.69×** helper speedup. This measures CPU helpers in PCSX2;
packet construction, DMA, full-game time and physical-console performance are
outside this observation.

The existing P4 selection policy remains explicit full-size mode
(`-hwdbg 33554432`): complete original P8 sources, both wrapping axes, at least
2048 texels, dimensions at most 1024, width divisible by eight, one exact
aligned CLUT band and the previous allocation/ownership rules. The change adds
no allocation, stored image or persistent cache.

## Implementation

`fill_p4` uses MMI only for a complete undecimated source (`dx = dy = 0`,
stored dimensions equal source dimensions), at least sixteen texels, a
16-byte-aligned source row and an 8-byte-aligned destination. Each `LQ` loads
sixteen indices. `PAND` keeps each low nibble; `PSRLH 4` and `POR` put the odd
nibble beside the even nibble; `PPACB` gathers eight even bytes and `SD` writes
the eight packed bytes. Complete groups remain inside the row. The original
byte loop handles tails and every rejected context, including width eight,
unaligned rows, crops and decimation.

`p4_band` scans aligned complete groups of sixteen bytes. It compares each
high nibble with the first index's high nibble and combines both 64-bit register
halves before rejecting a mismatch. It checks the scalar tail and publishes a
band only after the entire source succeeds. Unaligned and short sources use
the scalar loop. All 128-bit intermediate register values stay inside one asm
block; early-clobber outputs prevent overlap with its inputs.

The delta is 81 inserted and three removed lines. An isolated non-LTO EE driver
compile grows text by 456 bytes; data remains 1048 bytes and BSS remains 267514
bytes. Its `tex_upload` stack frame remains 304 bytes. These object measurements
do not predict the final linked LTO ELF size.

## Native and host evidence

The standalone fixture extracts the actual source functions, builds them with
the EE compiler, inspects their disassembly, and runs through the official
locked `run_pcsx2.py` runner with the standard 32 MiB profile. The combined
native run passes **10,653,592 checks in 66,544 generated cases**, with zero
failures. Coverage includes all sixteen palette bands, all 256 nibble pairs,
every source/destination offset modulo sixteen, widths from two through 1024,
width eight, NPOT widths, exact allocation tails, crops and decimation, both
halves of every MMI group, late mismatches and scalar scan tails.

The checked-in runner uses literal scalar function bodies from commit
`dbc98504e1ad2cc6c2e8e1d24a6ef5d2f31d6ebf` as its reference. It verifies that
the context and coordinate helpers match that commit before extraction. The
reference body receives only a function-name change and a `noinline` attribute;
there is no separate packing implementation to drift from the source.

The native fixture also streams the entire immutable stock-flat corpus:
**1386 textures / 34,735,104 original bytes**. Every band decision matches the
corpus census, and every one of the **8,796,160 eligible source indices** is
reconstructed exactly from its packed output. The corpus SHA-256 is
`af8b6db337884ff8bedcfddc65c3472d8b1f5affb1b32d9ee944c1c71627d3f8`.

Four deliberately wrong native variants are executed and detected: shift by
five, swapped `PPACB` operands, nibble mask `0x0E`, and a band reduction that
ignores the upper 64 register bits. Host fallback checks alone do not establish
these instruction semantics.

The complete production `tex_upload` host fixture passes plain and ASan/UBSan
runs after application: **2232 uploads / 101,369,320 texels**, including all
1386 stock textures, CLUT selection and mode-transition checks. The combined
production driver also compiles for the EE with `-Werror` and zero diagnostics.

## Count observations and limits

Each entry is the minimum of seven equal-work native trials. Packing uses
complete row callbacks for the stated image; band scanning is separate.

| Work, aligned source | Scalar Count | MMI Count | Speedup |
| --- | ---: | ---: | ---: |
| Pack 64×1024 | 948229 | 129029 | 7.35× |
| Pack 128×1024 | 1865733 | 190469 | 9.80× |
| Pack 512×1024 | 7370757 | 559109 | 13.18× |
| Pack 1024×1024 | 14710789 | 1050629 | 14.00× |
| Scan 1024×1024 | 9437191 | 852017 | 11.08× |
| Pack plus scan 1024×1024 | 24147980 | 1902646 | 12.69× |

The unaligned full-MiB band scan uses the scalar fallback and takes 11,534,349
Count versus 9,437,191 before, a 22.2% regression from compiler loop layout in
this fixture. Root inspected the common eligible engine allocation paths:
`MakeBlockEx` uses alignment exponent four (16 bytes), and the DCE allocator
uses exponent six (64 bytes). This limits the common path's exposure but does
not remove the fallback cost. Width-eight packing costs 156677 versus 145413
Count for 8×1024, an extra 11264 Count or 1.375 Count per texel. Every tested
alignment remains semantically exact.

## Reproducing from a checkout

The test code is checked in as
[`tools/ps2/p4_pack_mmi_hosttest.py`](../../../tools/ps2/p4_pack_mmi_hosttest.py)
and [its C fixture](../../../tools/ps2/p4_pack_mmi_hosttest.c). It requires local
Git history containing the pinned scalar commit, Python 3, and GCC with
ASan/UBSan. Supply the original asset externally; the existing corpus generator
creates the complete input without relying on retained build outputs:

```sh
python3 tools/ps2/next12_p4_corpus.py \
  --asset /path/to/srb2.pk3 --out build/p4-pack-mmi-corpus
python3 tools/ps2/p4_pack_mmi_hosttest.py \
  --corpus build/p4-pack-mmi-corpus/full-texels.bin \
  --out build/p4-pack-mmi-host
```

Each build command requires a fresh output directory. `--source-root` may select
a frozen root containing `src/`; it defaults to the current checkout. The runner
records source/function hashes, the exact pinned scalar commit, corpus hash,
commands and host results in `report.json`.

With the ps2dev toolchain configured as described in
[`docs/TOOLCHAIN.md`](../../TOOLCHAIN.md), build and disassemble the EE fixture
separately from launching it:

```sh
python3 tools/ps2/p4_pack_mmi_hosttest.py \
  --corpus build/p4-pack-mmi-corpus/full-texels.bin \
  --out build/p4-pack-mmi-ee --ee build
python3 tools/ps2/p4_pack_mmi_hosttest.py \
  --out build/p4-pack-mmi-ee --ee run --timeout 120 --lock-wait 20
```

`--ee build` runs the host checks, compiles the native fixture, checks its MMI
disassembly, and copies the corpus into the ELF's HostFS directory. `--ee run`
checks the frozen input hashes and then invokes the official locked runner with
the configured standard 32 MiB profile. The native timeout is capped at 120
seconds and lock wait at 60 seconds. The fixture performs seven trials for each
of eighteen packing and two band measurements, records every observation, and
requires all four executed MMI mutations to be detected. Host subprocesses have
a 60-second cap.

After promotion, the public runner passes plain and ASan/UBSan runs with
10,653,591 checks and builds the EE ELF. A second host run against the frozen
candidate root passes identically. Its generated `actual-functions.inc`,
including both literal references and all four native mutations, is
byte-identical to the bundle used in the recorded native execution:
`b608b44870cd8d1cba0fea0dca6c2444ac5c2158daf895bb13f04c508469c67e`.
The published fixture replaces the early research oracle with the pinned
scalar call and adds malformed-corpus bounds checks. Those changes pass host
sanitizers; the newly built public ELF has not been run. The native Count
observations in this report belong to the frozen ELF identified below.
