# Exact GS footprint calculation, iteration 4, 2026-11-14

The only production change in this component is `tex_footprint` in
`src/ps2/hw/ps2_hw_tex.inc`. The comparison is the immediately preceding
cumulative source in `build/nov14-next4/baseline-src/src`, recreated and verified
by `tools/ps2/prepare_next4_baseline.py`. Git HEAD is an older source revision
and is not the comparison baseline. Earlier REGLIST, free-list, direct CLUT and
alpha-conversion changes remain intact.

## Exact calculation

The old function chooses page and block dimensions, performs five runtime
divisions and scans up to 32 entries of the last page's block-order table.
For positive dimensions, the last texel's zero-based coordinates directly give
the last page and block coordinates using fixed shifts and masks for each
existing format. The same three 32-byte block tables remain in use.

In CT32/T8 and CT16 each table increases along both axes, so the maximum of a
rectangular prefix is its bottom-right entry. CT16S increases along columns;
its row offsets are `0,1,8,9,4,5,12,13`. Their prefix maxima are
`0,1,8,9,9,9,12,13`: when the last block row is 4 or 5, row 3 supplies the
maximum in every column. That correction is required; simply selecting the
last entry would underallocate some CT16S images.

The page-stride expression for T8 is `(tbw+1)>>1`, preserving the old upward
rounding for odd TBW. CT32/CT16/CT16S use `tbw` directly. The final block count
is unchanged, including partially occupied pages, arbitrary accepted texture
shapes, split images and all existing planner levels and footprint caps.

## Internal input domain and caller audit

This is an internal function for the four existing formats: CT32, CT16,
CT16S and T8. It requires positive dimensions. The equivalence proof covers
dimensions 1..65535 and TBW 0..1024, including virtual planning inputs wider
than an upload. It does **not** claim equivalence for arbitrary `u32` inputs,
zero dimensions, overflowing intermediates or unsupported PSM values. No
accepted caller supplies an unsupported PSM; the existing default branch and
format selection remain in place, without adding format support or a new
validation policy.

All production call sites and their surrounding bounds were audited:

| Path | Why dimensions stay positive and bounded |
| --- | --- |
| `tex_upload` → direct footprint, `upload_bands`/`upload_ref` → `vram_guard` | `tex_upload` rejects missing/zero-size data and any source axis over 16384 before selecting an upload format. Its format switch selects only T8 or CT32. Cropped AP88 sizes require both positive crop axes no larger than the source; even this override is within 1..16384. Normal planning halves a positive axis only while over 1024, or while over 16 for a cap. A selected existing mip level comes from the bounded frame/immediate plan. |
| Split upload's second footprint/guard | The split predicate requires `sh > tex_split_rows` and `sh <= 2*tex_split_rows`; the configured first-piece size is 64..1024 in multiples of 64. Thus both piece heights are positive, at most 1024. |
| `tex_plan` → footprint | Its actual inputs come from the validated upload or an existing resident texture record. Initial reductions only halve axes above 1024; cap reductions require that axis to exceed 16. Neither operation can turn a positive axis into zero. |
| Resident cap reconsideration in `settex_now` → `tex_plan_blocks` | Screen records are excluded and `r->sw` must be nonzero; ordinary records were published only after the preceding validated upload and retain its positive `sw/sh` and supported PSM. `dx/dy` come from successful `tex_plan`. |
| Frame `plan_blocks` → `tex_plan_blocks` | These calculations can precede upload validation, so the full positive `UINT16` GLMipmap dimension range is included. `plan_wants` and the matching engine batch `planwant` require at least 65536 texels, implying both axes are at least 2 because neither can exceed 65535. Normal selected levels are bounded by `plan_lmax`, which retains at least 16 texels per axis. The extra cached `cap+1` level retains at least 8; if the maximum level is 0, the extra shift by 1 still retains at least 1. |
| `plan_too_fine` → `tex_plan_blocks` | It excludes screens, requires a resident positive source size, and receives `want` from the same bounded frame/immediate plan. The immediate path clamps its level with `plan_lmax`. |
| Screen restore → `upload_bands` → `vram_guard` | Successful `gs_setup` requires width 64..1024 and height 16..1024, rounds its positive framebuffer stride to a multiple of 64, and selects CT32 or CT16S. Screen allocation/restoration retains those values. |

Upload TBW derived from the conservative 16384 source/crop bound is at most
256; ordinary GS-size images and screens use at most 16. Virtual full-size
frame planning may derive TBW 1024 from a positive 65535-texel axis. Even the
broader verified domain stays far from unsigned overflow: the original stride
numerator is at most 65663 and the largest CT32 result is 67108864 blocks.
The JSON audit records every direct/transitive call site and hashes all relevant
caller files in `build/nov14-next4/gs-next4-host/caller-audit.json`.

## Production-source verification

```sh
source /workspace/.onboarding/environment.sh
python3 -B tools/ps2/prepare_next4_baseline.py
python3 -B tools/ps2/gs_next4_hosttest.py \
  --out build/nov14-next4/gs-next4-host \
  --base-src build/nov14-next4/baseline-src/src \
  --sanitize --negative-controls
```

The script extracts the actual frozen/current block tables, `tex_footprint`,
`tex_plan` and `tex_plan_blocks` without changing their implementations. Each
version is compiled in a separate translation unit. Wrappers only expose the
static functions and set the existing split configuration. Shared format/VRAM
definitions are checked for equality. Production and fixture hashes, generated
sources, build logs and complete outputs are retained.

Both ordinary and ASan/UBSan host runs pass:

| Check | Count |
| --- | ---: |
| Exact frozen/current footprints | 6,774,252 |
| Exact `tex_plan` return values and both output fields | 154,080 |
| Exact `tex_plan_blocks` after successful planning | 56,707 |
| Deliberate CT16S-row, T8-stride, CT32-page and size-off-by-one corruptions | All four detected |

Coverage includes every width/height pair from 1..1024 in all four formats;
every last-page block residue with all TBW values 0..63; page/block edges through
65535; strides through 1024; large randomized virtual dimensions and derived
strides; narrow/odd sizes, split/no-split settings, rejection without changing
output canaries, footprint caps and deterministic randomized planner cases.
The test compares exact integers and does not use a tolerance.

These rows measure generic helpers, not the complete frame planner. The
preceding full Hardware ELF already has a T8-specialized LTO footprint clone
whose divisions become shifts; it still scans the table. This source change
removes that scan too, but the generic fixture percentages must not be assigned
to that specialized clone, `PS2HWD_PlanEnd`, full frames or physical hardware.

In the separate-TU fixture, the generic footprint function shrinks from
696 to 360 bytes and loses its conditional 16-byte stack frame. Its three block
tables remain 96 bytes in both versions; no new buffers, allocations or retained
metadata are added. Full-engine LTO section sizes are measured separately by the
coordinator. This component makes no independent persistent RAM, transient heap,
VRAM-capacity, DMA-byte-count or whole-game FPS claim.

Texture dimensions, image data, sampling/filtering, color/alpha values, planner
policies, allocator choices, fallback policies and compatibility limits remain
unchanged because their exact footprint inputs/outputs are retained. The fixture
does not exercise the historical VU0 outcode discrepancy and does not declare
the full GS integration suite entirely green. Full engine builds, CT32/CT16S GS
readbacks and paired game frames are the coordinator's integration checks.
