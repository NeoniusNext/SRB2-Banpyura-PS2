This work preserves the existing uncommitted port. Its own pre-edit snapshot is

## Accepted runtime changes

- `R_Draw2sMultiPatchColumn_8` and
  `R_Draw2sMultiPatchTranslucentColumn_8`: within the existing bounded NPOT
  path, advance four texture samples between wrap tests. Each sample still
  tests `TRANSPARENTPIXEL` and applies the original colormap/blend order.
- `R_DrawTranslucentColumn_8`: use the same bounded four-sample loop.
  Existing complete-post dispatch from `R_DrawTranslucentColumnClamped_8`
  benefits without changing its eligibility conditions or truncated-post path.

The new loop requires at least eight pixels, a positive texture period no larger
than `0x40000000`, and a nonnegative step at most one quarter of the period.
When `frac < period - 3 * step`, all four sample positions are below the period.
Only the final advance can cross the period, by less than one step; it receives
the original single subtraction. Otherwise one original sample/advance/wrap
is executed before retrying. All intermediates remain below `period + step`,
at most `0x50000000`, so this path introduces no signed overflow. Original start
normalization, scalar tails, negative/large steps, PO2 textures and short calls
retain their original paths.

This targets EE instruction and branch cost without changing the texel DDA.
Gathering arbitrary source bytes and dependent palette/blend lookups remains
scalar; adding MMI packing instructions would not remove those dependencies.
No new assembly, DMA buffers, precision approximation, global optimization
flag or fast-math option is introduced.

## Rejected flat allocation order experiment

The coordinator then delegated the existing MAP11 retail-RAM failure in
`Picture_TextureToFlat`. A guarded `PS2_PROFILE` experiment reserved its
independent output before `R_CheckTextureCache`. This is lifetime-safe: no
source alias has been obtained yet, eviction clears the cache owner, the later
check rebuilds it, and the output keeps its nonpurgeable `PU_RENDERWORK` tag
through every column read. No ownership was transferred or modified in place.

`oct4_render_flat_hosttest.{c,py}` extracts the actual frozen/current converter
into the real PS2 zone allocator, with generation and column lookup fixture
services. MSVC x86/x64 each compared 50 cold/warm conversions with overlapping,
empty, transparent and framebuffer-clipped posts, widths through 512 and
heights through 1024. Both variants have identical hash
`9957143228750526587`. The reordered variant also survives 25 forced legal
old-root evictions before source acquisition. Output/source roots stay
independent, owner clearing and zone accounting pass, output corruption is
caught. This establishes fixture equality/lifetime, not integrated map success.

The release engine built **110/110 units**, zero diagnostics, ELF **7,413,216 B**.
Its MAP11 run used the standard 32 MiB profile and
`-ps2prof -memtrace -zck -zquit 35`, through `opt_run.py`/`run_pcsx2.py`.
