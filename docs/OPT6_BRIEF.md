## Новые требования пользователя (дословно по смыслу)
1. **На PS2 намного больше FPS (хотя бы ≈ 60 при 35 TPS) и намного выше стабильность.** Рендер/движок можно переписывать, но без потери графики/физики (допуск — небольшая погрешность).
2. **ГЛАВНОЕ: полностью завершить GS Hardware Renderer** — нативный под PS2 (GS + VU0/VU1 + DMA + scratchpad), со всеми графическими эффектами/освещением/возможностями OpenGL-HW рендерера SRB2 (насколько позволяет железо),
   полностью стабильный, **без графических багов (сейчас текстуры на стенах и полах глючат)** и с **намного большим FPS, чем software**. Допустимо переписать HW-рендерер, шейдеры и функции под PS2.
3. **НОВОЕ (отменяет прежнее «только одиночная игра, без модов»): полностью вернуть систему аддонов (pk3/wad/soc/lua, меню Add-ons), Lua, UDMF, multiplayer (сплитскрин и сеть) и всё остальное, что `PS2_PROFILE` вырезал.**
   Реестр вырезанного (PS2-01 net_stub, PS2-02 lua_stub, PS2-09/11 урезанные лимиты слотов/кадров/скинов, PS2-13 cooked-паки, PS2-20 без PNG/zlib/ZIP/UDMF/add-ons, `soc_numbers` вместо `LUA_EvalMath`, урезанный `skin_t`, и т.д. — перечитать `docs/DEVIATIONS.md`,
   `grep -rn PS2_PROFILE src`). Память — 32 МБ: возвращать **динамически/лениво**: ванильный режим (кампания без аддонов) обязан остаться таким же лёгким и **golden-эквивалентным** (4 демо, 0 px), а лимиты/Lua/zlib/PNG
   расширяются только когда реально нужны (загрузка аддона, сетевая игра, сплитскрин). Любое возвращённое средство = тест (хост или PCSX2) с доказательством.

Решение пользователя «только PCSX2» остаётся (`D:\PCSX2-test`/`tools/ps2/run_pcsx2.py`; GS-рендерер эмулятора Vulkan, чтобы картинка реально растеризовалась), но код не привязывать к эмулятору.

## Роли и владение файлами (правишь ТОЛЬКО свои; чужое — в отчёт координатору; общие заголовки — через координатора)
### H — GS Hardware Renderer (главный приоритет)
Файлы: `src/ps2/hw/*`, `src/hardware/*` (под `PS2`/`PS2_PROFILE`/`HWRENDER`), HW-часть `src/ps2/i_video.c` (Impl_HW*), `tools/ps2/sources_hw.txt`, `hw_*`-тесты, новый VU-микрокод, `docs/HW_*.md`.
Задачи по порядку (подробности — `opt5-H.md`, `HW_RENDERER.md`, `PS2_RENDERER_PROGRESS.md` «Exact remaining blockers»):
1. **Баг пользователя: «текстуры на стенах и полах глючат».** Воспроизвести в обычном запуске `-renderer Hardware` (GFZ1, титул, несколько карт: CEZ, THZ, ACZ, DSZ, спец-этап), снимки через `-vidshot`, сравнить с software кадр в кадр.
   Типовые подозреваемые: перспективная коррекция (Q/ST), округление UV/XYZ на GS, повторы текстур NPOT/tiling, CLUT/палитра AP88, мипы/фильтр, перегрузка/вытеснение пула VRAM (перезагрузка «не той» текстуры), z-fighting (Z24/Z16 диапазон, near/far),
   клиппинг по near-plane, сортировка/декали. Найти реальные причины измерением, исправить, доказать визуально (до/после) и хост-тестом.
2. **Паритет эффектов** с OpenGL HW: освещение секторов и динамические (colormap/fog/fade), прозрачность/аддитив/вычитание/reverse-sub, небо, вода/FOF-блики, наклонные плоскости, портальные/вертикальные эффекты, спрайты (billboard/rotation/shadow), модели MD2/OBJ если
   есть в данных, полноэкранные эффекты (palette flash, wipe, screen-melt), HUD/меню 2D поверх 3D. Что невозможно на GS — задокументировать замену и погрешность (`PS2-HW-22..`).
3. **Скорость: HW должен быть явно быстрее software** (цель ≤ 4.9 М тактов EE/кадр = 60 FPS; software сейчас 9.4 М). Узкие места по OPT3/5: перезагрузка текстур (пул GS vs рабочий набор), CPU-стоимость `HWR_*`-обхода, подача геометрии.
   Решения: VU1-микрокод (трансформ/клип/свет/упаковка GIF), VIF1 DMA-цепочки двойной буферизации, предвычисленная геометрия карты, батчинг, кэш текстур в VRAM (LRU, сжатие палитровых PSMT8/PSMT4 + CLUT), отказ от `double`.
4. 60 FPS показа через интерполяцию кадров (механизм есть: `I_GetRefreshRate`, `r_fps.c`), 35 TPS не трогать.
5. Стабильность: смена рендерера Software↔Hardware, пауза/меню/титул/карты, 50 смен карт, длинные прогоны ≥ 3000 кадров, watchdog без срабатываний. Рекомендация координатору: сделать ли HW рендерером по умолчанию.
6. Подготовь HW к сплитскрину (несколько viewport'ов/scissor) — согласуй с S (сплитскрин).
Нумерация: `PS2-HW-22..`. Отчёт `docs/GATES/g1/opt6-H.md`. Каталоги `build/opt6-h/{out,run}`.

### F — Возврат контента/модов: Lua, аддоны, UDMF, PNG/zlib/ZIP, лимиты
Файлы: `src/lua_*.c`/`lua_*.h`/`src/blua/*`, `src/ps2/lua_stub.c`, `src/ps2/soc_numbers.*`, `deh_*.c/.h`, `filesrch.*`, `w_wad.*`, `w_pack.*`, `m_menu.c` (меню Add-ons), `p_setup.*` (UDMF-часть), `r_picformats.*`/`r_patch.*` (PNG), `info.h`/`info.c`/`r_defs.h`/`doomstat.h`/`doomtype.h`/`screen.h` (лимиты), `tools/ps2/build.py`/`sources.txt`/`cook.py` (добавление Lua/zlib/PNG в сборку; `build.py` общий с S — правь точечно, S владеет памятью/LTO-флагами).
Задачи:
1. Убрать из `PS2_PROFILE` по одной подсистеме, каждый раз с тестом: (a) **zlib+libpng+ZIP/pk3** (чтение pk3/PNG-патчей/текстур; cooked-паки остаются как ускоренный путь для базовых данных); (b) **настоящая Lua-VM** (`blua`, вместо `lua_stub.c`) + `LUA_EvalMath` вместо `soc_numbers`
   (таблица остаётся быстрым путём, неизвестное выражение → Lua); (c) **UDMF** карты; (d) **система аддонов**: `addfile`, меню Add-ons (источники: `host:`, `mc0:`, `mass:`/USB если доступно в PCSX2), автозагрузка, скины/спрайты/звуки/музыка аддонов, SOC/Lua из аддонов, сейвы/демо с аддонами;
   (e) **возврат лимитов**: freeslots mobj/sprite/state (1024/8192/…), `skin_t` полного размера (динамическое выделение под число реально загруженных скинов — не 4,24 МБ статически), `MAXFRAMENUM`, SFX-слоты, custom gametypes, `MAXVIDWIDTH` при необходимости. Всё динамически, размеры по факту загрузки.
2. Доказательства: загрузка реального аддона (найди/собери тестовые: pk3 со скином, lua-HUD, SOC-мод, UDMF-карту; на ПК SRB2 есть эталонная сборка — сравни поведение), 4 golden-демо без регрессий (0 px / идентичные tics), память ванильного режима не растёт (замер зоны до/после).
3. Работает ли Lua-мод с HW и software одинаково (HUD drawlist, хуки) — проверь.
Нумерация: `PS2-100..119`. Отчёт `docs/GATES/g1/opt6-F.md`. Каталоги `build/opt6-f/{out,run}`.

### S — Память/стабильность/звук + Multiplayer (сплитскрин и сеть)
Файлы: как в OPT3-S (`z_zone.*`, `ps2_mem.*`, `p_setup.c` (память), `p_saveg.c`, `w_*`, звук `ps2_audio*`/`ps2_athread*`/`i_sound.c`/`s_sound.c`, `ps2_boot.*`, `map_sweep.py`…) плюс сетевой/сплит слой:
`src/netcode/*`, `src/ps2/net_stub.c` (→ реальная сеть), `d_clisrv`/`d_net*`/`d_netfil`/`mserv`/`i_tcp` аналоги под PS2, `src/ps2/i_joy.c`/`ps2_padmap.*` (2–4 pad'а, multitap), сплитскрин-код (`r_main.c` viewport'ы, `st_stuff.c`, `hu_stuff.c`, `v_video.c` — правь точечно и согласуй с H/F через отчёт).
Задачи:
1. **Сначала (≤ 1/3 усилий) память:** MAP11 (CEZ2) OOM `PU_RENDERWORK 524288` — довести до решения (см. `opt5-S.md`; находка: LTO-шаг без `-ffunction-sections -fdata-sections`, −631 КБ арены — внести в `build.py` точечно, S разрешено),
   `map_sweep.py` по всем картам, утечки ×50 смен карт, звук без глюков при загрузке. Бюджет памяти для F (Lua/zlib/PNG/аддоны/лимиты) и H (HW) — зафиксируй в отчёте таблицей.
2. **Сплитскрин** (2–4 игрока, как в оригинале: viewport'ы, камеры, HUD, раздельные pad'ы/multitap, меню выбора), software и HW.
3. **Сетевая игра**: реальный сетевой слой вместо `net_stub.c` (ps2sdk `ps2ip`/lwIP BSD-sockets, DEV9 в PCSX2: Sockets/TAP), IPv4 UDP как у `i_tcp.c`, подключение по IP, хост/клиент, передача файлов аддонов (`d_netfil`), синхронизация; опционально мастер-сервер.
   Проверка: PS2-сервер ↔ ПК-клиент (эталонная PC-сборка SRB2 из репо) и/или две копии PCSX2; доказательство — N тиков синхронной игры без десинхронизации.
   Режимы Match/CTF/Race/Tag/Co-op должны работать (логика уже в ядре — не ломать).
4. Каждый шаг — тест, отчёт, 0 регрессий golden.
Нумерация: память/звук `PS2-70..79`, сплитскрин/сеть `PS2-120..139`. Отчёт `docs/GATES/g1/opt6-S.md`. Каталоги `build/opt6-s/{out,run}`.
