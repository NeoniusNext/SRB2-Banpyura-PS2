**Прочитай целиком перед работой:** этот файл, `docs/OPT7_BRIEF.md` (требования пользователя — в силе), `docs/AGENT_BRIEF.md` (железные правила),

## Требования пользователя (критерий приёмки, дословно по смыслу)
1. На PS2 **намного больше FPS** — хотя бы около **60 FPS при 35 TPS**, и **намного выше стабильность**. Рендер/движок можно переписывать целиком, но без потери графики/физики (допустима малая погрешность).
2. **Главное: полностью завершить GS Hardware Renderer** — нативный PS2 (GS + VU0/VU1 + VIF/GIF DMA + scratchpad), все эффекты/освещение/возможности OpenGL HW-рендерера SRB2 (в пределах железа),
   полностью стабильный, **без графических багов («текстуры на стенах и полах глючат»)**, и **намного быстрее software** (software сильно грузит CPU). Можно переписать HW-рендерер, «шейдеры», функции под PS2.
3. **Вернуть всё, что было заблокировано на PS2:** аддоны (pk3/wad/soc/lua, меню Add-ons), Lua, UDMF, multiplayer (сплитскрин, сеть), **подключение к серверам ПК**, **мастер-сервер на PS2** (список серверов, вход на ПК-сервер из списка).
4. В конце — ELF со всем этим (аддоны, Lua, UDMF, сеть, мастер-сервер) + HW-рендерер.

## Железные правила (как раньше)
* Ничего не утверждать без запуска; числа — только релизная сборка (`SRB2_PS2_RELEASE` по умолчанию 1); FPS = 294 912 000 / тактов_на_кадр.
* **Никто не делает `git add/commit/stash/checkout/reset/restore`** и не откатывает чужие правки. Коммитит/сводит координатор.
* Правки ядра (общие .c/.h движка) — только под `PS2`/`PS2_PROFILE`/`HAS_*`/`PS2_*`: PC-сборка должна оставаться прежней. Каждое отличие — строка реестра в твоём отчёте (координатор переносит в `docs/DEVIATIONS.md`).
* Свой каталог сборки/прогонов: `build/opt9-<роль>/{out,out-hw,out-full,run}` (`SRB2_PS2_OUT=...`). Отчёт — `docs/GATES/g1/opt9-<РОЛЬ>.md`, **дописывай после каждого этапа** (лимит API обрывал сессии).
* После каждого этапа дерево должно собираться: software (`python tools/ps2/build.py`), HW (`SRB2_PS2_HW=1`), полная (`SRB2_PS2_NO= SRB2_PS2_HW=1`).
  Если сборка падает в **чужом** файле из-за чужой незаконченной правки — подожди 3–5 минут и пересобери; чини сам только очевидную опечатку и запиши это в отчёт.
* Чужие файлы — только точечные правки инструментом Edit (никогда не переписывать файл целиком), каждую — в отчёт (раздел 5). Свои файлы правь как угодно, но перечитывай перед правкой (их могут точечно трогать другие).
* Golden: software-путь ванильного режима обязан остаться побитно прежним — 4 демо `DEMO_001..004`, `python tools/ps2/ftest_golden.py --name ... --elf <--ps2ref сборка> --demo DEMO_00n` → «0 differ».
  Агенты, которые трогают общий код движка (S, F, N, HG при правках r_fps.c и т.п.), прогоняют golden в конце каждого этапа.
* Паки: `build/opt6-s/pak` (или `build/opt7-h/pak`, жёсткие ссылки на те же файлы). ПК-эталон: `srb2-assets/srb2win.exe` (OpenGL/software снимки — `build/opt8-h/pcshot.py`), ПК-сборка из репо для сети — `build/opt7-s/pc/srb2-s7pc.exe`.
* Внешние сервисы: **запрещено** регистрировать сервер на настоящем мастер-сервере `ds.ms.srb2.org` и заходить на чужие публичные серверы. Разрешено только чтение списка (HTTP GET) с настоящего мастер-сервера и всё — на локальных ПК-сервере/mock-мастере.

## Стандартные замеры
* Скорость: `-timedemo DEMO_00n.lmp -ps2prof` (+ `-renderer Hardware` для HW) → строки `PROF`/`HWPROF` по окнам 105 кадров; в отчёт — среднее и максимум `wall`/`total` по окнам 1..N для **всех четырёх демо**, software и HW на одной и той же сборке.
* Картинка: `-skipintro -warp N -vidshot l300,...` (+ `=map~K` — несколько карт за прогон) → PPM; ПК-эталон тем же кадром/позицией (`pcshot.py`); монтаж/диф — скрипты `build/opt8-h/*.py` (копируй в свой каталог).
* Память: `-zck -zstack -zquit N`, `map_sweep.py`; строки `ZSTAT` (gpeak/free/largest).
* Бюджет кадра: 60 FPS = 4.9 М тактов; 35 FPS = 8.43 М. Логика тика ≈2–3 М → для 60 FPS рендер HW ≲ 3 М/кадр (на EE).

## Роли (6 агентов). Владение файлами: правишь свои; общие — точечно и в отчёт.

### HT — HW: текстуры, VRAM, загрузка, GIF/DMA (реестр `PS2-HW-30..39`)
Файлы: `src/ps2/hw/ps2_hw_tex.inc`, `ps2_hw_gs.inc`, `ps2_hw_priv.inc` (структуры — общие для HT/HG/HF: добавляй, не ломай), `ps2_hwd.c` (Init/VRAM/статистика), `ps2_hw_regs.inc`, `src/hardware/hw_cache.c`, `hw_batching.c`, PS2-части `hw_data.h`/`hw_glob.h`.
1. **Убрать потерю качества PS2-HW-24 (децимация) без возврата тормозов:** один экземпляр данных в VRAM для вариантов, отличающихся только CLUT (с ключом/без, палитровые трансляции/colormap при тех же индексах);
   размещение по фактическому размеру (TBW/строки, а не степень двойки, где возможно); **zero-copy загрузка** (DMA REF/IMAGE прямо из выровненных данных `GLMipmap_t`, `SyncDCache`), без копирования в кольцо;
   потоковая подкачка в порядке батчей (отсортированных по текстуре), политика вытеснения, при которой текстура не грузится дважды за кадр; при необходимости MIP-уровни GS (MIPTBP) для дальних поверхностей.
2. Цели: `tex` ≈ 0 М/кадр, `decim=0` на всех картах, загрузок за кадр — минимально; проверка рабочих наборов на картах 1..33 (+ спец-этапы, NiGHTS, CEZ/ACZ/ERZ, титул, меню).
3. Корректность текстур: нет «чужой» текстуры после вытеснения, нет устаревшей CLUT, NPOT/повтор, смена палитры (flash), смена рендерера Software↔Hardware и ClearMipMapCache без утечек VRAM/EE.
4. GIF-кольцо/DMA: двойная буферизация, никаких лишних ожиданий (`clear`/`flipwait`/`dmawait` — разобрать, что из них реальное ожидание GS, а что работа EE).

### HG — HW: геометрия и CPU-путь (движок + трансформ, VU) (реестр `PS2-HW-40..59`)
Файлы: `src/hardware/hw_main.c`, `hw_main.h`, `hw_bsp.c`, `hw_clip.c`, PS2-части `hw_defs.h`, `src/ps2/hw/ps2_hw_xform.inc`, `ps2_hw_vu0.inc`, новые `src/ps2/hw/ps2_hw_vu1.inc` + микрокод `src/ps2/hw/vu1/*.vsm`
(ассемблер есть: `D:/ps2dev/dvp/bin/dvp-as.exe`; интеграция в HW-часть `tools/ps2/build.py`/`sources_hw.txt`), HW-части `src/r_fps.c`.
1. Измерить подробно (доп. отсечки `HWP_*`), где уходят `bsp` 5–15 М, `clear` 4–5 М (небо?), `sprites`, `nodes`, `drv draw` 4 М.
2. Сократить CPU: предвычисленная статическая геометрия стен/плоскостей карты (пересчёт только «грязных» секторов: высоты, текстуры, смещения, свет), float без `double`/libm в горячих путях, дешёвое отсечение (frustum по bbox узлов + clipper),
   кэш неба, батчинг спрайтов; **трансформ/клип/упаковка на VU1** (VIF1 DMA, EE только отсекает и строит цепочку REF) или хотя бы VU0 macro-mode — по замеру, что даёт больше.
   Новый быстрый путь подачи геометрии — отдельным файлом с минимальным хуком в `ps2_hw_draw.inc` (владелец HF); результат (ST/Q/цвет/fog/Z) обязан совпадать с EE-путём (хост-тест или попиксельный диф снимков).
3. Цели: HW `wall` ≤ 8.4 М/кадр в среднем на всех 4 демо (≥35 FPS) и явно ниже software; стремиться к ≤ 4.9 М (60 FPS). Показ 60 Гц через интерполяцию (PS2-95, `r_fps.c`) при 35 TPS — проверить плавность и что тики не теряются.
4. Рекомендация координатору с числами: делать ли HW рендерером по умолчанию.
