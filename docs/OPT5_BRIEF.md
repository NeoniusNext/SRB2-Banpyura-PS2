## Гипотеза пользователя про зависание HW (проверить ПЕРВОЙ, агент H)
Пользователь заметил: **картинка в GS HW застывает, когда во время 3D-сцены появляется 2D-меню** (пауза/меню/оверлей поверх 3D, а не при самом входе в 3D).
Ищи в пути «2D-оверлей поверх 3D» в `Impl_FinishUpdateHW`/`ps2_hwd.c`: смена GS-контекста/Z-теста/альфа/текстурного состояния, переключение «3D → 2D (патчи, V_Draw*, screen capture/wipe, GENERIC-слоты)»,
снимок кадра для фона меню (screen capture local→local), ожидание `FINISH/SIGNAL`, который не приходит, переполнение кольца пакетов, DMA-tag/выравнивание, VIF1 в состоянии stall, залипший `GIF PATH`.
Воспроизведение: обычный запуск `-renderer Hardware` (не `-timedemo`): титул → новая игра → GFZ1 → открыть меню паузы/ESC (используй скрипт ввода/эмуляцию кнопки pad в PCSX2 или тестовый хук `-ps2autopause N`; при необходимости добавь отладочный хук ввода под `PS2_PROFILE`).
Доказательство: ≥ 3000 кадров 3D, из них ≥ 500 с открытым 2D-меню/оверлеем, счётчик кадров растёт, лог в отчёт. Добавь watchdog с диагностикой (какой DMA/канал/ожидание завис) вместо тихого зависания.
Затем: визуальная корректность (сравнение со software), потом скорость (цель: HW быстрее software, ≤ 4.9 М тактов EE/кадр; главное узкое место по OPT3 — перезагрузка текстур, пул GS 3 МиБ vs рабочий набор 4.6 МиБ, и CPU-стоимость HWR_* обхода).
Допустимо радикально перепроектировать (VU1-микрокод, предвычисленная геометрия карты, политика текстур). Рекомендация координатору: можно ли сделать HW рендерером по умолчанию.
