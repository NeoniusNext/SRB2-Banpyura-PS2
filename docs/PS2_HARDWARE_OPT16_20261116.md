# PS2 Hardware: checkpoint v7 — метаданные, отсечение и точный PSMT4

База этой волны — `604cfd150c5240142d8cb5367950b53d987916d1`.
Этот документ фиксирует проверенную полную Hardware/LTO-сборку **renderer-v7**
с изменениями по `45f8de1cbf33e8e7b2581afc08cb02499dd8c186` для обычных
**32 МиБ RAM**. Новые работы opt17 над loader/cooker и сжатием CPU-кэша
спрайтов в эти результаты не входят. Код физики и игровые ресурсы не менялись.
Уменьшения лимита текстур, отключения
Lua, аддонов, сети или форматов нет. Совпадение проверенных кадров не доказывает
совместимость всей игры и всех карт; физическая PS2 не проверена.
Границы checkpoint и замороженный ELF приведены в
[сводке v7](../build/nov16-hwopt/v7-renderer-validation-summary.json).

## Изменения по умолчанию

* Таблицы всех текстур заменены страницами по 16 записей, создаваемыми при
  обращении. Указатели живых записей сохраняются до освобождения таблиц.
  Диапазон ID и неполная последняя страница сохранены. Mipmap EE занимает
  **68 вместо 76 байт**, запись стены — 76 вместо 84. При 4740 ID начальные
  массивы указателей требуют 2376 вместо 758400 байт; реальные страницы
  добавляются по мере использования. Это граница payload, а не замер всей RAM.
* `PS2HWD_ParaHidden` сначала проверяет прежний eye guard всех углов,
  затем общую внешнюю плоскость после каждой координаты. При раннем отказе
  оставшиеся преобразования и деления не нужны. Решения о видимости сохранены.
* Планировщик хранит стоимость шести достижимых уровней вместо восьми:
  **8704 → 6528 байт** статического scratch. Убран расчёт стоимости уровня
  `cap+1`, который никогда не читается. Тип стоимости остаётся `u32`.
* Утраченный purgable AP88-источник обычного patch восстанавливается из уже
  закреплённых колонок живого patch, с исходной colormap. Новых полей на
  текстуру или второй копии источника нет. Выделение только пробное: при
  нехватке памяти сохраняется прежний отказ без нового fatal OOM.
* Первые 64 попытки LRU-выделения VRAM сохранены. После них аллокатор ещё
  раз проверяет свободный диапазон, затем пробует одно допустимое выровненное
  окно прежней `best_window`-политики. Защита pinned/current/shared/capture
  сохраняется; новых лимитов, уровней текстуры или бесконечных повторов нет.

[Метаданные и жизненный цикл](PS2_TEXTURE_METADATA_PAGES_20261116.md),
[отсечение и исходные Count-замеры](research/opt16/FRONT_PARA_CULL.md),
[границы индексов планировщика](research/opt16/PLAN_SCRATCH_20261116.md),
[восстановление AP88](research/opt16/PATCH_RESCUE_20261116.md) и
[восстановление выделения VRAM после 64 попыток](research/opt16/VRAM_RECOVERY_20261116.md)
содержат воспроизводимые проверки и отрицательные контроли.

В 12 отдельных EE/PCSX2-тестах с реальными флагами драйвера
`-O3 -G8 -flto` десять случаев отсечения быстрее на **20,85–63,66%**;
два eye-случая практически равны базе. Это результат процедуры, не общий FPS.
Пробный вариант повторного использования центра сущности оказался медленнее
и удалён. Сохранённые решения о видимости не вводят новой истории загрузки
текстур. Новых hard-distance отсечений или неподтверждённых occluder-границ нет.

## Реальная RAM: парный MAP02, 350 кадров

Оба диагностических ELF меняют только существующий initializer локального RNG
на один и тот же seed. Обычный публикуемый ELF сохраняет OS RNG. Наблюдатели,
настройки, ресурсы и 32-МиБ профиль эмулятора совпадают.

| Показатель, байт | База | Результат | Изменение |
| --- | ---: | ---: | ---: |
| Арена: used / peak / global peak | 22018736 | 21260384 | −758352 |
| Арена: free | 1529168 | 2279328 | +750160 |
| Арена: largest | 1511824 | 2261968 | +750144 |
| Свободно в C-куче | 169656 | 156584 | −13072 |
| `I_GetFreeMem` = свободно в арене + C-куче | 1698824 | 2435912 | **+737088** |
| Spill: текущий / пик | 2118912 | 1360512 | −758400 |
| Размер арены | 23547904 | 23539712 | −8192 |
| Относительный пик C-кучи | 426496 | 442240 | +15744 |
| Использованный стек | 132560 | 132560 | 0 |

Таким образом, суммарно доступной RAM в этом checkpoint больше на
**719,8125 КиБ**; used/peak арены ниже на **740,578125 КиБ**. Spill уже входит в
экономию арены: складывать эти две экономии нельзя. Новая программа увеличила
`_end` на 4728 байт; округление арены отняло 8192 байта. При этом её свободное
место заметно увеличилось. Меньший запас C-кучи остаётся ограничением:
фоновые потоки не используют main-thread spill в арену.

После начальной очистки уровня дополнительных zone evictions нет. Числа
начальных evictions, неудачных попыток выделения, flush и стек совпали.
Все полные упорядоченные потоки совпали: 10 `LHASH`, 407 `HWPH`, 2 `HWLT`,
49 `HWWS` и 3 resource-хвоста `HWPROF`.

Строгий прежний memory gate **остаётся красным**: он отдельно требует, чтобы
C-peak не вырос, C-free не уменьшился и размер арены не уменьшился. Все три
ограничения нарушены ровно в указанных выше размерах. Правила не ослаблены;
вывод об экономии основан на исходных числах и реальном `I_GetFreeMem`.
Один сырой итог Count вырос с 387113003 до 397309189; wall `t_ms` —
27893 → 27729. Этот прогон не подтверждает рост общего FPS. Исходные числа,
совпадение потоков и все три ошибки сохранены в
[strict pressure report v7](../build/nov16-hwopt/v7-default-pressure/report.json).

## Игровые кадры и строгие проверки v7

Проверены по три полных PPM для MAP02, MAP01, fog/NPOT/stereo и двух режимов
старого коллектора, отдельно в default и полном режиме. В каждом наборе
**15 из 15 пар побайтно совпали**: изменённых пикселей и RGB-ошибки нет.
Loader hashes и сохранённые конфигурации совпали. Снимки получены обычными
ELF с OS RNG и сравниваются целиком, без crop, масштабирования или исключений.

Строгий **default image gate остаётся красным**: в каждом из десяти запусков
базы и кандидата записано по **40** `HWSKIP` класса `selected while collecting`.
Это унаследованные сигналы, присутствующие с обеих сторон сравнения; для них
нет исключения из gate. `purged_source`, `not_resident` и `other` в этих
диагностических строках отсутствуют. Строки не являются полным счётчиком
draw calls, а совпавшие снимки не доказывают отсутствия пропусков между ними.
[Default image report v7](../build/nov16-hwopt/v7-default-images/report.json)
сохраняет все десять ошибок.

В полном режиме все десять запусков завершили тот же набор сцен без
диагностик missing/skipped draw; его строгий image report не содержит ошибок.
Обе роли использовали одинаковый `-hwdbg 33554432`.
[Full image report v7](../build/nov16-hwopt/v7-full-images/report.json)
относится к этим пяти сценам и 15 снимкам, а не ко всей игре.

## Необязательный режим полных текстур

`-hwfulltex` — удобное имя существующего `-hwdbg 33554432`: frame/immediate
mip planning отключён. В этом режиме подходящие полные P8 map/flat текстуры
упаковываются в PSMT4, когда все исходные индексы лежат в одном выровненном
диапазоне из 16 цветов. Размер, исходные индексы, CLUT CT32, фильтрация и
альфа сохраняются; квантизации цвета нет. Неудачное выделение P4 повторяет
прежнюю попытку P8. Другие debug bits, cap/budget и неподходящие изображения
оставляют прежний путь. **Обычный режим планировщика остаётся P8.**

Селектор строки P4 перенесён из VU data quadword **28 в 856**: прежний адрес
перезаписывал boot-таблицу плоскостей/масок clipping. Расширенный нативный GS
fixture прошёл **700/700 в CT32 и 700/700 в CT16**. Все **232 полные
P8/P4-пары, 16629760 пикселей**, совпали. Помимо прежних случаев, в каждом
формате выполнены 42 clipping-пары со свежей P8-базой, всеми шестью плоскостями,
negative-W/eye crossings и переходами P4 → clipped T8/T4 и mode exit → T8.
Все 48 слов VU plane/mask остались целы. Исполненный контроль со старым адресом
28 дал 48 ошибок: 42 нарушения таблицы и шесть расхождений целого кадра.
Прежние 447 проверок не обнаруживали этот дефект. Проверены все 16 банков,
32 строки освещения с реальными VU1-полигонами, новые палитры и таблицы,
plain/keyed views и pending draws при переключении режима. Текстура 1024²
действительно резервирует **4096 → 2048 блоков GS**, то есть экономит
**512 КиБ VRAM**. Дополнительная копия исходника или CLUT не выделяется;
частные record size/offsets остались прежними, 140 байт.
Полный [native clipping report](../build/nov16-hwopt/p4-clip-native-fixed-v1/native-summary.json)
относится к изолированному GS fixture; он не является запуском полной LTO-игры.

Отдельный [stock trace v7](../build/nov16-hwopt/v7-stock-trace/report.json)
показывает реальную `F:GFS_CLD3` размером 1024² как P8 (`psm=19`) у базы
и P4 (`psm=20`) у кандидата. Stock trace печатает формат, размер и адрес,
но не `nblk`: **4096 → 2048 блоков** напрямую измерены отдельным native fixture.
Между ним и v7 побайтно связаны функции footprint/stride и layout, а не весь
файл загрузки текстур. Это подтверждает экономию 512 КиБ на таком изображении,
без вывода о суммарной занятости VRAM сцены.

Режим полных текстур может увеличить CPU-работу и число загрузок относительно
обычного адаптивного режима. У него нет обещания роста FPS. Уменьшение одной
аллокации также не означает, что итоговая занятость GS всегда ниже: в пуле
могут остаться дополнительные полные изображения. Подробные ограничения,
реальные footprint и raw full-mode counters приведены в
[P4_FULL_SIZE.md](research/opt16/P4_FULL_SIZE.md).

Отдельный 350-кадровый MAP02-прогон с полными текстурами завершён без missing
content. Сумма свободной арены и C-кучи выросла на 721072 байта, used арены
снизился на 742336, а peak — на 425008 байт. Наблюдавшиеся значения GS-пула
в блоках: база 9864/8141/9487, кандидат 9732/11225/9359 при ёмкости 12032.
Суммарная экономия пула не заявляется. Это
[сырой профиль одинакового full-mode v7](../build/nov16-hwopt/v7-full-profile/report.json),
а не успех исходного strict memory gate или сравнение с default-качеством.
Меньшие arena/C-free и больший C-peak, zone failures/evictions и изменившаяся
резидентность сохранены в отчёте; вывод о FPS по нему не делается.

## Сборка, проверки и источники

В source manifest checkpoint v7 закреплены все 602 production-файла каждой роли.
Для A/B метаданные обеих сборок закреплены на базе 604; действительный код
задаёт этот manifest, а не строка revision на экране. Полная сборка включает
203 C units и две VU-программы, с прежними функциями и release/LTO-флагами.
Замороженный shipping ELF v7 занимает **11268908 байт**, SHA256:
`8fabe702b3785a8a5b80b0711c0e7b2edcf95d561a58586fc2e91d07983f67df`.
Текущее дерево и последующие изменения opt17 этим ELF не проверены.

Component fixtures проверяют 851 lifecycle-сценарий страниц, полное заполнение
4740 записей, ID 65537, allocation failures и реальные free под ASan/UBSan;
компактизация — 270 сценариев и полный replay upload/cache; P4 — более
101 млн проверок на обычном host и с sanitizers; planner — 703 сценария,
включая размеры 16384² и `cap=5`. Исполняемые повреждения выявлены, а не
отклонены только текстовым поиском. Native host suite: 20 групп и 22 контроля.

Численный VU0 gate стандартного GS suite остаётся отдельным известным FAIL;
арифметика transform и допуски в этой волне не менялись. Успех целевого P4
fixture не выдаётся за успех этого gate. Все три нарушения default memory gate
и красный default image gate также сохранены. Связанные отчёты выше и
[сводка renderer-v7](../build/nov16-hwopt/v7-renderer-validation-summary.json)
описывают этот checkpoint; новые оптимизации требуют собственной интеграционной
проверки.

Расширен [каталог проверенных PS2-источников](research/opt16/PS2_SOURCES_20261116.md):
GS page/block layouts и ограничения CLUT, SCEE clipping slides, оригинальная
статья о conservative/tiled rasterization. Он продолжает прежние 47 основных
источников, не объявляя интернет-исследование исчерпывающим. Полные руководства,
BIOS и игровые PAK не публикуются. Физическая PS2 и длительный soak не проверены.
