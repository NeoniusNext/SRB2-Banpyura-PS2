# Exact CT32 upload preparation, sixth pass, 2026-11-14

Three texture row fillers retain their immutable context for one call instead
of reloading its width and column shift after every output store. In the
separate-TU EE workload, all **126 configurations improve**, and summed median
cost falls **30.1367%**. Complete object text falls **24 bytes**, with no added
stack frame or persistent storage. This component claims no VRAM/DMA/GPU-work
reduction or whole-game/physical-console FPS percentage.

The only production changes are in `fill_ap88_ct32`, `fill_ct32` and
`fill_ia88` in `src/ps2/hw/ps2_hw_tex.inc`. Each reads a fresh `fillctx_t` value
at entry. Source row/column formulas, texel reads, palette reads, alpha
conversion and pixel stores keep their original expressions and order. No
format, dimensions, sampling, filtering, precision or compatibility limit
changes. The earlier PSMT8 AP_88 gather and all preceding optimizations remain.

## Bounded alias and lifetime audit

The comparison baseline is the preceding completed fifth pass at
`build/nov14-next6/baseline-src/src`, reconstructed and verified by
`tools/ps2/prepare_next6_baseline.py`. The fixture mechanically checks that
reverting only the three context snapshots reconstructs the **entire frozen
texture source byte-for-byte**, including every other row filler, classifier,
planner, cache, allocator and packet function. Caller counts are checked too.

Each selected filler has one selection site, in its format case of
`tex_upload`. That function owns and clears `fc` on its stack, then supplies
its source, dimensions and shifts before calling `upload_bands`. The latter
is the only callback invoker for these three functions. Its other caller
uses the separate `fill_screen` callback.

`upload_bands` gets the output payload from `pk_alloc` before invoking the
filler synchronously. The rings are separate `memalign` allocations, so their
payload cannot overwrite the caller's stack context. No filler calls an
allocator, scheduler, palette mutator, callback or DMA submitter. The existing
ring ownership/space checks precede filling. Context changes for a split
image occur between completed upload calls. The new value is local to one
row call and never retained across calls, rows, textures or palette changes.
Source and palette **contents** are still read anew for each texel.

This removes an alias possibility that exists for a generic `void *` C
interface but cannot occur in these bounded production callers. It adds no
source padding requirement, alignment requirement, pointer lifetime or cache.
The audit is retained as `caller-audit.json` in both fixture directories.

```sh
source /workspace/.onboarding/environment.sh

  --out build/nov14-next6/gs-next6-host \

python3 -B tools/ps2/gs_next6_hosttest.py \
  --out build/nov14-next6/gs-next6-ee \

python3 -B tools/ps2/run_pcsx2.py \
  --elf build/nov14-next6/gs-next6-ee/GS_NEXT6.ELF \
  --log build/nov14-next6/gs-next6-ee/run.log \
  --until 'GS NEXT6 DONE' --timeout 300
python3 -B tools/ps2/gs_next6_hosttest.py \
  --out build/nov14-next6/gs-next6-ee \
  --summarize build/nov14-next6/gs-next6-ee/run.log
```

Actual frozen/current production functions and the driver are in **three
separate non-LTO translation units**. The independent byte-oriented oracle
uses the original `(alpha*128+127)/255` rounding. Every 16-bit AP_88 and IA_88
pair occurs in every one of four pixel positions. RGBA covers every alpha
value, byte/channel combinations and randomized/constant input. The host
matrix covers all widths 1..1024, the original valid source/output alignments,
cropped source strides, later rows, shifts 0..10, and repeated calls that
change the context and palette. Complete output/canary buffers, source bytes,
palette and context are compared.

Ordinary host and ASan/UBSan runs each pass **318,523 cases and 50,912,388
pixels**. Five deliberate corruptions are detected: retaining a snapshot
across calls, changing an alpha bit, sampling the next column, writing one
extra texel and using the wrong row. The standard 32 MiB EE run reaches
`GS NEXT6 DONE`, wrapper exit 0, after **208,224 exact/oracle cases and
2,524,390 pixels**. Its exhaustive width sweep is reduced to 1..65 plus the
same large boundary widths; the complete byte-pair set remains.

## EE cost and footprint

EE GCC 15.2 uses the normal `-O2 -G8 -mno-abicalls` ABI with `-Werror`.
Only the SDK's existing abicalls link warning remains. Volatile function
pointer selection prevents constant call specialization; nine repetitions
alternate version order. All timed outputs and canaries are compared after
each pair. Measurements are median CP0 counts for complete row calls.

| Format/path | 42-row baseline sum | Current sum | Change |
| --- | ---: | ---: | ---: |
| AP_88 requiring CT32 | 242,291,308 | 171,241,288 | −29.3242% |
| RGBA requiring CT32 | 213,062,652 | 149,319,796 | −29.9174% |
| Alpha/intensity 88 | 227,676,980 | 156,626,960 | −31.2065% |
| All 126 rows | 683,030,940 | 477,188,044 | **−30.1367%** |

Individual gains are **6.0605–34.4207%**, including every measured one-pixel
row. Each format covers widths 1/2/3/4/7/16/31/64/127/256/511/1024, source
and destination alignment variants, and both contiguous and existing
decimation paths. There is no newly introduced fast/fallback dispatch.
These sums describe this synthetic workload; they are not weighted by game
texture frequency or a complete texture upload's allocation/DMA cost.
Physical PS2 cache/bus behavior and frame-time stability were not measured.
