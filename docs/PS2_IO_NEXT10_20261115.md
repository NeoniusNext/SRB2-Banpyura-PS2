## Work removed and preserved semantics

The existing 64-entry lump-number cache keeps its hashes in a contiguous
256-byte array. The preceding lookup still masks, scales and adds a circular
slot index on every hash miss. The candidate checks the current slot first,
then scans the remaining hashes in two descending contiguous spans, deriving
a slot number only when its hash matches.

The order remains exactly `cursor, cursor-1, ..., 0, 63, ..., cursor+1`.
Both original hash bounds, case-conversion behavior, short-name byte-eight
test, short/long comparison functions, duplicate precedence, cursor updates,
replacement order, invalidation and every cache byte are preserved.
The complete cache stays **2,560 B** and its cursor stays **2 B**. There is no
new persistent scratch, allocation, resource limit or pack/read operation.

The first span starts at `base + cursor` and predecrements only while its
pointer differs from `base`. The second starts one past the 64-word array and
predecrements only while it differs from `base + cursor + 1`. Thus each
dereference addresses a word in the array, and no pointer before `base` is
formed. The pointer-derived local slot is always 0 through 63. The final
candidate uses a 32-bit local index to remove redundant 16-bit truncations;
the stored cursor width does not change.

WAD/ZWAD, ZIP, cooked packs, folders, lazy positions, dynamic reads, loader
errors/callbacks, Lua and network behavior are outside the changed function.
All accepted location/index/LZ4/recovery changes remain in place. The rejected
ninth-pass header overlay is not reintroduced.

cursors, seven hit depths including a full miss, and both ordinary and

`span1` regresses every first-hit row by a summed 4.314404% and every

but 61 collision rows and 13 ordinary rows remain slower. Both are rejected.
Their complete raw logs and reports remain in `io/linked` and
`io/refinement-linked`; `io/wide-linked` contains the final gate.

The selected summed count is **32,664,090 → 30,275,994**. Its first-hit group
improves 0.900466%, deliberate collisions 3.984729%, ordinary hashes

Removing the unnecessary local truncations eliminates four `andi 0xffff`
operations and one saved register from the preceding representation. The
stored cursor and every available slot remain unchanged.

No universal RAM saving is claimed. Even a text-size change can alter the
EE arena boundary; any retained candidate also needs the coordinator's full
gameplay/cache-pressure integration rather than relying on these kernel rows.

## Reproduction

The three checked zero-context patches reconstruct the exact tested sources
without editing production. `next10_io_variant.py` verifies the complete
preceding source, patch and resulting source hashes. Select `span1`, `fastslot`
or `wide` and use a fresh build directory:

```sh
python3 -B tools/ps2/next10_io_variant.py --variant wide \
  --out build/next10-io-replay/src/w_wad.c
python3 -B tools/ps2/next10_io_hosttest.py \
  --candidate build/next10-io-replay/src/w_wad.c \
  --out build/next10-io-replay/host --negative-controls
python3 -B tools/ps2/next10_io_hosttest.py \
  --candidate build/next10-io-replay/src/w_wad.c \
  --out build/next10-io-replay/asan --sanitize
```

The complete merge uses `next10_io_lto.py --build` with an intact canonical
build, `--snapshot` with frozen project/generated includes, the selected
`--source`, an isolated `--out` and optional `--link`. It uses one EE worker,
checks the original objects/binaries unchanged and never starts emulation.
The optional `--optout` selects the preceding cache function.

`next10_io_linked.py` builds the two actual-engine gates. Run them only through
`run_pcsx2.py`, using `--until 'CACHE10 DONE'`, then select their directory with
`next10_io_linked.py --out ... --summarize`. `next10_io_codecheck.py` checks
object/ELF binding, `--baseline` isolation and optional `--measured` final
binding. Add `--measured-elf` with the timed gate to compare the complete SDK
leaves/table and their individually resolved addresses. The checker never
compiles or runs the game.
