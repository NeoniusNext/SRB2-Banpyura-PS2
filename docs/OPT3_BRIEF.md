## Цель пользователя (по смыслу, дословно)
1. На PS2 **намного больше FPS: хотя бы более-менее 60 FPS при 35 TPS**, и **намного выше стабильность**. Рендер и движок можно переписывать полностью, но **максимально без потери графики, физики и прочего** (допустима небольшая погрешность).
2. **Довести до конца полноценный GS Hardware Renderer** — он должен быть намного быстрее software (software сильно грузит CPU), **полностью нативный под PS2, использующий все ресурсы PS2** (GS, VU0/VU1, DMA-цепочки, scratchpad, IPU при пользе); можно переписать hardware renderer, шейдеры, функции под PS2.
3. (из прошлой сессии, остаётся в силе) глюки звука при загрузках и при низком FPS; MAP11 (CEZ2) падает на 32 МБ из-за фрагментации (`PU_RENDERWORK` 524288 Б в `Picture_TextureToFlat`).

## Базовая линия (PCSX2, релиз, боевой путь, `--noref`)
Бюджет 8.43 М тактов EE/тик (35 Гц); для 60 кадров/с — 4.9 М тактов/кадр. Software: DEMO_001 **20.8 М/кадр (14 FPS)**, DEMO_002 19.5 М (15 FPS): BSP+стены+спрайты 9.0/7.8, planes 5.6/4.0, masked 1.9, P_Ticker 1.1/3.3.
Это означает, что **одного ускорения software недостаточно для 60 FPS**; главный путь — HW-рендерер (CPU делает только BSP-обход и подачу геометрии, растеризация на GS). 60 FPS показа при 35 TPS достигается интерполяцией кадров
(`r_fps.c`, `R_GetFramerateCap`, `cv_fpscap`; в `i_video.c` уже есть логика «cap выше tic rate»). Физика/тики не трогать.

## Общие правила
* Эмулятор — только через обёртки (общая блокировка; ожидание очереди — норма; один запуск за раз на всех агентов). Прогоны тратят время: не запускай лишних, не дублируй чужие.
* Замеры — только `SRB2_PS2_RELEASE=1`. Любая оптимизация = хост-тест эквивалентности (с негативным контролем) + замер COP0 до/после. Единица: такты EE на кадр, эквивалентный FPS = 294.912 М / (такты/кадр).
* Общие заголовки (`doomdef.h`, `doomtype.h`, `r_defs.h` вне S) — через координатора (опиши в отчёте).
* После каждого этапа дерево должно собираться (`build.py` и `SRB2_PS2_HW=1 build.py`), отчёт обновлён — сессию могут оборвать по лимиту. Пиши отчёт инкрементально.
* Не сломай software-путь: он остаётся эталоном «1:1», golden-демо (`tools/ps2/run_ps2_ref.py --mode demo --demo DEMO_00n`) должны остаться с 0 различий (DEMO_003 расходился с golden уже на базе — не ты виноват, но не ухудшай).
* Итоговый отчёт: 1. Что сделано. 2. Команды и числа до/после. 3. Не проверено/ограничения. 4. Строки реестра отличий. 5. Нужные правки в чужих файлах.
