# Exact VRAM range movement, tenth pass, 2026-11-15

The GS allocator now keeps each existing `u16` start/length pair in one
word-aligned four-byte record. Six list-shift loops copy that record with a C
structure assignment. Allocation arithmetic, search direction, alignment,
splitting, coalescing, return values and failures retain their original rules.
No `u32` type pun, reduced field width, extra allocation or capacity reduction
is introduced.

The actual default-LTO high/free helpers improve in **90 of 144 configurations**,
with **54 ties and zero slower rows**. Their summed median EE cost decreases
**47.1061438%**. The separately measured complete upload path, including its
inlined low allocator and actual memory wrappers, improves in **all 96 rows**;
its summed median cost decreases **6.0892792%**. These are unweighted component
measurements on emulated EE, not game FPS or physical-console measurements.

All later state offsets and alignment remain. Full 4 MiB GS address space,
the whole-memory length, and the defensive full-array handling remain. The
private range list is EE allocator metadata; it is not submitted to the GS.
Its consumers are the three allocator operations and initial pool setup. No
interrupt handler, serialization or DMA reader observes intermediate range
movement. GPU packet bytes and resource decisions remain unchanged.

There is a physical layout tradeoff. A start-only search traverses addresses
with stride four instead of two: its logical address span grows from about
`2*N` to `4*N` bytes. Allocator searches that read both members still consume
four metadata bytes per range, now adjacent. The measured flush-requested
emulator rows do not establish a physical PS2 cache-latency guarantee.
No VRAM, persistent EE-memory, DMA/GIF-byte or GPU-work saving is claimed.

## Complete source and state oracles

Ordinary host and ASan/UBSan runs each pass **52,637 cases**: 33,777 allocation
operations, 18,857 frees and three separately labelled defensive capacity
cases. They inspect **3,884,189,504 complete-state bytes**. The fixture compiles
the actual frozen/current allocator bodies separately and compares both with
an independent 16,384-block occupancy map. It checks placement, accounting,
every live range, all inactive range slots, all remaining driver-state bytes
and state canaries.

The matrix covers low/high allocation, positive requests through the full
16,384-block length, power-of-two alignments, empty and fragmented pools,
every split/coalesce shape, restoration after random allocation/free traces,
and 8,192 live singleton ranges. Defensive synthetic full-array states are
distinct from valid sorted/merged bitmap states; their refusal and existing
capacity diagnostic/abort are captured and checked. All RNG draws are
explicitly sequenced. Six executed source corruptions fail: skipped right
movement, wrong tail length, accounting, coalescing, skipped left movement
and changed return address.

The native high/free run uses the complete actual engine instructions and
passes the same shorter host corpus: **5,169 cases**, 4,574 allocations,
592 frees, three defensive cases, **381,430,848 state bytes**, digest
`f48827bb`. Low allocation in this first fixture is source-compiled and has
no native timing claim; the separate complete upload fixture covers the real
inlined low path.

That second fixture compiles the complete production source on the host and
executes the actual linked upload graph on EE. Each host version and its
sanitizer run passes **48 configurations**, digest `d665cb39`. A separate
Python occupancy oracle predicts those results and the interleaved native
**96 cases**, digest `b66319c9`, which match exactly.

The low oracle independently enumerates PSMT8 block addresses, chooses a
free span from a bitmap and constructs GIF tags, A+D words, image bytes and
padding. It compares the complete ring with canaries, all 8,194 fixture record
slots, the full owner map, mipmap, source bytes, upload history, `TX`, remaining
globals and complete production `H`. Only the observational
`H.st.cyc_tex` CP0 statistic is normalized for the state comparison; elapsed
counts are checked separately. Unexpected resource, format, device or callback
boundaries trap. Existing records are pinned and the next record slot and DMA
ring have room, so successful rows execute no allocation or device substitute.

Six further executed low source corruptions fail: wrong allocation result,
TRXREG width, omitted pixel, owner pointer, serial update and source corruption.
Both strict report parsers reject eight executed malformed/duplicate/missing
row, parameter, completion, failure, digest or counter corruptions. Raw failing
outputs remain under their respective `negative-*` directories.

Thus the four bodies shrink 268 B combined; their complete input sections,
including trailing alignment bytes, shrink 264 B. Startup grows eight bytes,

Both high/free shift sites go from two SDK `memmove` calls to one. Their native
fixture preserves every complete section byte and original ordered RELA, then
checks all resolved bytes against the real game and fixture ELFs, including
trailing padding. The actual 500-byte SDK `memmove` body is identical and is
verified to have no calls, nonreturn jumps or syscalls. Only the pre-existing
defensive capacity diagnostic/abort use capture hooks; timed high/free rows do
not call them.

The low fixture embeds **11 complete actual code nodes and 42 complete data
nodes**: `tex_upload`, `tex_plan`, `tex_footprint`, `upload_bands`, `rec_new`,
`fill_idx`, `weights_prepare`, `small_victim`, `scr_spill_victim`,
`__wrap_memcpy` and `__wrap_memset`. Production copy/set calls execute those
real wrappers, whose `__real_*` calls execute the identical complete SDK
`memcpy`/`memset` bodies; `memmove` is the identical direct SDK leaf.
`memcmp`/`snprintf` and other unexpected production callees trap if reached.
Whole code, data, jump tables and SDK bodies bind to the actual game ELF.
The isolated full game reports zero compile/link diagnostics. Standalone fixture
links retain the existing SDK abicalls compatibility warnings in their raw logs.

The graph retains original R32, R26, HI16, LO16 and GPREL16 records, explicit
addends, local/global binding and input GP0 **32,752**. GAS aliases inherit
OBJECT type and raw `.reloc` words do not infer GP0, so the fixture object
restores only the original local SECTION symbol metadata and `.reginfo` GP0.
Every restored field, instruction and ordered relocation is checked before
linking. Nothing masks instruction bits or rewrites original addends.

The linker merges individual string literals. When identical complete strings
have multiple suffix-merged candidates, the checker decodes the concrete
original HI/LO target, verifies the entire aligned NUL-terminated source
literal there and records that address before applying the original RELAs.
It does not claim independent uniqueness of those addresses. Nonliteral targets
resolve independently through real symbols or exact input-section map entries.
Original build-report hashes pin the game/fixture files. Complete original
literal-pool bytes remain checked in the extracted object and fixture, and all
literal contents are checked in the game. Instruction, moved-relocation and
explicit-addend mutations are detected. Earlier upload/state code, including
the three AP88 `PPACB` sites, remains separately retained.

## Native timing scope

All rows run on the standard 32 MiB emulator profile. Each has nine repetitions
with alternating version order through volatile function pointers. Interrupts
are masked only inside the CP0 timing window and their prior state is restored.
The exact post-call state/output is checked every time. Cache-flush requests
write back/invalidate D-cache and invalidate I-cache outside measurement.
Their modeled counts equal the warm counts; neither result measures a physical
console's cache/bus behavior.

The 144 high/free rows cover empty lists and populations
1/2/3/7/16/31/64/127/512/2048/8192, first hits, skipped/unfit ranges,
remove/split/insert/merge paths, and warm/flush-requested calls. Each sample
sums eight complete helper calls. Summed medians are
**15,295,024 → 8,090,128**, **90 faster / 54 ties / zero slower**.

The 96 low rows cover populations 0/1/2/7/127/8192, P_8 1×1 and 64×16 uploads,
first/later fits, singleton/unfit lists and first-range splits, in both cache
modes. Each sample includes the complete actual upload call. An unfit row
executes one controlled `low_output` diagnostic capture in place of production
console formatting/I/O; that boundary is outside any full-console-cost claim.

| Low-path cohort | Rows | Before sum | After sum | Change |
| --- | ---: | ---: | ---: | ---: |
| Successful uploads | 64 | 2,245,180 | 405,314 | −81.9473717% |
| Unfit, controlled diagnostic capture | 32 | 27,971,500 | 27,971,388 | −0.0004004% |
| Entire prescribed matrix | 96 | 30,216,680 | 28,376,702 | **−6.0892792%** |

All 96 rows improve. The successful sum heavily weights synthetic long list
movement and is not texture-frequency weighted. Neither table is a complete
frame or all-format upload percentage. The complete kernel runs exit zero and
reach their distinct completion markers. Low pre/post manifests pin every
native input, runner, environment/configuration and full log; exact input copies
remain in `low/pinned-run-inputs` before later parser-only additions.

Both unchanged ELFs then complete fresh staged reruns under
`gs/{high-staged,low-staged}`. Every row parameter and every repetition count
is exactly equal to the original runs. Full before/after INI text, emulator
binary hashes and all non-UI settings are captured and checked; only the
frontend `UI` and `GameListTableView` sections are excluded from the settings
comparison. The profile retains 32 MiB RAM, default EE cycle rate/skip,
disabled EE-cache emulation, disabled patches/cheats and the same renderer.
All source/ELF inputs remain unchanged and both wrappers return zero.
`gs/staged-validation-report.json` records the comparisons. These runs close
the original full-INI-text provenance gap without changing a measured binary;
they still make no physical cache, console FPS or frame-time claim.
