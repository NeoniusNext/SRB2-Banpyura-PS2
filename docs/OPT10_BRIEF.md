# Бриф сессии OPT10 (2026-10-06/07): 6 агентов Sonnet — GS HW до конца, FPS, стабильность, всё возвращено, итоговая ELF

Продолжение `docs/OPT9_BRIEF.md` (роли и цели те же; **прочитай его и `docs/AGENT_BRIEF.md`, `docs/DEVIATIONS.md`, `docs/HW_RENDERER.md`, `docs/GATES/g1/opt9-*.md` своей области**).
Отличия этой сессии: **Linux-контейнер** вместо Windows, у каждого агента **свой git worktree**, 4 ядра CPU на всех (не гоняй лишнего).

## Требования пользователя (критерий приёмки)
1. На PS2 **намного больше FPS** — хотя бы около **60 FPS при 35 TPS** (показ 60 Гц интерполяцией, тики 35) и **намного выше стабильность**. Рендер/движок можно переписывать целиком, но без потери графики/физики (допустима малая погрешность).
2. **Главное: полностью завершить GS Hardware Renderer** — нативный PS2 (GS + VU0/VU1 + VIF/GIF DMA + scratchpad), все эффекты/освещение/возможности OpenGL-рендерера SRB2 (в пределах железа),
   **стабильный, без графических багов** («текстуры на стенах и полах глючат»), и **заметно быстрее software** (software сильно грузит CPU). Можно переписывать HW-рендерер, «шейдеры», функции под PS2.
3. **Вернуть всё, что было заблокировано на PS2:** аддоны, Lua, UDMF, сплитскрин, сеть/multiplayer, **подключение к серверам ПК**, **мастер-сервер на PS2** (список серверов, вход на ПК-сервер).
4. В конце — **ELF со всем этим** (аддоны, Lua, UDMF, сеть, мастер-сервер) + HW-рендерер. Что не удалось — честно в отчёте с числами; ничего не «объявлять» без запуска.

## Окружение (Linux, проверено координатором запуском)
* Тулчейн: `/opt/ps2dev-x/ps2dev` (ps2dev release, EE GCC 15.2.0, `dvp-as` в `dvp/bin`). `tools/ps2/build.py` уже работает на Linux (переменная `PS2DEV` переопределяет путь).
* Эмулятор: PCSX2 2.6.3 (AppImage, распакован), 4 одинаковых копии `/opt/pcsx2/slot0..3` (portable, 32 МБ, HostFs, **программный GS**, звук Null, BIOS пользователя `scph50003`). Запуск **только** через `tools/ps2/run_pcsx2.py`
  (сам берёт свободный слот, lock в `/tmp/srb2ps2-locks`, внутри `xvfb-run`) или обёртки: `tools/ps2/opt_run.py`, `ftest_run.py`, `map_sweep.py`, `net_session.py` (последний ещё не портирован — задача X).
  Не убивай чужие процессы; **`pkill -f` с шаблоном, который есть в тексте твоей же команды, убивает твою оболочку** (используй `pkill -x имя` или pid).
* Ассеты SRB2 2.2.15: `/opt/srb2-assets` (srb2/zones/characters/music.pk3, `srb2win.exe` не запускается). Cooked-паки уже собраны: `/home/user/SRB2-Banpyura-PS2/build/pak/*.PAK` (общие, только чтение; пересборка — `python3 tools/ps2/cook.py --src /opt/srb2-assets --out <dir>`).
* **Worktree:** ты работаешь в своём worktree (ветка `worktree-*`). Первым делом: `tools/ps2/wt_setup.sh` (ссылки на `srb2-assets`, `golden`, `build/pak`, `build/pc-golden`, `build/pc-ref` в основном дереве).
  **Коммить свои правки в свою ветку маленькими порциями** (`git add -A; git commit`), **не пушь, не переключай ветки, не трогай основное дерево `/home/user/SRB2-Banpyura-PS2`** (координатор сливает ветки). Сообщения коммитов на русском/английском, по сути.
* Сборка (≈20–25 с, LTO-шаг один): `SRB2_PS2_OUT=$PWD/build/out python3 tools/ps2/build.py --jobs 2` — software-профиль по умолчанию (`SRB2_PS2_NO=lua,udmf,addons,limits` вырезает контент);
  **полная:** `SRB2_PS2_NO= SRB2_PS2_HW=1 python3 tools/ps2/build.py --jobs 2` (Lua+UDMF+аддоны+лимиты+сеть+HW). Профайлер: `--prof` (строки `PROF`/`HWPROF`), для golden — `--ps2ref`. Быстрая сборка без LTO: `SRB2_PS2_LTO=0` (только для функциональных проверок, не для цифр скорости).
  **`--jobs 2`**: на машине 4 ядра на 6 агентов + эмуляторы.
* Прогон: `python3 tools/ps2/opt_run.py --name N --elf build/out/SRB2.ELF --pak /home/user/SRB2-Banpyura-PS2/build/pak --out build/runs [--map MAP01 | --demo DEMO_001 --no-ref] [--timeout S] [--until TEXT] -- <аргументы движка>`.
  Лог движка — `build/runs/N/boot.txt`, лог эмулятора — `pcsx2.log`. Конец таймдемо: `--until "gametics in"`. `-zquit N` завершает прогон на N-м кадре карты (`ZQUIT DONE`). HW: **`-renderer Hardware -zreserve 3072`** (без резерва C-кучи `HWR_LoadMapTextures` падает).
  PCSX2 передаёт ELF **не больше 16 аргументов** и режет `-gameargs` на ~128 символах: `opt_run.py` кладёт аргументы в `ps2args` (по одному на строку) — лишнее не теряется.
  Снимки: `-skipintro -warp N -vidshot l120` (`lN` — кадр N, `kN` — первый кадр с `leveltime >= N`, `KN`, `wN` — кадр wipe) → `vidshot-*.ppm` в каталоге прогона; в PNG: `convert x.ppm -scale 200% x.png` (ImageMagick), смотреть инструментом Read.
  Один прогон таймдемо ≈ 2–5 мин (эмулятор медленнее реального времени, software GS); 4 слота на всех: не держи слот дольше нужного, длинные соки — отдельными прогонами.
* **Эталоны ПК на Linux (новое):**
  * `build/pc-golden/bin/*/*` — ПК-движок из этого дерева (software, `PS2REF`), `build/pc-ref/bin/*/*` — то же с OpenGL (`-opengl`). Запуск под Xvfb: `SRB2WADDIR=/opt/srb2-assets SDL_AUDIODRIVER=dummy LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a <exe> -home DIR -win -width 640 -height 400 -opengl -skipintro -warp 1 ...`
    (домашний каталог на Linux — `DIR/.srb2`; снимок окна: `import -display $DISPLAY -window root x.png`; OpenGL работает на llvmpipe). Пересборка ПК: `cmake -S . -B build/pc-ref -G Ninja -DSRB2_CONFIG_STATIC_STDLIB=OFF -DSRB2_CONFIG_USE_GME=OFF -DSRB2_CONFIG_PS2REF=ON && ninja`.
  * `golden/phase0-v2/run1/DEMO_00n` — ПК-golden четырёх атракт-демо (`tools/ps2/make_golden_linux.sh`): **физика (`tics.csv`) PS2 совпадает с ПК** (DEMO_001/002/004 — 1050 тиков идентичны; **DEMO_003: `state_hash` расходится с тика 45 при тех же позициях — разобраться (задача S)**);
    пиксели PS2 vs ПК-Linux различаются на ±1..4 индекса палитры (≈41 000 px/кадр; причина не изучена — gcc/glibc против newlib; на Windows было 1–2 px) — поэтому для software-рендерера **регрессионный эталон — `golden/ps2-head/DEMO_00n`** (вывод PS2 software на старте OPT10):
    `python3 tools/ps2/opt_run.py --name gN --elf <ps2ref ELF> --pak ... --out build/runs --demo DEMO_00n --golden` (сравнивает с ПК) и `python3 tools/ps2/golden_check.py --run build/runs/gN/refout --ref golden/ps2-head/DEMO_00n --pixels` (побитно, «0 differ»).
    ELF для golden: `SRB2_PS2_NO= python3 tools/ps2/build.py --ps2ref` (software-режим не должен меняться побитно, если правка не заявлена как отличие).
* Заметка про инструмент Bash: двойная обратная косая в аргументах схлопывается; для кода с `\n` в строках C/Python правь файлы инструментом Edit/Write, а не heredoc.

## Базовые цифры на старте OPT10 (сборка HEAD, релиз, `-timedemo DEMO_001.lmp -ps2prof`, окна по 105 кадров, такты EE на кадр; FPS = 294.912 М / такты)
* **software**, полная конфигурация: среднее окон 1..9 = **9.99 М/кадр (29.5 FPS)**, таймдемо «1051 gametics in 1209 realtics» (30.4 FPS); MAP01 арена 22.3 МБ, свободно 5.6 МБ.
* **HW (`-renderer Hardware -zreserve 3072`, без децимации текстур)**: `wall` ≈ **70 М/кадр (4.0 FPS)**: «1051 gametics in 9129 realtics»; разбивка окна 5: `clear` 25.8 М (setup/регены/небо), `batch` 18.2 М, `sprites` 23.3 М (почти всё — загрузки текстур спрайтов и их полигоны), `tex` 19.7 М (копирование текселей в кольцо GIF),
  `drv draw` 4.8 М, `bsp` 3.0 М; рабочий набор текстур кадра ≈ 25 000 блоков при пуле 12 032 (рабочий набор вдвое больше VRAM → всё грузится заново каждый кадр, 7 МБ/кадр). Картинка HW на MAP01 визуально близка к ПК-OpenGL.
* Цели: **HW ≤ 8.4 М/кадр (≥ 35 FPS) обязательно и явно ниже software на всех 4 демо; стремиться к ≤ 4.9 М (60 FPS)**. Software — ≤ 8.4 М на всех 4 демо без изменения картинки. 60 FPS = 4.9 М, 35 FPS = 8.43 М; логика тика ≈ 2–3 М.

## Железные правила
* Ничего не утверждать без запуска; числа — только релизная сборка с LTO; в отчёт — команда, среднее и максимум по окнам для **всех четырёх демо** (там, где это скорость).
* Правки общего ядра (`.c/.h` движка) — только под `PS2`/`PS2_PROFILE`/`HAS_*`/`PS2_*`: ПК-сборка должна оставаться прежней (проверка: `ninja -C build/pc-golden` собирается; golden ПК не меняется).
* Каждое отличие от оригинала — строка реестра в твоём отчёте (ID диапазона роли). `docs/DEVIATIONS.md` правит координатор.
* **Отчёт `docs/GATES/g1/opt10-<РОЛЬ>.md` дописывай после каждого этапа и коммить** (сессии обрываются лимитом API — недописанный отчёт = потерянная работа). Структура: 1) сделано; 2) команды и числа до/после; 3) не проверено/упёрлось; 4) строки реестра; 5) правки в чужих файлах.
* Файлы своей роли правь свободно; чужие — только точечно (Edit), с записью в отчёт. Слияние веток делает координатор: не переформатируй файлы целиком, не переименовывай/не переноси чужой код.
* Внешние сервисы: **запрещено** регистрировать сервер на настоящем мастер-сервере `ds.ms.srb2.org` и заходить на чужие серверы. Разрешено только чтение списка (HTTP GET) и всё остальное — на локальных ПК-сервере/mock-мастере.
* BIOS/файлы пользователя не копировать в репозиторий и не выкладывать.
* В конце — сводка ≤ 25 строк: что сделано, числа до/после, что не закрыто.

## Роли (6 агентов)

### HT — HW: текстуры, VRAM, загрузка, GIF/DMA (реестр `PS2-HW-30..39`; продолжение `opt9-HT.md`)
Файлы: `src/ps2/hw/ps2_hw_tex.inc`, `ps2_hw_gs.inc`, `ps2_hw_priv.inc`, `ps2_hwd.c`, `ps2_hw_regs.inc`, `src/hardware/hw_cache.c`, `hw_batching.c`, PS2-части `hw_data.h`/`hw_glob.h`.
Проблема № 1 всего HW: рабочий набор 25 000 блоков при пуле 12 032 → 7 МБ загрузок в кадр, `tex` 20 М + `clear`/`sprites` внутри загрузок. Решать **архитектурно, без потери качества сверх допуска**:
1. **Уровень детализации по поверхности (LOD на GS):** экран 320×224 — текстура 1024 в ширину на стене, занимающей 300 px, не нужна целиком. Хранить образ текстуры на нужном уровне пирамиды (box-фильтр из исходных индексов/RGBA, строится на EE один раз и кэшируется),
   уровень выбирать по реальной плотности текселей полигона (Якобиан: texel/px) с гистерезисом (без «мерцания» уровней), либо использовать MIPMAP GS (MIPTBP1/2, K/L) — измерить, что дешевле и правильнее. Погрешность — отличие от ПК-OpenGL без mip-фильтра на ≤ 1 уровень там, где текстура сжимается > 2:1 на экране (запиши в реестр; это не «децимация PS2-HW-24»: вблизи — полное разрешение).
2. Один образ в VRAM на варианты, отличающиеся только CLUT (с ключом/без, colormap/translation) — теперь два экземпляра по 2048 блоков; размещение по реальному размеру (TBW/строки), а не степень двойки; облачные «горизонтные» плоскости 1024² не должны вытеснять всё остальное.
3. **Zero-copy загрузка** (DMA REF/IMAGE прямо из выровненных данных, `SyncDCache`, блок под DMA не вытеснять из зоны), потоковая подкачка в порядке батчей (сортировка по текстуре уже есть), политика вытеснения «не грузить дважды за кадр», пакетная заливка (одна цепочка DMA на пачку).
4. Цели: `tex` ≈ 0 М/кадр, `decim=0`, загрузок за кадр — минимум; рабочие наборы проверить на картах 1..33 + спец-этапы/NiGHTS/титул/меню (`-hwdbg 0x100000` строки `HWTEX`). Нет «чужой» текстуры после вытеснения, нет устаревшей CLUT, NPOT/повторы, flash палитры, переключение Software↔Hardware без утечек.
5. GIF-кольцо/DMA: двойная буферизация, разобрать `clear`/`flipwait`/`dmawait` (что реальное ожидание, а что работа EE).

Стабильность HW: переключение рендерера в меню туда-обратно, пауза/меню/титул, 50 смен карт, ≥ 3000 кадров без зависаний/мусора; корректность на **реальном** GS (не только PCSX2): выравнивание DMA 64 Б, SyncDCache, лимиты GS (текстуры ≤ 1024, TBW, CLUT-буферы), отсутствие записи за границы VRAM.
