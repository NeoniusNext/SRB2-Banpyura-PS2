# Rejected CLUT quadword permutation, eleventh pass, 2026-11-15

No GS production change is retained. The final quadword candidate is exact,
but twelve supported native timing rows regress, including six ordinary tint
palette rows. The entire production texture source is restored byte for byte
to the preceding baseline, SHA256
`76de33ef5d73da9aae8f59b3e1bbdb34502e8c21319b31d765235344a252fe8a`.

All candidate sizes, code and timings below describe the preserved rejected
experiment. They are not savings claimed for the restored production source.
The compact decision is `build/nov15-next11/gs/rejection-decision.json`.

The candidate changes only the private CLUT permutation in
`src/ps2/hw/ps2_hw_tex.inc`. A tiny inline wrapper retains the original
`ps2hwd_dbg_flags & 16` identity return before any pointer access. A private
non-inlined active core swaps the two eight-entry spans in each 32-entry
CSM1 group. Its aligned EE path uses four `LQ` and four `SQ` instructions per
group; the original scalar algorithm handles the other word alignments.
Both loops keep explicit no-unroll pragmas. No CLUT format, entry, alpha,
precision, texture size, allocation, capacity, lifetime, transfer or feature
changes. The earlier byte state-register staging, paired VRAM ranges, PSMT8
fillers, three AP88 gathers and REGLIST paths remain.

## Source and ownership contract

The baseline is the complete 602-file source frozen from
`69a3e5319a0a2ee0afda9c460c4a158139d221dd`, whose published source is
`e87421615d0271dcf9074656c513f42d0ea1028d`. The measured source is that complete
freeze plus this texture-file overlay; peer memory and software candidates
are excluded. `next11_gs_variant.py --reverse` restores the complete original
texture file byte for byte. Every other GS source is separately identical.

There are exactly two source callers: `clut_build_into` and `ramp_clut`.
Both obtain their image pointer exclusively from `clut_alloc`. The driver
allocates every ring with `memalign(64)`; `pk_alloc` returns its `qw_t` pointer
plus an integer qword offset, and `clut_alloc` returns the image at `h[6]`,
96 bytes later. Thus every production image is 16-byte aligned. The scalar
fallback nevertheless preserves all four original word-alignment residues.
The open ring belongs to the EE until packet submission. No DMA reader sees
an intermediate permutation, and no pointer or palette content is retained
across calls. The assembly memory clobber orders the preceding image stores
before the quadword loads and stores.

The pool remains the complete 4 MiB, range capacity remains 8,193, and the
actual EE `H` remains 36,896 bytes with its original offsets. No persistent
EE storage, heap, ring, texture or CLUT capacity is reduced. The three caller
frames remain 48, 64 and 272 bytes; `clut_alloc` retains its 32-byte frame.
The new active core has no frame. Complete changed text sections decrease
**136 bytes** including the new core. This does not shrink the pre-reserved
stack. Whole-image sizes also include generated build metadata and are not
attributed to the CLUT component.

## Exactness scope

Ordinary host and ASan/UBSan runs each pass **135,234 cases** and **5,460
complete image packets**, digest `2abc9eb3`. The direct matrix covers every
one of the 8,192 entry bits, all four word alignments, identity and active
ordering, all-zero/all-one/indexed/random data, complete buffer guards and
the identity return with a null pointer.

The host compiles the two actual source versions separately. The aligned
assembly transfers are mechanically substituted with the same eight 16-byte
byte copies for the host oracle run. The native direct source helper executes
the actual assembly. There are **131,138 direct helper cases**, followed by
**4,096 complete actual-LTO builder calls** in the native kernel. The latter
cover all palette kinds, both palette sources, keyed variants, all five ramp
variants, fixed refresh/no-refresh, ramp cache hits,
counter wrapping, all rings, all 73 space positions around the largest CLUT
packet, and pending VU predicates.

The unchanged source formatters supply the unpermuted entries. An independent
bit-index mapping, not a swap loop, places them in CSM1 order and constructs
all GIF tags, A+D writes, image bytes and the following TEXFLUSH. A separate
state oracle predicts complete private state and controlled completion/ring
rotation effects. It compares the full production state, complete rings and
guards, VU state and every writable data node in the native graph. This
isolates the changed permutation and packet construction; it does not claim
to independently rederive the unchanged floating lighting mathematics.

Six executed source corruptions fail: scalar result bit, wrong wide-pair
source, transfer width, TEXFLUSH address, epoch accounting and lost identity
return. Eight executed strict-parser corruptions fail: missing/duplicate row,
changed parameters, missing completion, injected failure, wrong digest,
malformed counter and duplicate repetition. Their raw outputs remain archived.

## Actual default-LTO closure

The fixture embeds six complete baseline code nodes and seven candidate nodes,
including all original builder bodies, `clut_alloc`, the candidate active core
and the actual memory wrappers. Each version includes fourteen complete data
nodes. The original ordered R32/R26/HI16/LO16/GPREL16 records, explicit addends,
local symbol metadata and input GP0 32,752 remain. The baseline graph has
213 ordered RELAs and the candidate has 225. All complete input bytes,
trailing padding, emitted relocations and resolved game/fixture bytes bind.

Some palette cvar data contain R32 pointers into a large merged string pool.
The checker decodes the concrete pointer from the actual mapped data word,
checks the complete original NUL-terminated string and alignment at that
address, and then reapplies the original relocation. It records all identical
merge candidates without claiming the selected address is independently unique.
The existing HI/LO literal checks remain for code targets.

Ramp construction executes the real SDK `floorf`. Its original archive member,
316-byte function plus four padding bytes, all eight ordered RELAs and three
four-byte constants bind to both actual games and the native fixture. The
memory wrappers and complete SDK copy/set/move bodies also bind; their zero-byte
retention checks are outside timing, and no wrapper call is invented in a
CLUT path that does not call it. Production DMA/VU completion calls use explicit
capture hooks in exactness cases; timed rows have room and no pending chunk,
so these hooks are not reached in measurement.

The whole isolated game compiles/links without diagnostics. Standalone native
fixture linking retains the SDK's existing abicalls compatibility warnings.
The previous state helper, high/free allocators and complete `tex_upload`
retain all instruction bytes and canonical ordered RELAs. The preceding
recursive five-upload graph also remains identical, including all three AP88
`PPACB` sites. A renamed compiler-generated switch table in an unrelated
instruction-identical caller is accepted only after its complete bytes and
ordered RELAs are checked equal.

## Native timing and disposition

The complete final kernel passes its exactness corpus, reaches its completion
marker and exits zero. Its **156 prescribed rows** each have nine repetitions.
The summed medians improve overall, but that aggregate fails the zero-regression
gate:

| Final candidate cohort | Rows | Before sum | After sum | Change | Faster / ties / slower |
| --- | ---: | ---: | ---: | ---: | ---: |
| Ordinary mode | 78 | 10,392,972 | 10,028,040 | −3.5113344% | 70 / 2 / **6** |
| Diagnostic identity mode | 78 | 9,767,374 | 9,835,710 | +0.6996353% | 60 / 12 / **6** |
| Entire matrix | 156 | 20,160,346 | 19,863,750 | −1.4711851% | 130 / 14 / **12** |

Every slower row builds `CK_TINT`. The ordinary single-call cost rises
**36,568 → 36,752 cycles (+0.5031722%)**. Its eight- and 64-call rows are also
about 0.5034% slower. Identity single-call cost rises
**36,102 → 36,609 (+1.4043543%)**, with the two larger batches about 1.405% slower.
Each occurs in both cache modes, giving twelve regressions. Ordinary fixed
refresh rows and ramp rows improve or tie; cache-hit/no-refresh behavior does
not excuse the tint regressions. The complete actual palette-builder cost,
not a stand-alone memory-exchange loop, determines this rejection.

The rows and every repetition remain in `ee/benchmark-summary.json`; ordinary
cohorts are in `ee/normal-cohorts.json`. These sums are not weighted by game
frequency. The following immutable hashes identify rejected artifacts:

The checked source reversal and final worktree comparison establish restoration;
no new GS optimization is retained for a combined shipping build.

The complete kernel runs through `run_pcsx2.py` on the normal 32 MiB profile.
Each prescribed row has nine alternating repetitions through volatile function

Full before/after input archives, INI text, all non-frontend settings, emulator
binary hashes, environment and logs are retained. The profile keeps 32 MiB RAM,
normal EE cycle rate/skip, disabled EE-cache emulation and disabled patches.
Native input archives preserve the exact scripts as run before later report-only
work. The standard GS suite was not rerun for this rejected component. Its
inherited baseline signature remains a separate final integration gate:

## Reproduction

Use a fresh output directory. The explicit preserved candidate overlay is needed
because the production source has been restored. The original frozen build and
run inputs remain under `ee/pinned-run-inputs`; reproducing does not overwrite
that evidence. Any later rebuilt game requires a fresh actual-code binding.

```sh
GS_PROOF_OUT=build/next11-gs-reproduce
python3 -B tools/ps2/next11_gs_build.py --out "$GS_PROOF_OUT" --freeze-only \
  --candidate-src build/nov15-next11/gs/measured-source/src
python3 -B tools/ps2/next11_gs_hosttest.py --out "$GS_PROOF_OUT/host" \
  --current-src "$GS_PROOF_OUT/measured-source/src" --sanitize --negative-controls
source /workspace/.onboarding/environment.sh
python3 -B tools/ps2/next11_gs_build.py --out "$GS_PROOF_OUT" \
  --candidate-src build/nov15-next11/gs/measured-source/src
python3 -B tools/ps2/next11_gs_hosttest.py --build --out "$GS_PROOF_OUT/ee" \
  --current-src "$GS_PROOF_OUT/measured-source/src" \
  --current-engine "$GS_PROOF_OUT/candidate-hardware/obj/engine_lto.o"
python3 -B tools/ps2/next11_gs_hosttest.py --bind --out "$GS_PROOF_OUT/ee" \
  --current-src "$GS_PROOF_OUT/measured-source/src" \
  --current-engine "$GS_PROOF_OUT/candidate-hardware/obj/engine_lto.o" \
  --current-elf "$GS_PROOF_OUT/candidate-hardware/SRB2.ELF" --negative-controls
source /workspace/.onboarding/emulator-env.sh
python3 -B tools/ps2/next11_gs_run.py --out "$GS_PROOF_OUT/ee" --timeout 600
python3 -B tools/ps2/next11_gs_hosttest.py --out "$GS_PROOF_OUT/ee" \
  --host-report "$GS_PROOF_OUT/host/host-report.json" \
  --summarize "$GS_PROOF_OUT/ee/run.log" --negative-controls
```

All raw evidence is under `build/nov15-next11/gs`. Four earlier static variants
are preserved under `first-outlined`, `second-outlined`, `third-forced-inline`
and `fourth-inline-hint`. An active-only unguarded helper version is preserved
under `fifth-debug-regressions`: all normal rows improved or tied, but twelve
supported identity rows slowed, so it was rejected. No candidate percentages
are assigned to the restored production source.
