# Exact CT32 source-column induction, eighth pass, 2026-11-15

Only `fill_ap88_ct32` and `fill_ct32` in
`src/ps2/hw/ps2_hw_tex.inc` change. They advance an unsigned source-column
index instead of recomputing its variable shift for every pixel. AP_88 still
reads its selected palette entry live and applies the same rounded alpha;
RGBA keeps every RGB bit and applies the same alpha conversion. The preceding
immutable context snapshots, PSMT8 kernels and three native `PPACB` sites
remain intact.

In the exact complete default-LTO EE fixture, **76 configurations improve,
eight are equal and none regress**. Summed median callback cost decreases
**20.59470%**, with unchanged function sizes and stack frames. This is a
component measurement, not a game-weighted FPS or whole-upload percentage.

The source reference is frozen revision
`bd1160aaf3466ee8bcbb28a92f2116c1b8b64b2a`, reconstructed under
`build/nov15-next8/baseline-src/src`. Reversing only the two induction rewrites
reconstructs the complete frozen texture source byte for byte. The context,
source-row helpers, alpha helper, caller counts, driver, DMA ring and private
state layout are separately checked against that reference. No format,
dimensions, sampling, filtering, key, palette, precision, feature, capacity,
allocator, packet, ordering or lifetime changes are introduced.

For `step = 1u << dx`, the first column is `step >> 1`. Incrementing it by
`step` gives `(x << dx) + ((1u << dx) >> 1)` modulo 2^32, exactly the original
unsigned expression. The production input axes are bounded by 16384; the
planner's 16-texel minimum during cap reduction bounds the selected CT32
shifts by ten. The arithmetic proof also checks all shifts 0..31 and columns
0..16384. C advances an integer index, so it forms no source pointer beyond
the last accessed texel. Source and palette reads and destination writes keep
their original order. The original context snapshot is fresh for each row;
the caller's stack context and separately allocated DMA ring cannot overlap.

## Exactness

The host fixture extracts the actual frozen/current functions into separate
translation units and compares both against an independent byte-oriented
oracle using the original `(alpha*128+127)/255` rounding. Ordinary and
ASan/UBSan runs each pass **204,912 row cases and 30,192,631 pixels**, plus
**524,320 unsigned-column identities**. Every 16-bit index/alpha pair occurs
in each of four pixel positions. RGBA covers every alpha, channel combinations,
random, constant, zero and opaque input. Other cases cover widths 1..1024,
valid source/output byte residues, cropped strides, later rows, shifts
0..10, source axes of 16384, zero-width callbacks and repeated calls with
changed source, context and palette. Complete destination/canary buffers,
source bytes, context and palette are checked for writes.

All six executed mutations are detected: retaining the column across calls,
doubling its increment, changing its initial centre, changing an alpha bit,
using the wrong row and writing one extra texel. The linked-code checker
also rejects an instruction-bit change, a moved relocation and a changed
explicit relocation addend.

The standard 32 MiB native run passes **138,514 exact/oracle row cases and
1,645,624 pixels**, plus the same **524,320 unsigned-column identities**, then
completes all 84 timing configurations and reaches `GS NEXT8 DONE`, wrapper
exit zero. The driver also checks the state-layout prefix/suffix canaries.

## Actual engine code

The native fixture uses complete function sections from the saved baseline
and current default full-LTO Hardware `engine_lto.o`. It emits their exact
instruction words and original ordered HI16/LO16 RELA records into assembly.
After assembling, every section byte and relocation is compared with the
source object. Original function symbol sizes are retained; four trailing
zero alignment bytes in each RGBA section remain separately verified.

The code checker applies the original relocations and compares every complete
function byte with both the real Hardware ELF and the timing fixture ELF.
The AP88 helper retains its real `H.pal` offset, 35,264, inside the real
36,896-byte state layout. Prefix/suffix canaries surround the fixture's
palette. Whole PSMT8 and IA88 function instruction/relocation streams must
remain unchanged; all three existing native `PPACB` sites are counted.

| Actual linked helper | Baseline body | Current body | Stack frame | Pixel-loop instructions |
| --- | ---: | ---: | ---: | ---: |
| AP_88 requiring CT32 | 160 B | 160 B | 0 -> 0 B | 18 -> 14 |
| RGBA requiring CT32 | 148 B | 148 B | 0 -> 0 B | 15 -> 11 |

The instruction counts include each loop branch and delay slot. Both
positive-width setups grow from 20 to 24 instructions, so a one-pixel row
executes the same count and each later pixel removes four instructions.
This is no new dispatch or alignment-specialized path. No persistent state,
heap, scratch, stack frame or VRAM capacity is added. These are row-preparation
CPU changes; DMA/GIF bytes and GS draw work are unchanged.

The native driver selects each function through a volatile function pointer;
no C replacement implementation or constant-call specialization supplies the
timed code. Nine repetitions alternate baseline/current order. Every complete
timed output and its canaries are compared after each pair. The table sums

## Rejected IA88 extension

The first candidate also applied induction to IA88. Its actual-LTO fixture
passed exactness, but all four one-pixel IA88 configurations cost one extra
CP0 cycle per call, a 1.5873% increase. Operand swapping, explicit grey
shift/OR replication, named intermediates and byte-offset induction all
compiled to identical IA88 instructions. IA88 was therefore restored
completely; no special-case dispatch was added. The complete rejected run,
including its regression rows, is preserved under
`build/nov15-next8/gs/rejected-ia88-induction`. Its 126-row aggregate is not
the final retained change's measurement.

## Reproduction

With the configured SDK and saved default Hardware objects:

```sh
source /workspace/.onboarding/environment.sh
python3 -B tools/ps2/next8_gs_hosttest.py \
  --out build/nov15-next8/gs/host \
  --base-src build/nov15-next8/baseline-src/src --sanitize --negative-controls
python3 -B tools/ps2/next8_gs_hosttest.py \
  --out build/nov15-next8/gs/ee \
  --base-src build/nov15-next8/baseline-src/src --ee-only \
  --baseline-engine build/nov15-next8/baseline/hardware/engine_lto.o \
  --current-engine build/nov15-next8/hardware/obj/engine_lto.o
source /workspace/.onboarding/emulator-env.sh
python3 -B tools/ps2/run_pcsx2.py \
  --elf build/nov15-next8/gs/ee/GS_NEXT8.ELF \
  --log build/nov15-next8/gs/ee/run.log --until 'GS NEXT8 DONE' --timeout 600
python3 -B tools/ps2/next8_gs_hosttest.py \
  --out build/nov15-next8/gs/ee --summarize build/nov15-next8/gs/ee/run.log
python3 -B tools/ps2/next8_gs_codecheck.py \
  --out build/nov15-next8/gs/linked \
  --baseline-engine build/nov15-next8/baseline/hardware/engine_lto.o \
  --current-engine build/nov15-next8/hardware/obj/engine_lto.o \
  --baseline-elf build/nov15-next8/baseline/hardware/SRB2.ELF \
  --current-elf build/nov15-next8/hardware/SRB2.ELF \
  --fixture-elf build/nov15-next8/gs/ee/GS_NEXT8.ELF --negative-controls
```

The callback fixture does not exercise or declare fixed the historical VU0
outcode discrepancy: 24,625 of 49,152 vertices differ, while XYZ and
reciprocal-W match exactly. The historical full GS suite remains CT32 55/56
and CT16S 50/51, with its failing return preserved. Readbacks and complete
game-frame checks are separate integration evidence. No whole-game FPS,
physical-console timing, power or frame-time stability measurement is claimed.
